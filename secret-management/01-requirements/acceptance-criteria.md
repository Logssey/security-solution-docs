# 제품 수용 기준

요구사항과 기능·API·데이터 설계가 충족되는지를 판단하는 시나리오다. 각 시나리오는 구현 완료 현황이나 시험 결과를 나타내지 않는다. 사용자의 역할·승인 범위·관련 증거를 고정하고 같은 기준으로 판정한다.

| ID | 상황과 행동 | 판정 기준 |
|---|---|---|
| AC-01 위치별 상태 | 같은 완전 키의 필수 대응 위치에 현재 발견·비교 가능한 미발견·최근 검사 실패 세 상태를 만든다. | 키 1개·위치 3곳으로 묶고 각 상태를 보존한다. 필수 대응 위치의 `presence=UNKNOWN`이 남으면 건 해결을 막는다. |
| AC-02 메타데이터 | IAM 접근키 메타데이터와 AWS 목록 개수 범위만 수집한 결과를 조회한다. | IAM 인벤토리와 목록 범위를 구별하고 값 노출·유효성·심각도나 가상의 키를 만들지 않는다. |
| AC-03 정상 보관 | 완전 값 위치에 적용 가능한 보관 정책·버전·기한으로 `NORMAL`을 판정하고 이후 정책을 만료시킨다. | 근거 있는 정상 인벤토리로 보이되 만료 후 재확인 대상으로 전환한다. 불완전 후보의 동일 요청은 근거 부족으로 거부한다. |
| AC-04 추가 확인 | 환경·소유자·노출 범위 근거가 부족한 후보를 담당자·기한과 함께 조사로 남긴다. | `UNKNOWN`을 유지하고 조사로 연결한다. 단순 기한 도래·과제 종료 입력으로 노출·안전을 확정하지 않는다. |
| AC-05 단일 결정 | 같은 위치의 `ABNORMAL` 결정을 재시도하고 다른 사용자가 같은 키의 추가 위치를 동시에 판정한다. | 멱등 결과와 현재 건 유일성이 유지되고 권한 내 위치만 정확히 연결된다. 판정만 저장되고 건 연결이 빠지는 반쪽 성공은 없다. |
| AC-06 권한·직접 링크 | 위치 하나만 허용된 사용자, 지정 조치 담당자, 권한 철회 사용자로 카드·목록·키/위치 URL을 연다. | 응답·집계·CSV·스냅샷에서 권한 밖 정보가 노출되지 않는다. 조치 담당자는 필요한 안전한 근거를 볼 수 있지만 노출 판정 권한은 자동 부여되지 않는다. |
| AC-07 시험과 실키 | 동일 키별 fixture 증거가 있는 합성과 증거 없는 완전 값 후보를 시험 원천에서 반복 발견한다. 후보는 최신 성공 검사에서 현재 발견됐고 유효 Finding이 남은 상태다. | 합성은 명시적 시험 조회, 의심 후보는 중복 없는 교차 환경 경고로 표시한다. 불완전 후보·메타데이터·모든 Finding이 오탐인 위치는 이 경고에서 제외한다. 반복 검사로 경고를 증식하지 않고 운영 대응 수와 합산하지 않는다. 실키 확인·반증은 각각 근거 있는 승격·종료로 남긴다. |
| AC-08 부분 실패 | 수집 8범위 중 7성공·1부분 실패 및 탐지 실패를 포함해 재검사를 실행한다. | 전체 결과와 범위별 성공/누락 수가 일치하고 실패 구간을 미발견으로 갱신하지 않는다. 해당 위치와 해결 차단 사유로 이동할 수 있다. |
| AC-09 조치와 폐기 | 파일 제거 조치를 기록하고 재검사 미발견을 얻되 공급자 수명주기 근거는 넣지 않는다. | «해당 위치 미발견»은 표시하지만 실제 키 폐기 확인·전체 해결로 표현하지 않는다. 누락 근거와 다음 행동을 보여준다. |
| AC-10 동시 수정 | 두 사용자가 같은 버전으로 담당 변경·결정·조치를 요청하고, 해결 직전에 새 위치나 새 검증 결과를 반영한다. | 한 요청은 충돌·새 근거 안내를 받고 입력을 조용히 덮지 않는다. 해결은 최신 사실을 재검사하고 오래된 성공으로 통과하지 않는다. |
| AC-11 새 위치·재발 | 재검사 대기 건에 새 위치를 연결하고, 해결 뒤 같은 키를 다시 발견한다. | 대기 건은 새 위치 조치가 필요해지고 과거 기록을 보존한다. 해결 후 재발은 이전 건을 참조하는 새 대응 건으로 기록하며 옛 `MISSING`으로 자동 해결하지 않는다. |
| AC-12 스캔 탐색 | 실행 목록 필터·페이지 상태에서 독립 상세로 이동하고 직접 상세 주소·새로고침·뒤로 가기를 사용한다. | 상세가 독립적으로 표시되고 목록 상태·포커스가 복원된다. 하단 누적·중복 상세가 없다. |
| AC-13 집계 일관성 | 동일 스냅샷으로 카드와 목록을 열고 중간에 데이터·역할을 변경하거나 스냅샷을 만료시킨다. | 유효한 동일 스냅샷 수치는 일치한다. 권한 철회·만료는 안전하게 거부하고 변경 요청은 최신 버전을 요구한다. |
| AC-14 문구·오류 | 로딩, 0건, 미지원, 미확인, 실패, 세션 만료·권한 오류·잘못된 키/위치 링크를 연다. | 의미가 다른 상태가 같은 0·완료·흰 화면이 되지 않는다. 짧은 상태·이유와 유효한 다음 행동을 제공한다. |
| AC-15 기록 보존·정정 | 판정·조치·해결 근거의 정정과 새 증거 추가를 수행한다. | 이전 근거·확인 한계·수행자·시각을 보존하고 새 근거를 추가한다. 과거 기록을 소급 수정하거나 과거 해결을 더 넓은 범위의 확인으로 승격하지 않는다. |
| AC-16 원문 비노출 | 합성 비밀·민감한 경로·공급자 오류·수식형 표시값을 포함한 정상·실패·CSV 흐름을 실행한다. | 키·본문·공급자 오류 원문이 결과 DB·로그·브라우저·내보내기·추적 파일에 새지 않는다. 수집을 위해 승인 운영 저장소에 필요한 원천 참조는 보존하되 조회·집계·로그에는 승인된 안전 별칭만 제공한다. 원천 본문을 외부 AI에 보내지 않는다. |
| AC-17 증거 생성·권한 | 외부 조치 기록만 저장한 경우, 수동 수명주기 증거를 제출·검토한 경우, 워커의 공급자 확인, fixture 보호 manifest 매칭을 각각 실행한다. | 자기 신고만으로 해결하지 않는다. 수동 확인은 APPROVED_MANUAL과 제한 확인이며 FULL로 승격할 수 없다. PROVIDER_VERIFIED는 일반 사용자 요청으로 만들 수 없다. 시험 출처나 fixture 주장만으로 SIMULATION을 허용하지 않는다. |
| AC-18 다중 사실·필터 | 같은 키에 노출 확인·검사 누락·권한 제한이 함께 있는 상태에서 보안 담당자·조치 담당자·수집 운영자로 현황과 키 상세를 연다. | 사실은 유지하고 가능한 다음 행동만 제공한다. 대응 담당자 카드가 권한 없는 판정 대기열로 연결되지 않는다. 범위 지표에 적용되지 않는 환경·발급자 필터를 명시하고 카드·도착 대기열은 같은 스냅샷과 단위를 유지한다. CSV는 같은 INVENTORY 스냅샷 전건 또는 명시적 실패이며 조용한 일부 내보내기가 없다. |
| AC-19 자동 조사 배정 | 기본 조사 담당자·기한 정책이 없는 연결에서 실키 의심 경고가 생성되고 이후 적격 담당자를 배정한다. | 경고 생성은 누락되지 않고 배정 대기로 남는다. 기한 미설정을 지연·기한 초과로 위장하지 않는다. 수동 추가 확인 결정에는 요구된 담당자·기한이 있어야 한다. 반복 검사로 과제를 증식하지 않는다. |
| AC-20 범위와 위치 업무 | 미분류·정책 미설정 범위의 값 후보를 수집하고 SECURITY가 정책 연결을 유지한 채 운영 출처로 저장한다. | 직접 저장의 근거·변경 이력을 남기며 재승인을 요구하지 않는다. 범위 설정에는 정책 미설정 사유만 남고 해당 위치의 확인 필요와 독립 집계된다. 위치·키·범위 합계 또는 수동 상태 이동을 만들지 않는다. |
| AC-21 독립 검토 | 시험 최초 분류, 운영→시험, 보관 허용 정책 연결 변경을 요청한다. | 미리보기와 제출이 같은 검토 요건을 설명한다. 제안자 자기 승인을 거부하고 담당·대기 시각·영향·반려 근거를 표시한다. 검토자 미지정은 대기로 보존하며 보안 역할을 자동 부여하지 않는다. |
| AC-22 단독 운영 | SECURITY 권한을 가진 한 사용자만 있는 상태에서 출처 보완·조사·담당 지정·조치 기록·재검사를 수행한다. | 직접 허용된 작업은 수행할 수 있다. 독립 검토 필수 변경은 이유와 담당자 지정 경로가 남고 자동 승인되지 않는다. 조회·조사·이미 확인된 노출의 조치가 일괄 잠기지 않는다. |
| AC-23 내부 담당 요청 | 열람·요청 권한은 있지만 필요한 실행 권한이 없는 사용자가 같은 대상·같은 질문을 반복 요청한다. | 허용된 역할·담당 경로를 보여주고 같은 열린 HUMAN_HANDOFF 과제를 반환한다. 요청 등록으로 권한·노출 판정·해결을 부여하지 않고 다른 대상의 존재도 노출하지 않는다. |
| AC-24 목록 잔여 이유 | 범위 분류 저장 또는 검토 요청 후 원래 필터·페이지의 목록으로 돌아간다. | 성공 효과와 남은 이유를 보여준다. 변경된 스냅샷은 명시적으로 새 기준으로 열고, 설정이 덜 끝난 범위를 저장 실패 또는 자동 완료로 오해하게 하지 않는다. |
| AC-25 키 중심 사용자 여정 | 한 키의 세 필수 대응 위치를 제거 확인·현재 발견·검사 실패로 만들고 담당자가 남은 조치와 재검사를 진행한다. | 키·소스별 위치·대응·실행을 조건 유지 상태로 탐색한다. 잔존 1곳·현재 확인 불가 1곳과 키 사용 종료의 확인 수준을 구분하고 해결을 막는 이유·다음 행동을 제공한다. |
| AC-26 재발견과 우선 이유 | 조치 이후 같은 위치에서 다시 발견된 건, VALID이며 금지 규칙이 일치한 미판정 위치, 미검증 위치를 조회한다. | 동일 단위 안에서 각 추천 이유·근거 시각을 설명한다. 금지 일치만으로 노출을 자동 확정하지 않고 미검증·미평가를 LOW로 내려 순위를 계산하지 않는다. |
| AC-27 보안 효과의 경계 | 시험 재분류·필터 변경·검사 실패·오탐 교정·위험 수용으로 화면 수치가 감소한다. | 제거·폐기 성공이나 위험 감소율로 표현하지 않는다. 확인된 동일 대상의 조치 후 재검사와 수명주기 근거만 각각의 확인 결과로 제시한다. |

숫자·단위·권한·기준시각은 [데이터 계약](../03-architecture/data-contract.md), 화면 탐색은 [화면 명세](../02-functional-design/dashboard-flow.md), 오류·동시성은 [API 계약](../03-architecture/api-contract.md)을 따른다.
