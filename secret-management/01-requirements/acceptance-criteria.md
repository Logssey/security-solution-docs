# 제품 수용 기준

요구사항과 기능·API·데이터 설계가 충족되는지를 판단하는 시나리오다. 각 시나리오는 구현 완료 현황이나 시험 결과를 나타내지 않는다. 사용자의 역할·승인 범위·관련 증거를 고정하고 같은 기준으로 판정한다.

| ID | 상황과 행동 | 판정 기준 |
|---|---|---|
| AC-01 위치별 상태 | 같은 완전 키의 필수 대응 위치에 현재 발견·비교 가능한 미발견·최근 검사 실패 세 상태를 만든다. | 키 1개·위치 3곳으로 묶고 각 상태를 보존한다. 필수 대응 위치의 `presence=UNKNOWN`이 남으면 건 해결을 막는다. |
| AC-02 메타데이터 | IAM 접근키 메타데이터와 AWS 목록 개수 범위만 수집한 결과를 조회한다. | IAM 인벤토리와 목록 범위를 구별하고 값 노출·유효성·심각도나 가상의 키를 만들지 않는다. |
| AC-03 정상 보관 | 완전 값 위치에 적용 가능한 보관 정책·버전·기한으로 `NORMAL`을 판정하고 이후 정책을 만료시킨다. | 근거 있는 정상 인벤토리로 보이되 만료 후 재확인 대상으로 전환한다. 불완전 후보의 동일 요청은 근거 부족으로 거부한다. |
| AC-04 추가 확인 | 환경·소유자·노출 범위 근거가 부족한 후보를 담당자·기한과 함께 조사로 남긴다. | `UNKNOWN`을 유지하고 조사로 연결한다. 단순 기한 도래·과제 종료 입력으로 노출·안전을 확정하지 않는다. |
| AC-05 단일 결정 | 같은 위치의 `ABNORMAL` 결정을 재시도하고 다른 사용자가 같은 키의 추가 위치를 동시에 판정한다. | 멱등 결과와 현재 건 유일성이 유지되고 권한 내 위치만 정확히 연결된다. 판정만 저장되고 건 연결이 빠지는 반쪽 성공은 없다. |
| AC-06 권한·직접 링크 | 위치 하나만 허용된 사용자, 지정 조치 담당자, 권한 철회 사용자로 카드·목록·키/위치 URL을 연다. | 응답·집계·CSV·스냅샷에서 권한 밖 정보가 노출되지 않는다. 조치 담당자는 필요한 안전한 근거를 볼 수 있지만 노출 판정 권한은 자동 부여되지 않는다. |
| AC-07 시험과 실키 | 동일 키별 fixture 증거가 있는 합성과 증거 없는 완전 값 후보를 시험 원천에서 반복 발견한다. 후보는 최신 성공 검사에서 현재 발견됐고 유효 Finding이 남은 상태다. | 합성은 명시적 시험 조회, 의심 후보는 중복 없는 교차 환경 경고로 표시한다. 불완전 후보·메타데이터·모든 Finding이 오탐인 위치는 이 경고에서 제외한다. 반복 검사로 경고를 증식하지 않고 운영 대응 수와 합산하지 않는다. 실키 확인·반증은 각각 근거 있는 승격·종료로 남긴다. |
| AC-08 부분 실패 | 수집 8범위 중 7성공·1부분 실패 및 탐지 실패를 포함해 재검사를 실행한다. | 전체 결과와 범위별 성공/누락 수가 일치하고 실패 구간을 미발견으로 갱신하지 않는다. 해당 위치와 해결 차단 사유로 이동할 수 있다. |
| AC-09 조치와 폐기 | 파일 제거 조치를 기록하고 재검사 미발견을 얻되 공급자 수명주기 근거는 넣지 않는다. | «해당 위치 미발견»은 표시하지만 실제 키 폐기 확인·전체 해결로 표현하지 않는다. 누락 근거와 다음 행동을 보여준다. |
| AC-10 동시 수정 | 두 사용자가 같은 버전으로 담당 변경·결정·조치를 요청하고, 해결 직전에 새 위치나 새 검증 결과를 반영한다. | 한 요청은 충돌·새 근거 안내를 받고 입력을 조용히 덮지 않는다. 해결은 최신 사실을 재검사하고 오래된 성공으로 통과하지 않는다. |
| AC-11 새 위치·재발 | 재검사 대기 건에 새 위치를 연결하고, 해결 뒤 같은 키를 다시 발견한다. | 대기 건은 새 위치 조치가 필요해지고 과거 기록을 보존한다. 해결 후 재발은 이전 건을 참조하는 새 대응 건으로 기록하며 옛 `MISSING`으로 자동 해결하지 않는다. |
| AC-12 스캔 탐색 | 실행 목록 필터·페이지 상태에서 독립 상세로 이동하고 직접 상세 주소·새로고침·뒤로 가기를 사용한다. | 상세가 독립적으로 표시되고 목록 상태·포커스가 복원된다. 하단 누적·중복 상세가 없다. |
| AC-13 집계 일관성 | 동일 스냅샷으로 카드와 목록을 열고 중간에 데이터·역할을 변경하거나 스냅샷을 만료시킨다. | 유효한 동일 스냅샷 수치는 일치한다. 권한 철회·만료는 안전하게 거부하고 변경 요청은 최신 버전을 요구한다. |
| AC-14 문구·오류 | 로딩, 0건, 미지원, 미확인, 실패, 세션 만료·권한 오류·잘못된 키/위치 링크를 연다. | 의미가 다른 상태가 같은 0·완료·흰 화면이 되지 않는다. 짧은 상태·이유와 유효한 다음 행동을 제공한다. |
| AC-15 기록 보존·정정 | 판정·조치·해결 근거의 정정과 새 증거 추가를 수행한다. | 이전 근거·확인 한계·수행자·시각을 보존하고 새 근거를 추가한다. 과거 기록을 소급 수정하거나 과거 해결을 더 넓은 범위의 확인으로 승격하지 않는다. |
| AC-16 원문 비노출 | 합성 비밀·민감한 경로·공급자 오류·수식형 표시값을 포함한 정상·실패·CSV 흐름을 실행한다. | 키·본문·공급자 오류 원문이 결과 DB·로그·브라우저·내보내기·추적 파일에 새지 않는다. 수집을 위해 승인 운영 저장소에 필요한 원천 참조는 보존하되 조회·집계·로그에는 승인된 안전 별칭만 제공한다. 원천 본문을 외부 AI에 보내지 않는다. |
| AC-17 증거 생성·권한 | 외부 조치 기록만 저장한 경우, 수동 수명주기 증거를 제출·검토한 경우, 워커의 공급자 확인, fixture 보호 manifest 매칭을 각각 실행한다. | 자기 신고만으로 해결하지 않는다. 수동 확인은 APPROVED_MANUAL과 제한 확인이며 FULL로 승격할 수 없다. PROVIDER_VERIFIED는 일반 사용자 요청으로 만들 수 없다. 시험 출처나 fixture 주장만으로 SIMULATION을 허용하지 않는다. |
| AC-18 다중 사실·필터 | 같은 키에 노출 확인·검사 누락·권한 제한이 함께 있는 상태에서 보안 담당자·조치 담당자·수집 운영자로 현황과 키 상세를 연다. | 사실은 유지하고 가능한 다음 행동만 제공한다. 대응 담당자 카드가 권한 없는 판정 대기열로 연결되지 않는다. 범위 지표에 적용되지 않는 환경·발급자 필터를 명시하고 카드·도착 대기열은 같은 스냅샷과 단위를 유지한다. CSV는 같은 INVENTORY 스냅샷 전건 또는 명시적 실패이며 조용한 일부 내보내기가 없다. |
| AC-19 자동 조사 배정 | 기본 조사 담당자·기한 정책이 없는 연결에서 실키 의심 경고가 생성되고 이후 적격 담당자를 배정한다. | 경고 생성은 누락되지 않고 배정 대기로 남는다. 기한 미설정을 지연·기한 초과로 위장하지 않는다. 수동 추가 확인 결정에는 요구된 담당자·기한이 있어야 한다. 반복 검사로 과제를 증식하지 않는다. |
| AC-20 범위와 위치 업무 | 미분류·정책 미설정 범위의 값 후보를 수집하고 SECURITY가 정책 연결을 유지한 채 운영 출처로 저장한다. | 직접 저장의 근거·변경 이력을 남기며 재승인을 요구하지 않는다. 범위 설정에는 정책 미설정 사유만 남고 해당 위치의 확인 필요와 독립 집계된다. 위치·키·범위 합계 또는 수동 상태 이동을 만들지 않는다. |
| AC-21 독립 검토 | 시험 최초 분류, 운영→시험, 보관 허용 정책 연결 변경을 요청한다. | 미리보기와 제출이 같은 검토 요건을 설명한다. 제안자 자기 승인을 거부하고 담당·대기 시각·영향·반려 근거를 표시한다. 검토자 미지정은 대기로 보존하며 보안 역할을 자동 부여하지 않는다. |
| AC-22 단독 운영 | SECURITY 권한을 가진 한 사용자만 있는 상태에서 출처 보완·조사·담당 지정·조치 기록·재검사를 수행한다. | 직접 허용된 작업은 수행할 수 있다. 독립 검토 필수 변경은 이유와 담당자 지정 경로가 남고 자동 승인되지 않는다. 조회·조사·이미 확인된 노출의 조치가 일괄 잠기지 않는다. |
| AC-23 내부 담당 요청 | 열람·요청 권한은 있지만 필요한 실행 권한이 없는 사용자가 같은 대상·같은 질문을 반복 요청한다. | 허용된 역할·담당 경로를 보여주고 같은 열린 HUMAN_HANDOFF 과제를 반환한다. 요청 등록으로 권한·노출 판정·해결을 부여하지 않고 다른 대상의 존재도 노출하지 않는다. |
| AC-24 목록 잔여 이유 | 범위 분류 저장 또는 검토 요청 후 원래 필터·페이지의 목록으로 돌아간다. | 성공 효과와 남은 이유를 보여준다. 변경된 스냅샷은 명시적으로 새 기준으로 열고, 설정이 덜 끝난 범위를 저장 실패 또는 자동 완료로 오해하게 하지 않는다. |
| AC-25 키 중심 사용자 여정 | 한 키의 세 필수 대응 위치를 제거 확인·현재 발견·검사 실패로 만들고 담당자가 남은 조치와 재검사를 진행한다. | 키·소스별 위치·대응·실행을 조건 유지 상태로 탐색한다. 잔존 1곳·현재 확인 불가 1곳과 키 사용 종료의 확인 수준을 구분하고 해결을 막는 이유·다음 행동을 제공한다. |
| AC-26 재발견과 우선 이유 | 조치 이후 같은 위치에서 다시 발견된 건, VALID이며 금지 규칙이 일치한 미판정 위치, 미검증 위치를 조회한다. | 동일 단위 안에서 각 추천 이유·근거 시각을 설명한다. 금지 일치만으로 노출을 자동 확정하지 않고 미검증·미평가를 LOW로 내려 순위를 계산하지 않는다. |
| AC-27 보안 효과의 경계 | 시험 재분류·필터 변경·검사 실패·오탐 교정·위험 수용으로 화면 수치가 감소한다. | 제거·폐기 성공이나 위험 감소율로 표현하지 않는다. 확인된 동일 대상의 조치 후 재검사와 수명주기 근거만 각각의 확인 결과로 제시한다. |
| AC-28 검증 지원·생략 | 미등록 유형, 비활성 검증, 불완전 구성, 합성 입증 키, TEST 표식만 있는 후보를 조회·요청한다. | 미지원·꺼짐·구성 부족·합성 생략을 구별한다. TEST 표식만으로 합성 또는 검증 제외를 확정하지 않는다. 원천 전체가 합성 전용으로 승인된 경우 해당 원천의 능동 호출 금지는 유지한다. |
| AC-29 PAT 인증과 권한 | Classic/Fine-grained PAT의 인증 성공과 명확한 인증 거부, 403·호출 제한·timeout을 승인 모의 응답으로 시험한다. | 지원 유형만 고정된 인증 endpoint로 요청한다. 공급자 인증 성공만 VALID이며 403·통신 오류를 INVALID·폐기로 만들지 않는다. 수집용 App 토큰의 성공을 발견 PAT 결과로 기록하지 않는다. |
| AC-30 시간과 최신성 | VALID 뒤 UNKNOWN/UNCHECKED가 발생하고 확인 기한·조치 revision이 바뀐다. | 실제 공급자 관측·최근 시도·마지막 인증 성공을 분리한다. 실패·생략은 성공 시각을 갱신하지 않고 과거 VALID를 현재 확인으로 강조하지 않는다. 확인 기한은 토큰 만료일이 아니다. |
| AC-31 원천 재취득 | 같은 위치의 원문을 삭제·교체하거나 읽기 권한을 철회하고 유효성 확인을 요청한다. | 현재 승인·HMAC 동일성을 재검사한다. 다른 새 키를 옛 키로 검증하지 않고 재취득 실패를 INVALID·MISSING·해결로 바꾸지 않는다. 원문은 큐·DB·로그·임시 파일에 남지 않는다. |
| AC-32 검증 경합과 취소 | 다중 워커·동일 요청 재시도·lease 만료·전송 직전/직후 승인 취소를 만든다. | 실행 예약·멱등·한도를 지키고 lease를 잃은 워커가 현재 결과를 저장하지 못한다. 전송 후 취소 응답은 허용된 이력으로만 보존하고 현재 판단에 적용하지 않는다. 이미 전송된 외부 요청의 취소를 보장한다고 표시하지 않는다. |
| AC-33 영향 범위의 근거 | 수집용 관리자 계정과 최소 권한 발견 키, 일부 대상만 확인되는 토큰, 제한 통제를 조회하지 못한 키를 비교한다. | 수집 계정 권한을 발견 키 영향으로 복사하지 않는다. 지원·권한·대상·자산·제한 통제의 완전성이 부족하면 UNKNOWN이며 TEST 이름만으로 MINIMAL을 부여하지 않는다. |
| AC-34 규칙 재현과 예외 | R00~R99의 예시와 UNKNOWN·명시적 ANY·불완전 후보·METADATA_ONLY·악용 미조사를 조합한다. | 정책/우선순위/규칙에 따라 같은 결과가 나온다. R00/R01에 불필요한 축을 강제하지 않고 메타데이터를 CONFIRMED로 승격하지 않는다. NOT_CONFIRMED를 악용 없음으로 설명하지 않는다. |
| AC-35 정상·사고 충돌 | NORMAL 입력과 해당 위치의 확정 중대한 악용 근거를 함께 제공하고 최신 권한 조회를 실패시킨다. | 정상 자동 처리를 보류하고 충돌과 재검토를 표시한다. 과거 확정 사고 CRITICAL·근거·적용 중 판단을 삭제하지 않으며 자동 ABNORMAL 승격으로 충돌을 숨기지 않는다. |
| AC-36 룰 버전·재평가 | 동일 입력 재시도, 새 정책 활성화, 평가 중 근거 revision 변경과 증거 만료를 만든다. | 활성 규칙 수정과 임의 SQL/스크립트 조건을 거부한다. 평가 이력은 추가 전용이고 오래된 결과를 현재 head로 적용하지 않는다. 현재 UNASSESSED/NOT_APPLICABLE에는 등급이 없으며 LOW로 채우지 않는다. |
| AC-37 일반 자료와 수동 조정 | REMEDIATOR 자료 제출, SECURITY의 일반 자료 직접 수용, 높은 등급 하향 제안·자기 승인·승인 전 근거 변경을 수행한다. | 일반 보완에 중복 승인을 강제하지 않는다. 수동 수용을 PROVIDER_VERIFIED로 표시하지 않고 명시적 등급 조정은 독립 승인·최신 근거 확인을 요구한다. 자동 평가 원본을 덮지 않는다. |
| AC-38 위치별·역할별 표시 | 같은 키의 공개 노출·정상 보관·근거 부족 위치를 서로 다른 ACL로 조회한다. | 위치별 판단과 R00/R99를 구분한다. 현재 대응 건의 최고 유효 등급·미평가 수·제한 범위가 같은 스냅샷과 일치하고 권한 밖 근거·활동 시각을 공개하지 않는다. |
| AC-39 작업 목적과 화면 탐색 | 연결 테스트·유효성 확인·조치 후 재검사·DB 심각도 재평가를 각각 수행하고 탭·직접 링크·뒤로 가기를 사용한다. | 접수와 성공을 구분하고 목적별 결과를 섞지 않는다. ASSESS는 스캔 성공 횟수에 포함하지 않는다. 상세는 단일 패널/탭으로 표시하고 하단 누적 없이 위치·탭·필터·초점을 복원한다. |
| AC-40 검증 데이터 비노출 | 비밀 sentinel과 credential처럼 보이는 오류·헤더·표시명·evidence facts를 정상/예외/재시도 경로에 주입한다. | DB·일반 로그·stdout/stderr·HTTP 추적·APM·브라우저·CSV·백업에 원문과 전체 공급자 응답이 없다. 허용되지 않은 구조화 필드·URL·수동 PROVIDER_VERIFIED 주장을 거부한다. |
| AC-41 현황과 설정의 모수 | 운영 업무는 없고 시험 발견·대응은 있으며, 미분류 활성 범위·정책 미설정 시험 범위·중지 연결의 범위가 함께 있다. | 운영·시험 지표와 도착 목록의 출처·모수·스냅샷이 일치한다. 미분류·중지 설정은 별도 이유로 표시한다. 운영 빈 상태에서 시험 결과로 명시적으로 이동할 수 있고 설정 수를 노출 수나 안전 판단으로 읽게 하지 않는다. |
| AC-42 첫 화면의 발견 근거 | 여러 소스에서 같은 키를 발견하고 검증·영향 분석은 미지원 또는 미평가로 둔다. | 키 상세 첫 구역에서 확인할 이유·최근 검사·키와 소스의 관계를 읽고 위치 표에서 파일·줄·존재·유효성·다음 행동을 찾는다. 긴 검증 차단 목록·평가 엔진 카드가 발견 위치를 밀어내지 않는다. 위치 상세는 좌표·탐지·대응을 기본으로 표시하며 평가 근거는 펼쳐 본다. |
| AC-43 실제 처리의 연결 | 위치를 선택해 현재 대응의 담당자를 바꾸고 실제 조치를 기록한 뒤 비동기 재검사를 요청한다. | 저장 직후 담당·다음 작업과 목록이 갱신되고 성공 효과와 남은 조건을 알린다. 재검사 실행으로 이동해 대기·진행·결과를 확인한다. 미발견·키 사용 종료의 근거가 부족하면 해결을 막고 이유·다음 행동을 표시한다. 미평가 자체를 담당·외부 조치의 일괄 차단 조건으로 쓰지 않는다. |
| AC-44 선택·상세·이력 일관성 | 같은 키의 서로 다른 두 위치를 번갈아 선택하고 유효성·평가·대응·스캔 이력을 연다. | URL의 선택 위치와 실제 검증·평가 대상이 같다. 이력 선택 시 제목·초점·스크롤이 바뀌어 결과를 즉시 알 수 있다. 상세가 페이지 끝에 누적되지 않고 닫기·뒤로 가기에서 호출 위치와 필터를 복원한다. |
| AC-45 과거 판정과 최신 근거 | 범위 revision이 없는 과거 ABNORMAL 판정과 진행 중 대응에 대해 최신 심각도는 UNKNOWN으로 계산한다. | 기존 노출 판정·현재 대응을 유지하면서 최신 근거 재확인 필요를 설명한다. 같은 UNKNOWN 결과를 자동·적용 판단 두 카드로 반복하지 않고 과거 판정을 현재 재검증된 사실로 표시하지 않는다. |
| AC-46 위치와 입력의 격리 | A 위치의 대응·검증을 열고 다른 대응 또는 대응이 없는 B 위치를 선택한다. | 상단 행동·확인창·진행 요청·검증 결과가 선택 위치와 일치한다. B의 행동을 A의 대응으로 조용히 연결하지 않는다. 선택 변경 시 이전 위치의 미제출 확인·요청 상태를 새 위치에 표시하지 않는다. |
| AC-47 출처 유지와 발견 좌표 | 시험 출처에서 키 목록·연결·검사 범위·스캔 상세·실행 결과·대응·위치 확인으로 이동한다. 잘못된 저장소·범위 밖 경로도 제공한다. | 허용된 출처 선택을 URL과 화면에 유지하고 운영 0건으로 조용히 바꾸지 않는다. 대응·위치 확인에서도 승인 범위와 일치한 실제 파일·줄을 표시하며 불일치·권한 제한·민감한 경로는 안전한 별칭과 이유로 대체한다. |

## Notion 인증과 근거

| ID·시험 | 수용 조건 |
|---|---|
| AC-N01 인증과 제한 | 승인된 콘텐츠 API 토큰 후보의 정상 User는 VALID, 401 unauthorized는 INVALID/인증 거부. 403/404·비정상 응답은 정의된 UNKNOWN이며 정확한 만료·폐기 원인은 별도 근거로 관리한다. |
| AC-N02 주체와 선택 메타데이터 | 정상 인증에 결합한 NOTION_BOT UUID와 제한된 선택 owner/workspace만 기록한다. 선택 필드 미확인은 VALID와 함께 표시하며 capability·만료·전체 페이지 접근을 추정하지 않는다. |
| AC-N03 원천·형식·동일성 | GitHub/AWS/Notion 원천과 Notion/AWS/GitHub 발급자를 교차한다. ntn_/secret_ 지원 형식을 탐지·정규화·재검증에서 일치시키고 문장·설정값·코드 블록의 위치를 보존한다. 같은 bot의 다른 키는 별도 키이며 이전 키 재취득에 새 키 응답을 붙이지 않는다. |
| AC-N04 신고와 관측 | 과거 정상 인증·폐기 신고·현재 인증 거부를 각각 보존한다. 수행 시각 미상 신고를 등록하고 접수/관측 시각과 분리한다. 이후200은 조치 재확인, timeout은 확인 불가로 표시하며 일반401을 PROVIDER_VERIFIED로 승격하지 않는다. |
| AC-N05 한도와 전송 | 연결·workspace·endpoint 제한, 429/529/5xx, 긴 Retry-After, 헤더 이후 본문 정지·EOF·타임아웃을 재현한다. 전체 deadline·호출 횟수·공유 NOTION_SELF 대기를 보존하고 공급자 차단은 운영 확인 필요로 종료한다. |
| AC-N06 권한·시간·화면 | 인증·페이지 메타데이터·본문 읽기·설정상 권한을 대상·출처·시각·완전성과 함께 분리한다. 이전 VALID·현재 UNKNOWN·진행 요청과 토큰 만료·근거 TTL·다음 확인 기한을 각각 표시한다. |
| AC-N07 수집 완전성과 보호 | 승인 페이지·블록만 읽고 중첩·페이지 나눔·truncated·부분 실패를 범위 결과로 보존한다. 인증 거부를 원본 미발견으로 바꾸지 않고 원문·전체 응답·자유 제목이 DB·큐·로그·화면·CSV·AI 입력에 남지 않는다. |

숫자·단위·권한·기준시각은 [데이터 계약](../03-architecture/data-contract.md), 화면 탐색은 [화면 명세](../02-functional-design/dashboard-flow.md), 오류·동시성은 [API 계약](../03-architecture/api-contract.md)을 따른다.

유효성의 공급자별 시험은 [검증 계약](../03-architecture/credential-validation.md), 등급·근거·버전의 시험은 [평가 계약](../03-architecture/risk-assessment-contract.md)과 [심각도 정책](../02-functional-design/severity-policy.md), 사용자 확인은 [검증·심각도 화면](../02-functional-design/validation-and-risk-experience.md)을 따른다.
