## 1. 기록 단위

| 논리 기록 | 필수 정보 | 관계와 불변 조건 |
|---|---|---|
| Connection | 연결 ID, 플랫폼, 승인 범위, 권한 참조, 자원별 자산 분류 참조와 버전, 활성 상태, 범위 버전, 다음 6시간 정기 수집 예정 시각 | 플랫폼은 발견 위치의 속성이다. 키 발급자와 혼동하지 않는다. 권한 참조는 비밀 값이 아니다. 분류가 없는 자원의 중요도를 이름에서 추정하지 않는다. 범위별 대응 구분은 `UNCLASSIFIED`로 시작하며 연결 승인 시 출처와 **별도** 보관 정책의 적용·승인 근거를 등록한다. 미분류를 운영 0건으로 숨기지 않는다. |
| ConnectionProbe | 연결 ID, `IDENTITY_OR_INSTALLATION` 검사 종류, `CONNECTED\|FAILED\|UNAVAILABLE`, 안전한 사유 코드, 시도·완료 시각, 요청자·요청 ID | STS 신원 또는 설치 토큰 발급 확인의 사실만 보존한다. 연결 상태·전체 수집 성공 시각·키 유효성을 바꾸지 않는다. 공급자 응답·인증 토큰·계정 ID를 저장하지 않는다. |
| ScopeCoverageProjection | 범위 ID·현재 revision, 당시 필수 단계 구성, 최근 전체 검사 시도, 동일 revision의 마지막 성공, 예정 시각·신선도, 누락 사유 집합, 실행·진행·일시중지 참조 | 실행·범위 이력에서 파생한다. 과거 revision 성공이나 단일 위치 재검사를 전체 현재 범위 성공으로 확장하지 않는다. 누락 사유가 여러 개여도 범위 수는 하나다. 실패는 마지막 성공을 지우지 않는다. |
| ScopeOriginDecision | 승인 범위 ID, 이전·새 대응 구분, 허용된 분류 사유, 수행자, 승인자, 안전한 근거 참조, 시각, 버전 | 연결 승인 시 제안·독립 승인과 오분류 교정을 추가 전용 이력으로 남기고 영향받은 발견·대응 건을 명시적으로 처리한다. 이름·공급자·수집 허가에서 출처를 추정하지 않으며 시험 범위를 운영 집계에 포함하지 않는다. |
| StoragePolicyDecision | 정책 ID·버전, 적용할 연결·범위·브랜치·경로·콘텐츠 유형, 허용·금지 규칙, 승인자와 유효 기간 | `policyResult=ALLOWED\|DENIED\|UNKNOWN`은 판정 당시 정확한 위치·정책 버전으로 계산한다. `ALLOWED`는 근거 있는 자동 `NORMAL`의 후보, `DENIED`는 사람의 노출 확인 우선 후보이며 `UNKNOWN`은 조사 대상이다. 수집 허가나 `TEST`만으로 `ALLOWED`를 만들지 않는다. |
| ScanRun | 실행 ID, 연결 ID, 정기 또는 수동 실행 구분, 예정 및 요청, 시작, 종료 시각, 범위, 수집, 탐지, 검증 단계별 성공, 부분 실패와 사유, 실행한 도구별 상태, 버전과 설정 해시 | 실제 0건과 접근 실패를 다른 결과로 기록한다. AWS 목록 메타데이터는 범위별 안전한 콘텐츠 유형·리전·항목 수·상태·누락 코드만 조회에 제공한다. 병행 운영 시 한 도구의 실패를 다른 도구의 0건 성공으로 덮지 않는다. 재실행도 별도 실행 ID를 갖고 수동 실행은 정기 예정 시각을 바꾸지 않는다. |
| CredentialSet | 내부 ID, 발급자, 유형, `CONFIRMED`·`CANDIDATE`·`METADATA_ONLY` 구성 상태, 보호된 동일성 식별값, 최초 및 최근 발견 시각 | 동일성 식별값은 원문이나 단순 해시가 아니다. `METADATA_ONLY`는 발급처 목록에서 존재만 관측한 항목이며 Secret 값의 발견을 뜻하지 않는다. 증명되지 않은 후보와 목록 항목은 자동 병합하지 않는다. |
| CredentialSet 최초 생성 실행 | 최초 값 후보 탐지의 `firstSeenRunId`, 구성 상태·동일성 키, 생성 시각 | 동일성 키를 원자적으로 처음 삽입한 실행만 ‘신규 후보’로 센다. 동일 실행의 여러 Finding·위치와 동일 항목의 구성 승격은 중복 제거하고 이전 후보의 새 위치는 신규가 아니다. 메타데이터 관측과 재검증은 새 값 후보 집계에 넣지 않는다. 과거 기록에 실행 근거가 없으면 수는 미확인으로 남긴다. |
| Occurrence | 위치 ID, CredentialSet ID, Connection ID, 원천 객체와 버전, 위치, 환경, 최초 및 최근 발견, 노출 판정·판정 버전 | 한 키의 여러 발견 위치를 보존한다. IAM 메타데이터 항목의 위치는 승인된 계정의 목록 관측 위치이며 비정상 노출 위치가 아니다. UNKNOWN 환경을 PROD 또는 DEV로 바꾸지 않는다. 재스캔은 수동 노출 판정을 덮어쓰지 않는다. |
| Finding | 발견 ID, Occurrence ID, ScanRun ID, 엔진, 룰 ID와 버전, 마스킹된 문맥 | 같은 위치의 두 엔진 결과를 보존하되 위치 수를 중복하지 않는다. 형식 탐지 결과 자체는 비정상 노출·유효성의 자동 증거가 아니다. |
| ValidationAttempt | 시도 ID, CredentialSet ID, 실행 ID, 검증기와 버전, 요청, 완료, 결과, 사유, 승인된 엔드포인트 분류 | 시도 실패는 과거 성공 시각을 갱신하지 않는다. 원문과 공급자 응답 본문을 일반 필드에 저장하지 않는다. |
| AWS IAM 접근키 관측 | CredentialSet ID, 실행 ID, 키 상태, 발급·최근 사용·관측 시각, 최근 사용 서비스와 리전 | 실행마다 한 관측을 저장한다. `ACTIVE`는 IAM 목록의 상태이지 `VALID` 검증 결과가 아니다. 사용 기록 부재는 미사용의 증거가 아니며 노출·권한·심각도를 추정하지 않는다. |
| UsageEvidence | 증거 ID, 유형, 관측 주체, 근거 시각, 확인 범위, 출처 | 인증 가능, 사용 기록, 리소스 접근 가능, 침해 사실은 서로 다른 주장이다. 미지원과 기록 부재를 구분한다. |
| ExposureDecision | 위치 ID, `ABNORMAL`·`NORMAL` 판정, 이전 상태, 해당 위치의 Finding ID·룰·실행 ID 스냅샷, 판단에 쓴 보관 정책·버전, 안전한 근거 참조와 관측 시각, `decisionSource`, 수행자 또는 자동 정책 버전, 판정 시각, 버전 | 연결별 `SECURITY` 수동 판정과 정확한 허용 정책에 의한 `NORMAL`을 구분한다. 자동 `NORMAL`만 `POLICY` 출처로 기록할 수 있고 금지 정책은 보안 담당자 확인 전 `ABNORMAL`으로 자동 전이하지 않는다. Finding 행이 교체돼도 판정 당시 근거는 보존한다. 근거 부족은 `UNKNOWN`과 조사 과제로 남긴다. 원문·자유 문장은 받지 않는다. |
| FindingDisposition | 발견 ID, `FALSE_POSITIVE` 또는 유지, 유형별 근거 코드, 검토자, 시각, 범위 ID·객체 버전·원천/위치의 보호된 동일성 지문, 규칙·엔진 버전과 보호된 후보 동일성, 재사용 원결정 ID·만료일 | 오탐은 실제 자격 증명이 아님을 입증한 발견 결과의 정정이다. 위치의 보관 허용 `NORMAL`이나 키의 무효 `INVALID`와 혼동하지 않는다. 똑같은 근거의 재탐지만 최대 30일 `EXACT_EVIDENCE_REUSE` 행으로 연결하고, 다른 위치·버전·후보에는 자동 적용하지 않는다. 원천 식별자·키 원문을 재사용 색인이나 일반 응답에 남기지 않는다. |
| InvestigationTask | 위치 또는 범위 ID, 부족 근거 유형, 담당자, 기한, 안전한 참조, 생성·변경·완료 시각, 버전 | `NEEDS_MORE_INFO`는 노출 상태 `UNKNOWN`을 유지하고 조사·검사 복구 대기열에 남긴다. 근거가 들어와도 사람이 재판정하기 전에는 자동으로 정상·비정상으로 바꾸지 않는다. |
| TestFixtureAttestation·CrossEnvironmentAlert | 시험 목록 ID·버전, 키 ID의 보호된 일치 근거, 확인자·시각·상태; 별도 경고 ID·CredentialSet·해당 위치들·담당자·기한과 선택적 시험 건 또는 조사 과제 ID | `TEST` 출처만으로 합성 키임을 증명하지 않는다. 완전한 현재 값 후보와 유효 Finding이 있고 합성 확인이 안 된 경우에만 실키 의심 경고를 열며, 같은 키의 재검사는 열린 경고를 갱신한다. 불완전 후보·메타데이터·모두 오탐인 위치는 제외한다. 경고는 조사 과제 또는 기존 건에 연결하고 운영 대응 건 수에 더하지 않는다. 키별 합성 반증, 모든 관련 Finding의 오탐 교정 또는 실키의 수명주기 근거 없이 닫지 않는다. |
| Assessment | 평가 ID, CredentialSet ID, 위치 ID, 심각도 또는 미평가, 정책 버전, 규칙 ID, 정규화 입력, 증거 ID와 관측 시각, 누락 사유, 평가 시각, 자동 판정자 또는 수동 승인자 | 위치마다 평가하고 과거 평가는 덮어쓰지 않는다. 수동 변경은 자동 결과와 분리한다. 확인되지 않은 사실로 등급을 낮추지 않는다. |
| ResponseCase | 대응 ID, CredentialSet ID, 운영·시험 구분, 생성 원인, 단계, 예외 상태, 담당 팀과 개인, 버전, 생성 및 변경 시각 | 한 CredentialSet과 한 구분(`PRODUCTION` 또는 `TEST`)에 현재 대응 건은 최대 하나다. `TEST`는 별도 시뮬레이션 범위이며 운영 목록·집계에서 제외한다. 해결 후 같은 구분에서 재발하면 새 ID를 쓴다. |
| ResponseOccurrence | 대응 ID, 위치 ID, 연결 ID, 위치별 담당 팀·개인, 연결 시각·근거, 노출 판정, 조치 주기, 재확인, 예외 범위와 증거 | 한 위치의 해결 또는 예외가 다른 위치를 자동 처리하지 않는다. 같은 키·출처의 현재 대응 건에는 새 비정상 위치를 원자적으로 추가하며 다른 출처 건에 연결하지 않는다. |
| ActionRecord | 작업 ID, 대응 ID, 수행자, 종류, 외부 조치 시각, 기록 시각, 증거 참조 | 절차 안내와 실제 외부 실행 기록을 구별한다. 제품 실행으로 표시하지 않는다. |
| CredentialLifecycleEvidence | 대응 ID, 키 ID, 외부 교체·폐기 또는 사용 종료의 증거 유형·확인 수준·참조, 수행·관측 시각, 확인자 | 위치별 `MISSING`과 별도로 보존한다. 공급자에서 직접 확인하지 못한 외부 수행 기록은 수동 증거로 표시하며, 누락·미확인은 자동 해결 근거가 아니다. |
| CaseClosureEvidence | 대응 ID·건 버전, 위치별 조치 후 재검증·키 수명주기·미연결 위치 확인, `FULL\|LIMITED\|SIMULATION`, 승인자·시각·결과 | `SIMULATION`은 확인된 합성 fixture의 시험 종료에만 쓴다. `FALSE_POSITIVE`·`OUT_OF_SCOPE` 교정 종료는 `RESOLVED`와 다른 disposition·이력이며 실제 남은 노출을 제외하는 우회 수단이 아니다. |

위 필드와 관계는 화면과 API가 지켜야 할 논리 계약이다. 물리 테이블, 제약과 인덱스는 [데이터베이스 스키마](database-schema.md)에 정의한다. 공통 인증의 `dashboard_users`와 자산의 `assets`는 외부 참조 경계다. 일반 `detection_events`와 Secret 전용 기록은 원본을 분리하고 통합 조회에서 출처·ID·단위를 명시해 합성한다.

Secrets Manager `ListSecrets`, SSM `DescribeParameters`, S3 `ListBuckets` 결과는 범위별 개수와 실행 상태만 남긴다. **목록 응답에서 받은** 자원 이름·ARN·설명·태그와 공급자 오류 본문은 일반 DB·API·로그에 넣지 않는다. 이 목록으로 `CredentialSet`, `Occurrence`, `Finding`, `ValidationAttempt`를 만들거나 비밀 값의 노출로 집계하지 않는다. IAM 접근키 목록의 `METADATA_ONLY` 인벤토리와도 별개다.

별도로 승인한 정확한 단일 AWS 값 범위는 `secret_connection_scopes.approved_ref`에 자원 ARN 또는 버킷·객체 키가 들어갈 수 있다. 이 참조는 비밀 값은 아니지만 민감한 메타데이터이므로 DB와 백업 접근을 제한하고 일반 API·로그에 반환하지 않는다. 값 읽기 설정을 별도로 켠 경우에만 해당 본문을 작업 메모리에서 탐지한다. 발견 위치의 `source_object_ref`는 자원명 대신 안정적인 `aws-content-scope:<scope_id>` 별칭을 사용한다. 본문에서 키 후보를 찾았다는 사실은 그 저장 위치가 외부에 노출됐거나 실제로 유효하다는 증거가 아니며 노출·권한·심각도는 별도로 평가한다.

## 2. 동일성, 시간과 원문

CredentialSet의 동일성은 발급자, 유형, 구성요소 형식과 보호키 기반 식별값으로 판정한다. 구성요소가 빠졌거나 값을 검증할 수 없으면 같은 접두사, 마스킹 문자열, 위치만으로 병합하지 않는다. IAM 목록에서 받은 접근키 ID는 워커 메모리에서 보호키 HMAC으로 바꿔 `external_key_ref`에 저장하고 화면에는 끝 4자리만 표시한다. 동일한 접근키의 반복 관측은 같은 메타데이터 항목과 실행별 관측 이력으로 묶되, 원문 없이 GitHub 등에서 발견한 자격 증명과 자동 병합하지 않는다. 식별키 교체 시 이전 식별값과 새 식별값의 대응은 접근 제한된 전환 작업에서 처리하고 일반 API에 노출하지 않는다.

일반 영속 저장소에는 발견한 원문을 보관하지 않는다. 검사할 때 승인된 원천에서 필요한 값을 다시 읽고 격리된 검증 작업의 메모리에서만 사용한다. 정확한 AWS 본문 경로는 탐지·정규화와 선택적 검증을 동기 처리한 뒤 소유 `byte[]`를 지운다. 다만 AWS SDK가 Secrets Manager와 SSM의 문자열을 Java 불변 `String`으로 이미 만들 수 있어 메모리 전체 소거는 보장하지 못한다. 큐에는 원문 대신 내부 ID와 작업 ID를 넣는다. 재취득 실패는 UNKNOWN 또는 UNCHECKED와 `SOURCE_UNAVAILABLE` 사유로 남긴다. 시도 실패로 마지막 성공 판정이나 사용 메타데이터의 성공 시각을 갱신하지 않는다. 원문 정책의 근거는 [ADR-S005](adr/ADR-S005.md)에 둔다.

모든 시각은 UTC로 저장하고 API에서 UTC 시각을 반환한다. `lastAttemptAt`, `lastSuccessfulValidationAt`, `nextDueAt`, `lastCollectionSuccessAt`, `actionPerformedAt`은 각각 다른 사실이다. 조치가 마지막 유효성 판정 뒤에 있으면 `postActionValidationPending`을 표시한다. 예약 기준은 마지막 성공만을 기준으로 밀리지 않도록 직전 예정 시각과 운영 정책을 사용한다.

## 3. 현재 상태와 이력

현재 유효성은 최신 시도의 결과와 사유를 표시한다. 이전 성공 결과가 있을 때는 그 결과와 시각을 별도 필드로 보존한다. 오류 시도를 마지막 성공으로 덮어쓰지 않는다. 현재 심각도는 최신 평가와 정책 버전이며 과거 평가를 삭제하지 않는다. 대응 단계와 예외는 독립된 상태로 저장하며, 건 개설은 보안 결정 ID를 근거로 보존한다. 같은 판단의 별도 확인 검토를 요구하지 않는다.

대응 건 분포의 기본 집계는 `PRODUCTION`의 각 CredentialSet 현재 ResponseCase 한 건을 모수로 한다. `TEST` 건은 명시적인 시험 조회에서만 같은 단위로 세고 운영의 카드·매트릭스·목록·통합 현황에 포함하지 않는다. 같은 CredentialSet의 시험 건과 운영 건이 동시에 있어도 각 구분 안에서 한 번만 센다. `scope=currentCases`에서 정상 인벤토리, 대응 건이 없는 만료 및 폐기 이력, 오탐과 대상 제외로 닫은 건은 제외한다. `METADATA_ONLY`는 인벤토리에 표시하되 별도 비정상 노출 근거가 없으면 대응 건을 만들거나 심각도 분포에 넣지 않는다. `scope=inventory`는 모든 CredentialSet을 고유 항목 단위로 조회하고 정상 보관, 대응 중, 만료, 폐기 및 메타데이터만 확인한 항목을 구분한다. `scope=history`는 과거 ResponseCase를 별도 건으로 조회한다. 같은 구분·필터·기준시점에서 조치 네 단계와 전체 위험 수용 예외는 배타적으로 집계한다. 남은 미해결 위치가 모두 승인된 예외 범위에 있을 때만 예외로 센다. 다른 미해결 위치가 있으면 조치 단계에 센다. 카드, 매트릭스, 목록은 동일한 구분, `scope`, 필터와 `asOf`를 적용한다.

집계 스냅샷은 서버가 발급한 `snapshotId`로 고정한다. 이 ID는 집계에 반영한 기준시점, 범위 버전, 운영·시험 대응 구분, 대응 건 행과 수집 누락 상태를 가리키며 요약, 매트릭스, 목록에서 같은 ID를 사용한다. 이후 저장된 변경은 기존 스냅샷의 수를 바꾸지 않는다. 만료된 스냅샷 요청은 새 조회를 요구하는 오류를 반환한다. 발견 소스나 환경 필터에 여러 위치가 걸려도 해당 구분의 대응 건을 한 번만 센다.

소스와 환경 필터를 함께 적용하면 같은 발견 위치가 두 조건을 모두 만족해야 한다. 한 대응 건에 GitHub DEV 위치와 Notion PROD 위치가 따로 있다는 이유만으로 GitHub PROD 결과에 포함하지 않는다.

## 4. 보존과 복구

메타데이터, 감사 이력, 조치 증거는 서로 다른 보존 정책을 적용한다. 운영 설정에는 범주별 기간, 삭제 방식, 백업과 복구 범위를 명시한다. 기간이 정의되지 않은 범주의 자동 삭제나 무기한 보존을 기본값으로 두지 않는다. 원문은 영속 저장하지 않으므로 백업에도 포함하지 않는다. 복구 후에는 대응 단계와 감사 이력, 마지막 성공 및 최근 시도의 구분, 집계의 배타성을 검증한다.

## 5. 행동 중심 화면의 파생 사실

3절의 `currentCases`·네 단계·예외 집계는 대응 건 분포에만 적용하고, 현황의 서로 다른 업무 단위를 한 모수로 확장하지 않는다. 화면의 작업 묶음과 다음 행동은 저장된 근거를 설명하는 조회 투영이며 구성·존재·노출·유효성·심각도 상태를 대체하지 않는다.

| 파생 보기·사실 | 모수와 조건 | 다른 사실과의 관계 |
|---|---|---|
| `ongoingCases` | 같은 출처의 현재 `OPEN\|IN_PROGRESS`인 `ResponseCase` | 화면의 대응 중. 재검사 대기와 배타적이며, 두 묶음은 `ACTION_REQUIRED`의 부분집합이다. 예외·해결은 제외한다. |
| `revalidationPendingCases` | 같은 출처의 현재 `REVALIDATION_PENDING`인 `ResponseCase` | 화면의 재검사 대기. 요청만 등록됐는지·실행 중인지·실패했는지는 별도 작업 사실이다. |
| `NEEDS_DECISION` | `UNKNOWN` 또는 재검토가 필요하고 유효 Finding이 남은 `Occurrence` | 화면의 확인 필요. 같은 키의 위치가 3개면 최대 3개 위치로 세며 키 3개라고 부르지 않는다. |
| `NEEDS_CASE_LINK` | 유효 비정상 판정이 현재 건과 연결되지 않은 `Occurrence` | 확인된 노출은 이미 존재한다. 단순 UNKNOWN 후보로 낮추지 않고 무결성 복구 연결 작업을 제시한다. |
| `NORMAL_INVENTORY` | 정책상 허용 위치만 있거나, `METADATA_ONLY` 또는 근거 있는 폐기·만료 이력인 `CredentialSet` | 화면은 인벤토리, 하위는 승인 보관·메타데이터·과거 기록. 메타데이터를 정상 보관 확정으로 부르지 않는다. 전체 인벤토리는 더 넓은 별도 보기다. |
| `coverageGapScopes` | 현재 필수 승인 범위의 동일 revision에 누락 사유가 있는 고유 `Scope` | 위치·키·건과 더하지 않는다. 같은 범위의 실패·기한 초과·중지 사유가 겹쳐도 1개 범위다. |
| `crossEnvironmentAlerts` | 승인 fixture와 일치하지 않은 완전한 현재 TEST 값 후보의 열린 고유 경고 | 운영 현황에서도 허용 범위의 경고를 별도 표시하지만 운영 대응 건 수에는 더하지 않는다. |

`facts[]`는 동시에 여러 개 성립한다. 예를 들어 한 위치의 `ABNORMAL`, 최신 검사 누락, 마지막 유효성 `UNCHECKED`, 담당자 미지정은 모두 사실이며 `검사 누락` 한 라벨로 나머지를 덮지 않는다. `whyHereCode`는 목록에 포함된 이유, `nextActionCode`는 **해당 사용자에게 허용된** 다음 작업 한 개다. 우선순위와 사용자 문구는 [워크플로 상태](../02-functional-design/workflow-and-states.md), [문구와 표시 기준](../02-functional-design/content-and-labels.md)에서 정의하며 서버 템플릿으로 생성한다. 자유 입력·AI 문장·수치 점수로 우선순위를 대체하지 않는다. 근거가 없는 경우 `확인 필요`와 부족 이유를 제공하며 `LOW`를 기본값으로 만들지 않는다.

키별 위치 비교는 다음 네 축을 반드시 따로 보존한다.

| 축 | 확인하려는 사실 | 대표 근거 |
|---|---|---|
| 위치 존재 | 그 승인 위치에서 최근 비교 가능한 검사에 키가 보였는가 | 전체 검사 또는 위치 재검사의 실행·범위 revision·탐지 설정·관측 시각 |
| 노출 판정 | 그 위치가 키를 보관해도 되는 곳인가 | 위치별 보관 정책 버전 또는 근거 있는 보안 담당자 결정 |
| 위치 조치 | 담당자가 무엇을 수행했고 재검사를 기다리는가 | 위치 조치 주기·실질 외부 조치·기록 마침·재검사 작업 |
| 키 수명주기 | 실제 키가 교체·폐기되었음을 어느 수준에서 확인했는가 | 공급자 확인 또는 승인된 수동 증거. 위치의 미발견과 별개 |

기록 시각과 주장하는 사건 시각도 구분한다. 외부 작업의 `actionPerformedAt`이 오래되거나 정책·객체 버전이 다르면 최신으로 보이는 기록을 추가해도 비교 가능성이 생기지 않는다. 위치가 `UNKNOWN`이어도 마지막 확인 상태·시각을 보존하고, 실패 때문에 기존 `ABNORMAL` 판정을 지우지 않는다. 권한·자산이 확인되지 않았으면 관계도를 위해 연결을 추정하지 않는다.

## 6. 위치 집계의 권한·스냅샷·시간

현황의 `scope=workbench`, `unit=Mixed`에는 최상위 합계가 없다. 각 지표는 `unit`, 적용·해당 없음 필터, `AVAILABLE|NOT_AUTHORIZED|LEGACY_UNAVAILABLE|UNAVAILABLE`과 `value`를 가진다. 확인 가능한 실제 0만 `value=0`이고 다른 상태는 null이다. 현재 대응 건 분포는 하위 `caseSummary`의 `scope=currentCases`, `unit=ResponseCase`를 유지한다. 위치·범위·키 지표가 대응 건 분포의 합계에 들어가지 않는다.

읽기 스냅샷은 사용자 ID, 역할·권한 revision, 허용 범위 revision, 정규화 필터, 출처 구분에 묶고 기준시각·만료시각을 고정한다. TTL은 15분이며 동일 스냅샷의 카드와 도착 목록은 같은 대상 행·필터에서 계산한다. 역할 취소 시 이전 스냅샷을 즉시 무효화하고 권한 밖 행을 반환하지 않는다. 사용자당 유효 5개 상한과 만료 후 새로고침은 [API 계약](api-contract.md)을 따른다. 쓰기 명령은 읽기 스냅샷이 아닌 현재 행·정책 버전과 실제 권한으로 검증한다.

`source`와 `environment`는 같은 위치가 두 조건을 만족해야 하고, 위치 수·대표 위치·마지막 관측도 허용된 위치에서만 산출한다. 키가 여러 위치에 있다는 이유로 권한 없는 위치의 판정·담당자·시각을 합쳐 보내지 않는다. 판정 근거, 조치 기록, 범위 운영 상태는 각각 원본 접근 권한에 따라 필드를 제한한다. 보안 담당자의 위치 열람과 담당자의 할당 위치 조치를 합집합으로 계산해 모든 데이터를 공개하지 않는다. `restrictedCoverage`는 완전한 키 범위 접근을 갖지 못한 사용자에게 일관되게 주는 일반 신호이며 숨겨진 위치의 실제 존재 여부에 따라 참·거짓을 달리해 존재를 누출하지 않는다. 전체 해결 가능성은 서버의 별도 전체 권한·근거 검사로 판단한다.

안전한 표시명은 원천 경로를 자동으로 줄인 문자열이 아니다. 별도 승인한 자원·위치 별칭을 사용하고 없으면 `범위 #ID`·`위치 #ID`를 쓴다. 원문·ARN·계정·비밀이 섞인 객체 키·자유 URL·도구 문맥을 표시명에 넣지 않는다. 외부 근거 참조는 내부의 허용된 정책·티켓·변경 ID로 제한한다. 원천 직접 열기가 필요한 경우 별도 capability와 서버의 허용 URL 생성·접근 검사 계약을 충족해야 하며 이번 설계에서 공급자 권한까지 자동 보장하지 않는다.

시각 필터는 현재 상태 카드와 활동 이력을 구분한다. 현재 현황에는 기간 필터를 두지 않는다. 대응 목록은 변경 시각, 확인 대기열은 최근 발견 시각, 스캔 이력은 요청 시각에 각각 `[from,to)`를 적용한다. 화면 시간대를 UTC 경계로 바꿔 요청하며 보존 기간 전의 미확인은 실제 0건이 아니다. 상세는 스냅샷 이후 바뀐 사실을 최신으로 읽고 기준시각 차이를 표시한다.

## 7. 범위 커버리지의 시간과 분모

현재 범위는 승인된 `scope_id`와 revision, 필수 수집·탐지·검증 단계 구성으로 식별한다. 최근 시도, 동일 구성의 마지막 성공, 6시간 예정 시각, 일시중지·현재 실행 여부를 따로 보존한다. `lastSuccessfulScan`은 같은 revision의 필수 단계가 모두 성공한 전체 검사 결과다. 단일 위치 재검사, 신원 연결 테스트, 이전 revision 결과와 여러 실행의 부분 성공을 합쳐 만들지 않는다.

실행 범위의 배타적 `PENDING|RUNNING|SUCCEEDED|PARTIAL|FAILED|SKIPPED` 수 합은 그 실행의 범위 수다. `finishedScopeCount`는 종료 수, `successfulScopeCount`는 성공 수, `gapScopeCount`는 종료 중 부분·실패·건너뜀 수, `unverifiedScopeCount`는 아직 성공하지 않은 범위 수다. 현재 승인 범위의 `coverageGapScopes`는 이 실행 카운터와 달리 최근 불완전 시도·새 revision 미검사·미실행·기한 초과·일시중지를 근거로 계산한 현재 범위 수다. 두 지표를 같은 이름·분모로 표시하지 않는다.

필수 단계의 성공이 확인된 범위만 존재 부재나 검사 완료 근거가 된다. 선택적으로 비활성인 검증과 메타데이터의 해당 없음 단계는 미실행 이유를 남기되 수집 누락으로 만들지 않는다. 실행 중인 것만으로 최종 실패로 세지 않지만 이전 누락·기한 초과를 숨기지도 않는다. 범위 비활성화는 예약 분모를 바꾸는 행위이며 기존 노출이나 해결 근거를 삭제하는 행위가 아니다. 알려진 미해결 위치는 승인된 이관·종료 또는 해결 근거 없이 제외할 수 없다.

## 8. 근거 제출·확인 수준과 해결 대상

`ActionRecord`는 수행자의 외부 조치 기록이다. `CredentialLifecycleEvidence`는 그 주장에 대해 제출한 안전한 증거와 별도 검토를 연결하며, 검토한 사실과 공급자가 직접 확인한 사실을 분리한다. 외부 증거 제출은 `EXTERNAL_RECORD/PENDING`, SECURITY의 근거 검토 후에도 `APPROVED_MANUAL`이고 `LIMITED` 수준에만 사용할 수 있다. 실제 공급자 근거를 생성한 승인 워커만 `PROVIDER/PROVIDER_VERIFIED`를 남긴다. 일반 요청의 확인 수준 입력·단순 체크리스트·자기 신고·원인 불명 인증 거절은 공급자 확인으로 승격하지 않는다. 제출·검토·취소/거절은 추가 전용이고 현재 유효 근거는 해당 키·출처·적용 시각·현재 건과 비교해 선택한다.

합성 표본 attestation은 승인된 manifest ID·버전, 정확한 `CredentialSet` ID·scope revision, 내부의 보호된 일치 근거 ID, 확인 주체·시각을 함께 고정한다. 원문·마스킹 suffix·TEST 구분으로 일치시킬 수 없다. SECURITY가 승인한 manifest와 워커/신뢰된 비교기의 정확한 매칭이 모두 있어야 하며, 수동 attestation도 이 검증 결과를 참조해야 한다. manifest 만료·취소·상충하는 실제 키 근거·위치 revision 변경은 SIMULATION의 유효한 증거를 다시 확인하게 한다. 합성 확인은 위치 제거·조치 이후 재검사를 대신하지 않는다.

해결 검사의 대상은 **같은 키·같은 대응 출처**에서 다음과 같이 나눈다. 연결된 비정상 위치에는 마지막 실질 조치 이후 비교 가능한 미발견이 필요하다. 아직 연결되지 않은 유효 비정상 위치는 건 연결 대기로, 현재 값이 있거나 확인 불가인 노출 미판정 위치는 판단 대기로 차단한다. `presence=UNKNOWN`은 검사의 불확실성이고 `exposure=UNKNOWN`은 보관 판단의 불확실성이다. 노출은 미판정이지만 최신 완전·비교 가능한 검사에서 미발견인 과거 위치는 이력과 확인 한계에 보존하며 현재 PRESENT를 요구하는 판정을 강요하지 않는다. 이후 실패·범위 개정·비교 불가로 그 부재 근거가 낡으면 다시 현재 미확인 대상이 된다. 활성 정책의 정상 보관 위치는 삭제·미발견을 요구하지 않는다. 다른 출처 위치·건은 별도 경고·관련 링크로 유지하고 현재 출처 건의 단계·위치 수에 섞지 않는다.

자동 실키 의심 경고의 과제는 연결의 기본 적격 SECURITY 담당자와 기본 기한 정책이 있으면 적용한다. 미설정이면 **담당자와 기한을 각각 독립적으로 nullable**로 두고 경고·과제 생성을 성공시킨다. 이 경우 `assignmentStatus=UNASSIGNED` 또는 `dueStatus=UNSET`, 다음 행동 `ASSIGN_INVESTIGATION`을 표시하며 기한이 없는 과제를 기한 초과 수에 넣지 않는다. 사람이 `NEEDS_MORE_INFO`를 제출하는 경우의 담당자·기한 필수 조건은 유지한다. 기본 담당자 부재로 의심 경고 자체를 누락시키지 않는다.

WORKBENCH 스냅샷의 typed membership은 같은 헤더 안에서 건·위치·범위 목록으로 투영할 수 있다. 독립 생성한 CURRENT_CASES/INVENTORY/HISTORY의 ID를 다른 독립 범위에 재사용하는 것은 여전히 금지한다. 마스킹 CSV는 선택 출처와 `contentKind`·`workBucket`을 포함한 정규화 필터의 **독립 INVENTORY 스냅샷** 전체 페이지를 사용한다. 10,000개 상한·만료·권한 변경·오류 중단과 필드 보호는 [API 계약](api-contract.md)의 5.12절을 따른다.
