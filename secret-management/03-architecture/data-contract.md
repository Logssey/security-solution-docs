# 데이터 계약과 집계 기준

기준: [PRD](../01-requirements/PRD.md), [ADR-S003](adr/ADR-S003.md), [ADR-S005](adr/ADR-S005.md), [ADR-S008](adr/ADR-S008.md), [대응 정책](../02-functional-design/response-policy.md)

## 1. 기록 단위

| 논리 기록 | 필수 정보 | 관계와 불변 조건 |
|---|---|---|
| Connection | 연결 ID, 플랫폼, 승인 범위, 권한 참조, 자원별 자산 분류 참조와 버전, 활성 상태, 범위 버전, 다음 6시간 정기 수집 예정 시각 | 플랫폼은 발견 위치의 속성이다. 키 발급자와 혼동하지 않는다. 권한 참조는 비밀 값이 아니다. 분류가 없는 자원의 중요도를 이름에서 추정하지 않는다. |
| ScanRun | 실행 ID, 연결 ID, 정기 또는 수동 실행 구분, 예정 및 요청, 시작, 종료 시각, 범위, 수집, 탐지, 검증 단계별 성공, 부분 실패와 사유, 실행한 도구별 상태, 버전과 설정 해시 | 실제 0건과 접근 실패를 다른 결과로 기록한다. AWS 목록 메타데이터는 범위별 안전한 콘텐츠 유형·리전·항목 수·상태·누락 코드만 조회에 제공한다. 병행 운영 시 한 도구의 실패를 다른 도구의 0건 성공으로 덮지 않는다. 재실행도 별도 실행 ID를 갖고 수동 실행은 정기 예정 시각을 바꾸지 않는다. |
| CredentialSet | 내부 ID, 발급자, 유형, `CONFIRMED`·`CANDIDATE`·`METADATA_ONLY` 구성 상태, 보호된 동일성 식별값, 최초 및 최근 발견 시각 | 동일성 식별값은 원문이나 단순 해시가 아니다. `METADATA_ONLY`는 발급처 목록에서 존재만 관측한 항목이며 Secret 값의 발견을 뜻하지 않는다. 증명되지 않은 후보와 목록 항목은 자동 병합하지 않는다. |
| Occurrence | 위치 ID, CredentialSet ID, Connection ID, 원천 객체와 버전, 위치, 환경, 최초 및 최근 발견, 노출 판정 | 한 키의 여러 발견 위치를 보존한다. IAM 메타데이터 항목의 위치는 승인된 계정의 목록 관측 위치이며 비정상 노출 위치가 아니다. UNKNOWN 환경을 PROD 또는 DEV로 바꾸지 않는다. |
| Finding | 발견 ID, Occurrence ID, ScanRun ID, 엔진, 룰 ID와 버전, 마스킹된 문맥 | 같은 위치의 두 엔진 결과를 보존하되 위치 수를 중복하지 않는다. |
| ValidationAttempt | 시도 ID, CredentialSet ID, 실행 ID, 검증기와 버전, 요청, 완료, 결과, 사유, 승인된 엔드포인트 분류 | 시도 실패는 과거 성공 시각을 갱신하지 않는다. 원문과 공급자 응답 본문을 일반 필드에 저장하지 않는다. |
| AWS IAM 접근키 관측 | CredentialSet ID, 실행 ID, 키 상태, 발급·최근 사용·관측 시각, 최근 사용 서비스와 리전 | V6에서 실행마다 한 관측을 저장한다. `ACTIVE`는 IAM 목록의 상태이지 `VALID` 검증 결과가 아니다. 사용 기록 부재는 미사용의 증거가 아니며 노출·권한·심각도를 추정하지 않는다. |
| UsageEvidence | 증거 ID, 유형, 관측 주체, 근거 시각, 확인 범위, 출처 | 인증 가능, 사용 기록, 리소스 접근 가능, 침해 사실은 서로 다른 주장이다. 미지원과 기록 부재를 구분한다. |
| Assessment | 평가 ID, CredentialSet ID, 위치 ID, 심각도 또는 미평가, 정책 버전, 규칙 ID, 정규화 입력, 증거 ID와 관측 시각, 누락 사유, 평가 시각, 자동 판정자 또는 수동 승인자 | 위치마다 평가하고 과거 평가는 덮어쓰지 않는다. 수동 변경은 자동 결과와 분리한다. 확인되지 않은 사실로 등급을 낮추지 않는다. |
| ResponseCase | 대응 ID, CredentialSet ID, 생성 원인, 단계, 예외 상태, 담당 팀과 개인, 버전, 생성 및 변경 시각 | 한 CredentialSet의 현재 대응 건은 최대 하나다. 해결 후 재발은 새 ID를 쓴다. |
| ResponseOccurrence | 대응 ID, 위치 ID, 노출 판정, 조치, 재확인, 예외 범위와 증거 | 한 위치의 해결 또는 예외가 다른 위치를 자동 처리하지 않는다. |
| ActionRecord | 작업 ID, 대응 ID, 수행자, 종류, 외부 조치 시각, 기록 시각, 증거 참조 | 절차 안내와 실제 외부 실행 기록을 구별한다. 제품 실행으로 표시하지 않는다. |
| AuditEvent | 감사 ID, 실행 ID 또는 요청 ID, 대상, 변경 전후의 비밀 제거 값, 수행자, 시각 | 변경과 실패를 추적한다. 원문 비밀이나 전체 도구 출력을 담지 않는다. |

위 필드와 관계는 화면과 API가 지켜야 할 논리 계약이다. 물리 테이블, 제약과 인덱스는 [데이터베이스 스키마](database-schema.md)에 정의한다. 기존 `detection_events`는 일반 탐지 이력으로 유지하고 Secret 전용 기록은 별도 테이블로 연결한다. 기존 V1 마이그레이션은 수정하지 않으며 새 버전 마이그레이션으로 확장한다.

Secrets Manager `ListSecrets`, SSM `DescribeParameters`, S3 `ListBuckets` 결과는 현행 구현에서 범위별 개수와 실행 상태만 남긴다. **목록 응답에서 받은** 자원 이름·ARN·설명·태그와 공급자 오류 본문은 일반 DB·API·로그에 넣지 않는다. 이 목록으로 `CredentialSet`, `Occurrence`, `Finding`, `ValidationAttempt`를 만들거나 비밀 값의 노출로 집계하지 않는다. IAM 접근키 목록의 `METADATA_ONLY` 인벤토리와도 별개다.

별도로 승인한 정확한 단일 AWS 값 범위는 `secret_connection_scopes.approved_ref`에 자원 ARN 또는 버킷·객체 키가 들어갈 수 있다. 이 참조는 비밀 값은 아니지만 민감한 메타데이터이므로 DB와 백업 접근을 제한하고 일반 API·로그에 반환하지 않는다. 값 읽기 설정을 별도로 켠 경우에만 해당 본문을 작업 메모리에서 탐지한다. 발견 위치의 `source_object_ref`는 자원명 대신 안정적인 `aws-content-scope:<scope_id>` 별칭을 사용한다. 본문에서 키 후보를 찾았다는 사실은 그 저장 위치가 외부에 노출됐거나 실제로 유효하다는 증거가 아니며 노출·권한·심각도는 별도로 평가한다.

## 2. 동일성, 시간과 원문

CredentialSet의 동일성은 발급자, 유형, 구성요소 형식과 보호키 기반 식별값으로 판정한다. 구성요소가 빠졌거나 값을 검증할 수 없으면 같은 접두사, 마스킹 문자열, 위치만으로 병합하지 않는다. IAM 목록에서 받은 접근키 ID는 개발 워커 메모리에서 보호키 HMAC으로 바꿔 `external_key_ref`에 저장하고 화면에는 끝 4자리만 표시한다. 동일한 접근키의 반복 관측은 같은 메타데이터 항목과 실행별 관측 이력으로 묶되, 원문 없이 GitHub 등에서 발견한 자격 증명과 자동 병합하지 않는다. 식별키 교체 시 이전 식별값과 새 식별값의 대응은 접근 제한된 전환 작업에서 처리하고 일반 API에 노출하지 않는다.

일반 영속 저장소에는 발견한 원문을 보관하지 않는다. 검사할 때 승인된 원천에서 필요한 값을 다시 읽고 격리된 검증 작업의 메모리에서만 사용한다. 정확한 AWS 본문 경로는 탐지·정규화와 선택적 검증을 동기 처리한 뒤 소유 `byte[]`를 지운다. 다만 AWS SDK가 Secrets Manager와 SSM의 문자열을 Java 불변 `String`으로 이미 만들 수 있어 메모리 전체 소거는 보장하지 못한다. 큐에는 원문 대신 내부 ID와 작업 ID를 넣는다. 재취득 실패는 UNKNOWN 또는 UNCHECKED와 `SOURCE_UNAVAILABLE` 사유로 남긴다. 시도 실패로 마지막 성공 판정이나 사용 메타데이터의 성공 시각을 갱신하지 않는다. 원문 정책의 근거는 [ADR-S005](adr/ADR-S005.md)에 둔다.

모든 시각은 UTC로 저장하고 API에서 UTC 시각을 반환한다. `lastAttemptAt`, `lastSuccessfulValidationAt`, `nextDueAt`, `lastCollectionSuccessAt`, `actionPerformedAt`은 각각 다른 사실이다. 조치가 마지막 유효성 판정 뒤에 있으면 `postActionValidationPending`을 표시한다. 예약 기준은 마지막 성공만을 기준으로 밀리지 않도록 직전 예정 시각과 운영 정책을 사용한다.

## 3. 현재 상태와 이력

현재 유효성은 최신 시도의 결과와 사유를 표시한다. 이전 성공 결과가 있을 때는 그 결과와 시각을 별도 필드로 보존한다. 오류 시도를 마지막 성공으로 덮어쓰지 않는다. 현재 심각도는 최신 평가와 정책 버전이며 과거 평가를 삭제하지 않는다. 대응 단계, 검토, 예외는 독립된 상태로 저장한다.

기본 집계는 각 CredentialSet의 현재 ResponseCase 한 건을 모수로 한다. `scope=currentCases`에서 정상 인벤토리, 대응 건이 없는 만료 및 폐기 이력, 오탐과 대상 제외로 닫은 건은 제외한다. `METADATA_ONLY`는 인벤토리에 표시하되 별도 비정상 노출 근거가 없으면 대응 건을 만들거나 심각도 분포에 넣지 않는다. `scope=inventory`는 모든 CredentialSet을 고유 항목 단위로 조회하고 정상 보관, 대응 중, 만료, 폐기 및 메타데이터만 확인한 항목을 구분한다. `scope=history`는 과거 ResponseCase를 별도 건으로 조회한다. 같은 필터와 기준시점에서 조치 네 단계와 전체 위험 수용 예외는 배타적으로 집계한다. 남은 미해결 위치가 모두 승인된 예외 범위에 있을 때만 예외로 센다. 다른 미해결 위치가 있으면 조치 단계에 센다. 카드, 매트릭스, 목록은 동일한 `scope`, 필터와 `asOf`를 적용한다.

집계 스냅샷은 서버가 발급한 `snapshotId`로 고정한다. 이 ID는 집계에 반영한 기준시점, 범위 버전, 대응 건 행과 수집 누락 상태를 가리키며 요약, 매트릭스, 목록에서 같은 ID를 사용한다. 이후 저장된 변경은 기존 스냅샷의 수를 바꾸지 않는다. 만료된 스냅샷 요청은 새 조회를 요구하는 오류를 반환한다. 발견 소스나 환경 필터에 여러 위치가 걸려도 대응 건을 한 번만 센다.

소스와 환경 필터를 함께 적용하면 같은 발견 위치가 두 조건을 모두 만족해야 한다. 한 대응 건에 GitHub DEV 위치와 Notion PROD 위치가 따로 있다는 이유만으로 GitHub PROD 결과에 포함하지 않는다.

## 4. 보존과 복구

메타데이터, 감사 이력, 조치 증거는 서로 다른 보존 정책을 적용한다. 운영 설정에는 범주별 기간, 삭제 방식, 백업과 복구 범위를 명시한다. 기간이 정의되지 않은 범주의 자동 삭제나 무기한 보존을 기본값으로 두지 않는다. 원문은 영속 저장하지 않으므로 백업에도 포함하지 않는다. 복구 후에는 대응 단계와 감사 이력, 마지막 성공 및 최근 시도의 구분, 집계의 배타성을 검증한다.
