# ADR-S001 — 룰 기반 탐지와 키 유형 지원 범위

- 상태: **Accepted**
- 결정일: 2026-10-14
- 기준: [PRD](../../01-requirements/PRD.md), FR-01부터 FR-04, NFR-04

## 배경

코드·문서·설정에는 토큰뿐 아니라 키 쌍·개인키·암호·연결 문자열이 있을 수 있다. 발견 위치와 발급자는 다를 수 있으며 형식 탐지, 유효성, 실제 사용, 노출과 영향은 별도 판단이다. 비밀 탐지기는 일반 SAST의 실행 경로 분석을 대체하지 않는다.

## 결정

후보 추출기는 **Gitleaks 8.30.1**을 사용한다. AI는 탐지에 사용하지 않으며 TruffleHog는 운영 병행 엔진으로 채택하지 않는다. 탐지 도구가 원천 연결 범위나 공급자 검증 계약을 대신하지 않는다.

수집 어댑터가 승인 원천 객체·버전·위치를 추적하고 원천 객체별 텍스트를 Gitleaks stdin으로 전달한다. Git 현재 파일과 승인 이력은 독립된 수집 범위다. 탐지 도구에 연결 자격 증명을 전달하거나 Git 저장소를 워커 디스크에 복제하지 않는다. 접근 실패·크기 제한·이력 누락은 범위별 실패·미지원으로 보존한다.

기본 룰과 사용자 정의 룰·허용 목록을 버전 관리한다. 실행 파일 버전·해시·룰 ID·설정 해시·원천 위치를 남긴다. 비밀 구성요소와 공개 식별자를 구별하고 불완전 key set을 완전한 키로 표현하지 않는다. 동일성 근거 없이 다른 값을 한 자격 증명으로 묶지 않는다.

원문 포함 입력·결과는 제한된 파이프·메모리에서 처리하고 파일·보고서·일반 로그에 쓰지 않는다. 원천 위치 연결·정규화·비밀 제거 후 메타데이터만 저장한다. 실행·구조화 파싱 실패를 0건 성공으로 바꾸지 않는다. VALID·INVALID·UNKNOWN·UNCHECKED는 [별도 검증기](ADR-S002.md)만 판정한다.

## 근거와 결과

동일 합성 입력의 비교에서 요구한 유형의 후보 발견과 위치 복원·정규화에 적합한 결과를 얻은 점, 탐지와 능동 검증을 분리할 수 있는 점을 선정 근거로 삼는다. 합성 표본의 발견률은 운영 정밀도·재현율을 보장하지 않는다. 지원 유형은 [자격 증명 유형](../../04-reference/credential-types.md)과 검증된 수집 계약으로 한정한다.

룰 변경은 정상·오탐·변형·누락 구성·중복·위치 복원 회귀 사례를 통과해야 한다. 경로 문맥이 필요한 룰의 stdin 한계와 수집 누락도 별도로 확인한다. 다른 엔진을 채택할 때는 동일 입력에서 추가 발견·실패·위치·중복·원문 보호·배포 및 라이선스 조건을 비교한다. TruffleHog 평가는 `--no-verification`을 적용한다. 엔진을 추가해도 엔진별 Finding·실패는 보존하고 동일 키·위치는 중복 집계하지 않는다.
