# ADR-S001 — 룰 기반 탐지와 키 유형 지원 범위

- 상태: **Accepted — MVP 후보 추출기에 Gitleaks 8.30.1 사용**
- 제안일: 2026-10-09
- 결정일: 2026-10-14
- 기준: [PRD v0.4](../../01-requirements/PRD.md), FR-01부터 FR-04, NFR-04

## 이슈

AWS, GitHub, Notion, K8s에 연결된 코드, CI/CD 설정, 문서, 클라우드 자원에는 정형 토큰뿐 아니라 키 쌍, 개인키, 암호, 연결 문자열이 존재할 수 있다. 발견 위치와 발급자가 다를 수 있어 단순 접두사만으로 모든 유형을 판정할 수 없다.

여기서 정적 탐지는 코드의 전체 실행 경로나 취약점을 분석하는 일반 SAST가 아니라 읽은 콘텐츠에서 자격 증명 후보를 찾는 비밀 탐지다. 후보 발견과 실제 유효성, 사용 여부, 영향 평가는 서로 다른 단계다.

## 결정

MVP에서는 **Gitleaks 8.30.1**을 초기 후보 추출기로 사용한다. TruffleHog 3.99.2는 비교 대상이었으며 운영 워커에서 병행 실행하지 않는다. AI는 탐지에 사용하지 않는다. 이 선택은 [16개 합성 파일 비교 결과](https://github.com/Logssey/test-find-key/blob/86ca66a68d0e603a3da4e1e3884779c244cf3551/observations/comparison.md)에 근거한 초기 구현 결정이며, 모든 원천과 키 유형의 운영 지원 선언은 아니다.

워커의 수집 어댑터가 승인된 원천 객체, 버전과 위치를 추적하고 읽은 텍스트를 Gitleaks의 `stdin`에 전달한다. GitHub MVP는 승인된 브랜치의 현재 커밋 파일만 읽는다. 이력 검사를 추가할 때는 수집기가 파일 버전 또는 변경 내용을 읽어 같은 검사 단위로 전달한다. 수집 실패, API가 반환하지 않은 이력과 크기 제한으로 건너뛴 콘텐츠는 누락 범위로 기록한다. 탐지 도구에 수집원 연결 자격 증명을 전달하거나 Git 저장소를 워커 디스크에 복제하지 않는다. 도구의 원천 직접 스캔 기능은 수집 범위와 위치 추적을 별도로 입증하기 전까지 제품의 수집 계약을 대체하지 않는다.

Gitleaks의 기본 룰을 출발점으로 삼고 부족한 유형의 사용자 정의 룰은 설정으로 버전 관리한다. 도구명, 실행 파일 버전과 해시, 룰 ID와 설정 해시, 원천 위치를 실행 및 발견 기록에 남긴다. 키 ID나 공개 인증서처럼 단독 비밀이 아닌 구성요소는 별도로 분류하고, 불완전 key set을 유효한 전체 키로 표시하지 않는다. 룰과 허용 목록 변경은 합성 정상 및 노출 표본의 회귀 시험을 거친다.

Gitleaks는 **후보 탐지만** 수행한다. 제품의 `VALID`, `INVALID`, `UNKNOWN`, `UNCHECKED`는 별도 공급자 검증기만 판정한다. 원문을 포함할 수 있는 입력과 결과는 제한된 워커의 프로세스 파이프와 메모리에서만 처리하고 일반 파일, 보고서, 로그에 쓰지 않는다. 워커는 결과를 원천 위치에 연결해 정규화, 동일성 판정 및 비밀 제거한 뒤 메타데이터만 저장한다. 구조화 결과를 안전하게 변환할 수 없거나 실행이 실패하면 해당 검사 범위를 실패로 기록한다. 종료 코드만으로 0건 성공을 판정하지 않는다. 별도 공급자 검증기는 [ADR-S002](ADR-S002.md)를 따른다.

## 선정 근거와 한계

두 도구의 기본 설정을 사용하고 동일한 합성 파일 16개를 각각 `stdin`으로 전달했다. 양성 파일 13개 중 Gitleaks는 13개, TruffleHog는 9개에서 Finding을 냈고, 정상 파일 3개에서는 두 도구 모두 Finding이 없었다. 원시 Finding 수는 각각 23건과 10건으로, 정규화 전 구성요소별 결과이므로 논리 키나 발견 위치 수와 같지 않다. Gitleaks는 이번 표본의 공급자별 필수 룰 검사를 통과했고, TruffleHog는 Notion 토큰 세 위치와 불완전 AWS 후보 두 위치를 놓쳤다. TruffleHog의 `stdin` Finding에는 파일명과 줄 번호가 없으며, 보고서의 10/15 위치는 원문을 메모리에서 대조해 **추정한 줄** 기준이다.

표본에는 실제 발급된 키나 공급자 검증 결과가 없다. 실제 운영 파일의 오탐률, 처리량, 다른 공급자 형식의 탐지율도 측정하지 않았다. 합성 표본의 양성 파일 발견률을 운영 재현율로 해석하지 않는다. 승인된 테스트 자료와 실제 수집 경로에서 유형별 누락, 오탐, 중복, 위치 복원, 처리 시간, 부분 실패와 원문 출력 보호를 계속 검증한다. 경로 문맥이 필요한 룰이나 `stdin` 위치 손실로 빠진 유형은 지원 완료로 표시하지 않는다.

TruffleHog를 보조 탐지기로 재평가할 때는 동일 입력에서 추가로 얻는 후보와 중복, 위치 복원, 실패 처리, 원문 보호, 배포 및 라이선스 조건을 비교한다. 그때도 `--no-verification`으로 자체 능동 검증을 끄고 공급자 유효성 판단에는 사용하지 않는다. 병행 운영을 채택하면 엔진별 Finding과 실패는 구분하되 동일 CredentialSet과 발견 위치를 중복 집계하지 않는다. 선택 변경은 새 평가 근거와 함께 ADR을 갱신한다.

## 영향, 검증

- 탐지와 유효성 검사를 별도 단계로 분리한다. 탐지 결과 자체를 VALID 또는 INVALID로 변환하지 않는다.
- 유형별 정상, 오탐, 변형, 누락 구성요소 사례로 재현율과 오탐률을 측정한다.
- 운영 실행 파일 버전과 해시, 룰 설정을 고정한다. CI/CD 설정을 포함한 위치별 지원 여부와 수집 누락을 보고한다.
- 동일 키의 여러 위치와 엔진 결과를 연결하되 근거 없이 서로 다른 값들을 한 key set으로 묶지 않는다.
- Git 이력 API의 크기 제한과 `stdin`의 경로 문맥 손실을 별도 평가한다. 누락된 범위를 0건 성공으로 표시하지 않는다.
