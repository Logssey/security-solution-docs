# ADR-S002 — 6시간 검사와 영속 작업 실행

- 상태: **Accepted**
- 결정일: 2026-10-09
- 기준: [PRD](../../01-requirements/PRD.md), FR-01·FR-02·FR-05부터 FR-09, NFR-01, SEC-04·SEC-08

## 배경

승인 원천의 정기 재확인과 수동 검사는 API 요청 수명과 독립적으로 실행돼야 한다. 여러 워커·재시도·재시작에서도 중복 실행과 작업 유실을 제어하고 부분 누락을 추적해야 한다.

## 결정

각 연결의 승인 범위를 기본 **6시간**마다 재수집·재탐지한다. 완전한 자격 증명은 유형별 승인 유효성·지원 사용 메타데이터를 확인한다. 주기 내 같은 자격 증명은 중복 검증하지 않고 결과를 여러 위치에 연결한다. 최초 발견의 수집·정규화가 끝나면 첫 검증을 예약한다.

예약·대기·재시도는 PostgreSQL 작업 테이블에 대상 연결·종류·예정 시각·시도·상태·멱등 키로 영속화한다. 별도 Java 21 워커가 도래한 작업을 기본 **30초**마다 확인한다. Spring 스케줄러는 도래 작업을 찾는 기동 역할이며 DB 변경 이벤트가 즉시 검사를 실행하지 않는다. 30초 확인 간격과 6시간 검사 주기는 독립 설정이다.

여러 워커는 행 잠금으로 선점하고 lease가 만료된 실행을 복구한다. 정기 예정은 마지막 성공만을 기준으로 뒤로 밀지 않는다. 수동 검사·재검증은 독립 작업으로 등록하고 정기 예정 시각을 바꾸지 않는다. 같은 대상·목적의 진행 작업은 멱등 처리한다. API는 실행 ID·상태만 제공하고 원천 읽기·탐지·검증을 수행하지 않는다.

## 검증과 재시도 경계

공급자별 필수 구성·허용 엔드포인트·권한·응답 해석·호출 한도를 버전 관리한다. AWS는 AWS SDK for Java 2.x, GitHub·Notion은 승인된 호스트의 Java HTTP 클라이언트를 사용한다. Python·탐지 도구의 자체 검증 결과를 운영 유효성 판정자로 사용하지 않는다.

미시도는 UNCHECKED, 시도 후 결론 불가는 UNKNOWN이다. 403·404·429·타임아웃을 일괄 INVALID로 바꾸지 않는다. 검증으로 키·권한을 변경하거나 실제 데이터를 내려받지 않는다. 인증 가능성·업무 사용·권한 영향은 독립 근거로 기록한다.

호출량·백오프·최대 재시도·지연 허용치는 승인 설정으로 고정하며 한도가 없으면 능동 요청을 시작하지 않는다. 기한 초과·한도 도달은 사유와 다음 시도를 노출한다. 일부 수집 누락·재취득 실패를 무효·해결·0건 성공으로 처리하지 않는다. 최근 시도와 마지막 성공을 분리하고 실패는 과거 성공 시각을 갱신하지 않는다.

## 결과

만료·폐기가 확인된 신규 발견은 보존하되 신규 사고로 자동 개설하지 않는다. 보존 이력의 별도 재검사 범위는 운영 정책으로 설정한다. 외부 조치 이후 검사를 하기 전에는 과거 VALID를 현재 확정 결과처럼 표시하지 않는다. 검증 트래픽도 감사·사용 이력에 나타날 수 있으므로 업무 사용과 구별한다.
