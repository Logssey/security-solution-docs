# ADR-S011 — 규칙 평가와 사용 이력·AI 조사 요약의 분리

상태: Accepted

## 배경

인증 성공, 사용 기록, 권한 후보와 실제 사고는 서로 다른 증거다. 설명을 위해 외부 AI를 사용하더라도 등급의 재현성, 민감 정보 보호, 공급자 장애 시 대응 가능성이 유지되어야 한다.

## 결정

- `severity-v2`와 `risk-freshness-v1`을 유지한다. AI가 등급·근거·상태를 생성하거나 변경하지 못한다.
- AWS 관리 이벤트의 사용 조회는 정확한 키 결합·승인 범위·관측 커버리지를 가진 별도 사실 원장으로 기록한다. 일반 사용과 사고 입력을 분리한다.
- 기본 설명은 서버 규칙으로 항상 제공한다. 선택형 risk-briefing은 독립 영속 큐에서 허용 사실 코드·요청 내부 별칭만 외부 공급자에 보내고 검증된 코드 순서만 채택한다.
- 초기 공급자는 Groq openai/gpt-oss-20b다. OFF가 기본이며 실데이터 전송은 별도 SANITIZED_APPROVED 정책을 요구한다. 기존 대응 가이드의 합성 제한은 유지한다.
- 모든 replica와 기존 가이드의 호출 예산을 DB 원장으로 합산한다. 전송 불명 상태를 무료 재시도로 처리하지 않고 근거·권한 변경 뒤 낡은 결과를 적용하지 않는다.

## 결과와 검증

AI가 실패해도 평가·대응은 계속된다. 외부 모델 출력은 원문 대신 안전한 코드만 저장하고 필수 사실·다음 행동은 서버가 보장한다. 기본 설명보다 사용자 이해가 나빠지는 경우 AI를 자동화하지 않는다. 사용 조회·AI 요청은 스캔·인증 성공으로 집계하지 않는다.
