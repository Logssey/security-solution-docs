# ADR-S010 — 근거 중심 Secret 검토와 대응 완결

- 상태: **Accepted**
- 결정일: 2026-10-19
- 개정일: 2026-10-21
- 기준: [PRD](../../01-requirements/PRD.md), [ADR-S003](ADR-S003.md), [ADR-S004](ADR-S004.md), [ADR-S005](ADR-S005.md), [ADR-S008](ADR-S008.md)

## 문제

수집·탐지 기록만으로는 보관 허용 여부·우선 조치·해결을 판단할 수 없다. 출처·보관 정책·수집 완전성·접근 범위·검증 최신성·위치별 조치·검사 한계를 별도 근거로 제공하고, 보안 판단을 중복 승인 없이 대응과 연결해야 한다. 건 전체 해결은 위치 미발견과 키 수명주기 증거를 함께 요구한다.

## 결정

### 서로 다른 사실을 분리한다

수집을 허가한 범위는 **읽어도 되는 곳**이다. `TEST`·`PRODUCTION`은 대응 집계의 출처 구분이고, 해당 위치에 키를 **보관해도 되는지**는 버전이 있는 별도 정책으로 판정한다. 구성요소의 완전성, 현재 존재, 유효성, 사용, 권한·영향, 심각도, 조치 단계도 독립된 사실이다. 어느 한 사실로 다른 사실을 자동 확정하지 않는다. `METADATA_ONLY`는 비밀 값 노출 후보가 아닌 인벤토리다. 시험 출처 역시 안전하다는 뜻이 아니다.

### 연결 승인에서 출처를 구분하고 교정한다

새 범위는 수집 허가와 별도로 `TEST` 또는 `PRODUCTION`의 결정 근거, 결정자, 정책·범위 버전을 기록한다. 알려진 합성 표본은 시험 출처로 제한하지만 다른 시험 범위를 이름만 보고 자동 분류하지 않는다. 혼합 원천은 범위를 나눈다. 기존 `UNCLASSIFIED` 범위와 정책 미설정·검토 대기는 **운영 설정**의 원인별 작업으로 표시하며 위치의 확인 필요·대응 단계와 구분한다. 선택 출처의 활성 설정과 전역 미분류·중지 연결의 모수는 [화면](../../02-functional-design/dashboard-flow.md)·[API 계약](../api-contract.md)을 따른다. 출처 미확인 상태에서 운영/시험 대응 건 분류는 보류해도 보안 담당자의 조사·임시 조치 안내는 막지 않는다.

범위·정책 연결과 기존 위험 처리를 유지하는 SECURITY의 일반 운영·시험 분류는 source-label-v2의 직접 저장으로 처리한다. 외부 티켓을 필수 입력으로 요구하지 않고 수행자·시각·변경 이력을 자동 기록한다. 알려진 합성 시험 대상의 운영 분류 제한은 유지한다. 보관 정책 변경은 제안자와 다른 SECURITY의 독립 검토를 요구한다. OPERATIONS만 가진 제안자에게 보안 결정 권한을 부여하지 않는다. 직접 처리할 작업까지 일괄 독립 승인하지 않고, 검토 필수 변경은 단독 운영에서도 자동 승인하지 않는다. 기준은 [사용자 작업과 승인 기준](../../02-functional-design/task-and-approval-policy.md)을 따른다.

변경 전후·근거·수행자·승인 방식·규칙 버전을 추가 전용으로 보존한다. 교정 뒤 기존 발견·대응 건·경고를 자동 이동·종료하지 않고 영향 목록을 검토해 명시적으로 연결하며 집계 스냅샷을 새로 만든다. 출처를 저장한 뒤 정책·기존 대응 검토가 남으면 해당 이유와 다음 행동을 계속 표시한다.

`TEST`는 수집 출처의 구분이며 발견한 키가 합성이라는 증명은 아니다. 키별 승인 fixture 목록과 일치해야 합성 시험으로 인정한다. 일치하지 않으면 확인 과제로 남기고, 실제 외부 키로 확인되면 시험 건과 별도로 운영 보안 담당자에게 교차 환경 경고를 띄운다. 경고는 운영 건수에 합산하지 않되 운영 화면에서 누락하지 않는다.

완전한 값 후보가 현재 발견됐고 유효한 Finding이 남아 있는 `TEST` 위치에서 키별 합성 증명이 없으면 `POSSIBLE_REAL` **실키 의심 경고**를 즉시 열고 담당자·기한·해당 위치를 연결한다. 불완전 후보, 메타데이터 관측과 모두 오탐으로 교정된 Finding은 경고 대상이 아니다. 시험 대응 건이 이미 있으면 건에, 아직 개설 조건을 충족하지 못했으면 조사 과제에 연결한다. 같은 키의 재검사는 열린 경고를 갱신하고 중복 생성하지 않는다. 공급자 근거로 실키가 확인되면 같은 경고를 승격한다. 나중에 합성 또는 전체 Finding 오탐이 입증되면 증빙을 검토해 경고를 닫는다. 인지 기록은 조치 완료가 아니다.

### 사람이 볼 항목을 근거로 고른다

서버는 후보를 `조치 필요`, `확인 필요`, `인벤토리`, `검사 누락`의 **표시용 작업 묶음**으로 도출한다. 이는 유효성 또는 심각도 enum을 대체하는 새 판정이 아니다. 목록에는 마지막 성공 검사와 최근 시도, 현재 존재 여부, 정책 근거, 검증 결과와 시각, 소유자, 알 수 없는 이유와 다음 행동을 제공한다. 스캔 누락, 정책 근거 없음, 불완전 후보는 정상 0건으로 처리하지 않는다. 안전하게 증명된 합성 표본 또는 승인 보관은 별도 표시할 수 있으나 단순한 `TEST` 표식이나 수집 허가만으로 정상 판정하지 않는다.

사람의 결정은 `ABNORMAL`, `NORMAL`, `FALSE_POSITIVE`, `NEEDS_MORE_INFO`를 구별한다. `FALSE_POSITIVE`는 형식 탐지가 자격 증명이 아님을 입증한 경우이고 `NORMAL`은 자격 증명이지만 그 위치의 보관이 정책상 허용된 경우다. `NEEDS_MORE_INFO`는 기존 노출 상태 `UNKNOWN`을 유지하며 부족 근거 코드, 조사 담당자, 기한과 안전한 작업 참조를 남긴다. **예외적으로** `CONFIRMED`·`PRESENT` 값 위치에 유효 Finding이 있고 정확한 위치·콘텐츠 유형·범위·유효 기간에 일치하는 명시적 허용 규칙이 있으면 정책 ID·버전·적용 근거·자동 판정자를 남기고 해당 위치를 `NORMAL`로 자동 기록할 수 있다. 금지 규칙은 보안 검토 권고만 만들며 `ABNORMAL`·대응 건을 자동 생성하지 않는다. 규칙 부재·충돌·만료는 `UNKNOWN`이다. 재스캔·정책 변경이 근거를 낡게 만들면 재검토 대상으로 돌리고 과거 결정을 삭제하거나 수동 결정을 조용히 덮지 않는다.

### 한 번의 보안 결정으로 대응을 시작한다

보안 담당자가 `ABNORMAL`을 확정하면 **노출 확인 및 조치 요청** 명령 한 번에서 위치 판정, 동일 키·동일 출처 구분의 현재 대응 건 생성 또는 해당 건에 위치 연결, 감사 기록을 원자적으로 저장한다. 동일한 노출 근거의 재승인을 조치 시작 조건으로 요구하지 않는다. 대응 시작 시각 기록과 계획 보완은 별도로 남길 수 있지만 동일 노출의 재판정은 요구하지 않는다. 근거가 부족하면 대응을 완료했다고 표시하지 않고 조사 작업으로 남긴다. 여러 위치의 담당자·조치·재검증은 위치별로 관리하고 보안 담당자는 건 전체를 조정한다. 같은 키의 새 비정상 위치는 열려 있는 건에 연결하고, 해결 이후 새 노출은 이전 건과 연결된 새 건으로 연다.

### 해결은 실제 조치와 재확인 근거를 요구한다

가이드·체크리스트·검토 완료는 위험 제거 증거가 아니다. 외부에서 수행한 교체·폐기 또는 더 이상 사용되지 않음을 입증한 수명주기 근거와, **모든 관련 위치**의 조치 이후 비교 가능한 재검사 결과를 분리해 기록한다. 현재 파일에서 `MISSING`은 그 파일에서 다시 찾지 못했다는 사실만 뜻한다. 공급자 키 폐기, Git 과거 이력, 미승인·미지원 원천까지 확인한 것으로 확대하지 않는다. 미연결 비정상 위치, 실패·부분 실패·비교 불가 검사, 조치 이후 키 상태 미확인은 해결을 막고 부족 근거를 보여준다. 공급자 API 확인이 불가능하면 검증되지 않은 사실을 숨기지 않고 승인된 외부 수행 증거와 확인 수준을 별도로 표시한다. 남은 위험의 수용은 만료가 있는 별도 예외 절차이며 `RESOLVED`와 합치지 않는다.

현재 `UNKNOWN` 위치는 단순 범위 제외로 해결 조건에서 뺄 수 없고 근거를 갖춰 먼저 판정한다. 승인 fixture로 확인된 합성 `TEST` 건은 fixture 제거와 비교 가능한 재검사로 `SIMULATION` 수준의 시험 종료를 기록하며 실제 공급자 키 폐기라고 표현하지 않는다. 합성 여부가 불명확하거나 실제 키로 확인된 시험 건에는 이 경로를 허용하지 않는다. 최초 노출 판정 자체가 틀렸던 건의 교정 종료는 `RESOLVED`와 구분해 이력에 남긴다.

### 스캔 범위와 결과를 정확히 읽게 한다

실행의 범위 상태는 `PENDING`, `RUNNING`, `SUCCEEDED`, `PARTIAL`, `FAILED`, `SKIPPED`를 배타적으로 센다. `종료`는 성공이 아니며 `누락/미확인`에는 실패·부분 실패·건너뜀과 아직 끝나지 않은 범위를 이유별로 표시한다. 수집 항목 수, 후보 발견 수, 새 고유 키 수, 노출 판정 수는 각각 다른 단위다. 상세에는 실행 당시 승인 범위 버전과 안전한 표시 별칭, 단계별 결과, 빠진 범위, 다음 재시도, 이 실행에서 확인한 후보 링크를 제공한다. 자원명·ARN·원문을 별칭으로 자동 추출하지 않는다. 스캔 이력 상세는 독립 주소를 사용하며 목록의 필터·페이지·포커스를 보존한다.

## 위치 시각화와 행동 중심 조회

주 화면의 사용자 표시는 `확인 필요`, `대응 중`, `재검사 대기`, `검사 누락`으로 구체화한다. 내부 `NEEDS_DECISION`과 네 조치 단계 enum은 보존한다. `NORMAL_INVENTORY`의 사용자명은 메타데이터를 정상 보관으로 오해하지 않도록 `인벤토리`로 쓴다. 현황 카드마다 위치·건·범위 단위와 기준시점을 명시한다. 키별 위치 증거 표를 기본 시각화로 삼고 근거 없는 권한·자산 관계선을 추가하지 않는다.

화면의 긴 정책 문구는 상태·한 줄 이유·다음 행동으로 요약하되 결정에 필요한 부족 근거와 확인 한계는 숨기지 않는다. 시험 출처는 명시적 보기와 독립 상세에 표시하며 실키 의심 경고를 가리지 않는다. [위치 시각화](../../02-functional-design/location-visualization.md), [문구 기준](../../02-functional-design/content-and-labels.md)에 상세를 둔다.

모든 상세는 진입 이유·가능한 행동·차단 원인·완료 조건·저장 후 결과를 제공한다. 소스별 위치 비교에서 남아 있는 필수 대응 위치와 키 사용 종료를 각각 확인하고 같은 키의 실제 조치·재검사까지 연결한다. 담당자가 자동 계산 가능한 사실을 다시 입력하지 않게 하며, 필요한 권한이 없으면 허용된 담당 역할·내부 요청·대기 내역을 제공한다. 업무 요청은 기존 조사 모델을 재사용하며 상태 입력·탐지 수 감소·시험 재분류를 위험 감소로 주장하지 않는다.

## 불변조건

ADR-S003의 독립 상태 축·네 조치 단계·배타적 집계와 ADR-S004의 외부 키 자동 변경 제외를 유지한다. 판정·대응 건 연결·감사는 하나의 명령에서 원자적으로 저장한다. `ABNORMAL`이지만 현재 건에 연결되지 않은 위치는 `NEEDS_CASE_LINK` 무결성 복구 대상으로 표시하고 조치 대기열에서 숨기지 않는다. 과거 감사·조회·조치 기록을 보존하며 근거 없이 노출·검토·해결 상태를 소급 확정하지 않는다. 모든 건은 같은 해결 증거 조건을 적용한다.

수용 기준과 필드·주소는 [검토 정책](../../02-functional-design/triage-policy.md), [대응 정책](../../02-functional-design/response-policy.md), [스캔 이력 정책](../../02-functional-design/scan-history-policy.md), [API 계약](../api-contract.md), [데이터 계약](../data-contract.md)에 둔다.
