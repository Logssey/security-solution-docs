# ADR-S003 — 독립 상태와 4단계 조치 집계

- 상태: **Accepted**
- 결정일: 2026-10-09
- 기준: [PRD](../../01-requirements/PRD.md), FR-08부터 FR-13·FR-15

## 배경

유효성·심각도·노출 판단·조치를 한 상태로 표현하면 검토·체크리스트 완료를 해결로 오해할 수 있다. 같은 키의 여러 위치와 운영·시험 출처도 집계 단위가 다르다.

## 결정

유효성·구성·존재·노출·심각도·조치는 독립 축으로 관리한다. 조치 상태는 OPEN·IN_PROGRESS·REVALIDATION_PENDING·RESOLVED의 네 단계이며 사용자 표시는 **신규 / 조치 중 / 재검사 대기 / 해결**이다. 위험 수용 예외는 별도로 집계하고 네 단계와 중복 계산하지 않는다. 오탐·대상 교정·위험 수용은 서로 다른 결과다.

한 CredentialSet·출처 구분마다 현재 ResponseCase는 최대 한 건이다. 여러 위치·Finding을 그 건에 연결하고 키·위치·건 수는 별도 단위로 표시한다. PRODUCTION·TEST·UNCLASSIFIED는 현재 건이 각각 존재할 수 있다. 일반 화면은 ALL로 조회하고 caseId로 한 번씩 세며 원본 origin 관계는 합치지 않는다. 자격증명 확인 경고는 별도 단위로 제공한다.

해결 후 같은 출처의 새 노출은 이전 건과 연결된 새 건으로 연다. 한 위치의 해결·예외로 다른 위치를 전체 해결·예외에 숨기지 않는다. 동일 범위의 네 조치 단계·전체 예외는 배타적으로 집계하며 카드·목록·시각화는 같은 권한·필터·기준시점·단위를 사용한다. 현황의 확인 필요 위치·검사 누락 범위는 대응 건 단계와 합산하지 않는다.

## 근거와 결과

단계 변경은 [대응 정책](../../02-functional-design/response-policy.md)의 실제 조치·재검사·수명주기 증거에 따른다. 검토·체크리스트 완료, 만료·폐기된 보존 이력만으로 해결을 만들지 않는다. 검증 불가는 위험 수용 예외가 아니다. 예외에는 별도 승인·만료·복귀와 감사가 필요하다.

상태·집계의 명세는 [워크플로](../../02-functional-design/workflow-and-states.md), 저장 관계는 [데이터 계약](../data-contract.md), 변경 명령은 [API 계약](../api-contract.md)을 따른다.
