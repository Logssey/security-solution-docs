# ADR-S003 — 상태 분리와 4단계 조치 현황

- 상태: **Accepted — 독립 상태 축, 대응 단위와 배타적 조치 집계**, 물리 테이블은 구현 계약에서 구체화
- 결정일: 2026-10-09
- 보완일: 2026-10-15 — `TEST` 시뮬레이션 범위를 운영 대응 건과 분리
- 기준: [PRD v0.4](../../01-requirements/PRD.md), FR-08부터 FR-13, FR-15

## 이슈

유효성, 심각도, 검토, 조치 상태를 혼합하면 검토 완료가 해결로 보이거나 검증 실패가 낮은 위험으로 보일 수 있다. 한 자격 증명이 여러 위치에서 발견될 수 있으므로 집계 대상과 위치별 근거도 분리해야 한다.

## 최종 결정

조치 막대는 **신규 및 분석 / 조치 중 / 재검증 대기 / 해결** 네 단계로 표시하고 **예외는 별도로 집계**한다. 같은 대응 건을 네 막대와 예외에 중복 집계하지 않는다. 유효성, 심각도, 검토, 조치는 독립 축으로 관리한다. 검토 완료와 체크리스트 완료만으로 해결 처리하지 않는다.

## 논리 상태 모델

OPEN, IN_PROGRESS, REVALIDATION_PENDING, RESOLVED를 네 막대에 대응시킨다. 위험 수용 예외를 분리하며 오탐과 대상 제외를 자동으로 위험 수용에 합치지 않는다. API 응답의 enum은 [API 계약](../api-contract.md)에 맞춘다.

운영 범위에서 한 CredentialSet에는 현재 ResponseCase를 최대 하나 둔다. 합성 시험을 운영 사고로 세지 않기 위해 `TEST`를 별도 시뮬레이션 범위로 분리한다. 같은 CredentialSet이라도 운영과 시험 노출이 각각 확인되면 범위별로 현재 건이 하나씩 존재할 수 있다. 운영 화면·집계의 기본 범위는 `PRODUCTION`이며 `TEST` 건을 포함하지 않는다. 시험 건은 명시적으로 선택한 시험 조회에서만 센다. 여러 발견 위치와 탐지 결과는 해당 범위의 건에 연결하되 각각의 수를 구분한다. 해결 후 같은 범위에서 새 노출이 생기면 새 대응 건을 만든다. 한 위치만 해결되거나 예외가 승인된 경우 다른 노출 위치를 전체 해결 또는 전체 예외로 숨기지 않는다. 같은 범위의 현재 대응 건에 대해 네 막대와 전체 예외는 배타적으로 집계하며 화면 카드, 목록, 매트릭스는 같은 필터, 기준시점, 집계 단위를 사용한다.

## 영향, 검증

저장 모델에는 재검증 대기, 유효성, 미평가 심각도와 예외 이력을 표현할 수 있어야 한다. 조치 추적 대상의 네 막대와 별도 예외는 같은 집계 단위의 대상 목록과 일치해야 한다. 만료 또는 폐기된 보존 이력을 자동으로 해결 막대에 넣지 않는다.

최종 해결 증거, 예외 승인 권한과 만료 후 복귀는 [대응 정책](../../02-functional-design/response-policy.md)과 [API 계약](../api-contract.md)을 따른다. 검증 불가는 예외 승인과 다르다.
