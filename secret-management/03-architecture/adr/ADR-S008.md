# ADR-S008 — 대시보드와 Secret 실행·데이터 경계

- 상태: **Accepted**
- 결정일: 2026-10-09
- 기준: [PRD](../../01-requirements/PRD.md), FR-04부터 FR-15, NFR-03·NFR-05, SEC-02·SEC-05

## 배경

탐지·검증·영향 평가·대응은 갱신 주기와 권한이 다르다. 화면에 같은 기준시점의 집계·상세 근거를 제공하면서 비밀 원문과 내부 실행 데이터는 차단해야 한다.

## 결정

화면은 **React·TypeScript**, API는 **Java 21·Spring Boot**, 메타데이터·영속 작업은 **PostgreSQL**, 스키마 변경은 **Flyway**를 사용한다. 수집·탐지 도구 실행·정규화·검증은 API와 별도 Java 워커 프로세스에서 수행한다. API·워커는 도메인 계약을 공유할 수 있지만 실행 계정·원문 접근·네트워크 권한을 분리한다. Python을 제품 실행 계층으로 도입하지 않는다.

API는 화면의 유일한 조회·변경 경계이며 인증·대상 범위 권한·마스킹·입력 검증·감사·동시 변경 통제를 적용한다. 조회는 외부 스캔을 시작하지 않는다. 작업 등록은 고정된 종류·내부 대상 ID만 허용해 임의 명령 실행 경로가 되지 않게 한다. 화면에는 위치·발급자·구성·유효성·심각도·최신성·담당자·조치 근거를 제공하고 원문은 반환하지 않는다.

## 논리 저장 모델

Connection·ScanRun, CredentialSet·Occurrence, ValidationAttempt, Assessment, ResponseCase·AssignmentHistory를 구별한다. 범용 detection_events는 일반 탐지 이력이며 Secret 기록의 원본은 전용 모델이다. 통합 조회는 권한·단위·기준시점을 맞춰 전용 기록을 합성한다. 동일 이벤트를 양쪽에서 중복 집계하지 않는다.

CredentialSet·출처마다 현재 대응 건은 최대 하나이며 여러 위치·시도·조치·재발 이력을 보존한다. TEST는 PRODUCTION과 분리하고 기본 운영 조회에서 제외하되 실키 의심 경고는 숨기지 않는다. 재검사 대기·미평가·환경 미확인·위치별 담당자를 독립적으로 표현한다.

물리 DB 위치와 실행 배치는 환경별 설정이다. 논리 경계가 물리 DB 한 개·독립 DB 여러 개 또는 모든 프로세스의 무제한 쓰기 권한을 뜻하지 않는다. 마이그레이션은 기존 이력을 보존하고 공통 DB 담당자가 번호·순서를 조율한다. 발행된 마이그레이션을 덮어쓰지 않는다.

## 도구와 원문

Gitleaks 8.30.1은 워커의 외부 실행 파일이며 Java 라이브러리로 재작성하지 않는다. 추가 엔진은 별도 결정과 회귀 검증을 거친다. 엔진별 실행·Finding·실패는 구분하고 동일 키·위치는 중복 집계하지 않는다. AWS·K8s는 공식 Java SDK, GitHub·Notion은 승인 REST 엔드포인트를 사용한다.

원문은 워커의 제한된 메모리에서만 처리한다. API에는 원문 접근 권한을 주지 않으며 PostgreSQL에는 마스킹 근거·식별값·검사·평가·대응·감사만 남긴다.

## 결과

카드·목록·시각화는 같은 권한·필터·기준시점·집계 단위를 사용하고 실제 수집·검사 시각을 표시한다. 쓰기는 최신 권한·기대 버전을 재검사하며 판정·건 연결·감사를 원자 저장한다. 구체적 관계와 변경 명령은 [데이터 계약](../data-contract.md), [DB 스키마](../database-schema.md), [API 계약](../api-contract.md)을 따른다.
