# ADR-S008 — 기존 대시보드 연동과 데이터 확장

- 상태: **Accepted — Java API와 워커 분리, PostgreSQL 데이터 경계**
- 결정일: 2026-10-09
- 기준: [PRD v0.4](../../01-requirements/PRD.md), FR-04부터 FR-15, NFR-03, NFR-05, SEC-02, SEC-05

## 이슈

탐지 결과, 검증 이력, 영향 평가, 담당자와 조치 기록은 갱신 주기와 접근 권한이 다르다. 대시보드에는 같은 기준시점의 집계와 상세 근거를 제공하면서 비밀 원문과 내부 실행 데이터를 차단해야 한다.

## 결정

대시보드 API가 화면의 유일한 조회 및 변경 경계가 된다. API에서 인증, 권한 검사, 서버 측 마스킹과 입력 검증을 적용한다. 화면에는 발견 위치, 발급자, 유효성, 심각도, 최신성, 담당자와 조치 근거를 제공하며 원문을 반환하지 않는다. URL과 응답의 논리 계약은 [API 계약](../api-contract.md), 기록 관계는 [데이터 계약](../data-contract.md)에 정의한다.

Connection/ScanRun, CredentialSet/Occurrence, ValidationAttempt, Assessment, ResponseCase/AssignmentHistory를 논리적으로 구분한다. 한 key set의 여러 발견 위치, 검사 시도와 대응 이력을 보존한다. Notion 연결, 재검증 대기, 심각도 미평가, 환경 미확인과 개인 담당자 표시를 데이터 계약에 포함한다.

## 구현 계약

기존 detection_events는 일반 탐지 이력으로 유지하고 Secret 전용 모델을 별도 논리 기록으로 연결한다. 한 CredentialSet의 현재 ResponseCase는 최대 한 건이며 발생 위치별 판정과 조치 근거를 보존한다. [데이터 계약](../data-contract.md)과 [API 계약](../api-contract.md)에 필드, 집계와 변경 경계를 정의한다. 실제 테이블 배치와 기존 저장소 통합은 코드 확인 후 새 마이그레이션으로 구현하며 기존 저장소 배치 ADR의 상태를 이 문서가 변경하지 않는다.

새 Secret 기능은 기존 기술 기반을 따른다. 화면은 **React와 TypeScript**, 인증 및 대시보드 API는 **Java 21과 Spring Boot**, 메타데이터와 영속 작업 대기열은 **PostgreSQL**, 스키마 변경은 **Flyway**로 구현한다. 수집, 탐지 도구 실행, 정규화와 공급자 검증은 API와 분리된 Java 워커 프로세스에서 수행한다. MVP 후보 탐지 도구는 [ADR-S001](ADR-S001.md)에 따라 Gitleaks 8.30.1을 사용한다. API와 워커는 필요한 도메인 계약을 공유할 수 있지만 실행 계정, 연결 권한과 네트워크 접근은 분리한다. Python을 제품의 기본 실행 언어나 별도 작업 계층으로 도입하지 않는다.

Gitleaks는 독립 실행 파일로 실행하며 Java 라이브러리로 다시 작성하지 않는다. 향후 다른 도구의 병행 운영을 선택해도 도구별 실행 상태와 발견 근거를 구분하고 동일 키와 위치는 중복 집계하지 않는다. AWS와 K8s는 공식 Java SDK, GitHub와 Notion은 승인된 REST 엔드포인트를 호출하는 Java HTTP 클라이언트를 사용한다. 워커는 원문을 메모리에서만 처리하고 API는 원문 접근 권한을 갖지 않는다. PostgreSQL에는 마스킹된 탐지 근거, 식별값, 검사, 평가와 대응 이력만 저장한다. 대시보드 API가 워커의 임의 명령 실행 경로가 되지 않도록 작업 종류와 대상 ID를 고정한다.

별도 Python 서비스와 API 프로세스 안에서의 전체 스캔은 초기 구조로 채택하지 않는다. TruffleHog의 운영 추가 여부는 [ADR-S001](ADR-S001.md)의 재평가 조건에 따라 정한다. 합성 비교에서 두 도구를 각각 실행한 사실을 운영 병행 결정으로 간주하지 않는다. 실제 코드 버전과 PostgreSQL 배포 위치는 구현 시 확인하되 위 책임과 보안 경계는 유지한다.

## 영향, 검증

기존 대시보드의 인증과 조회 계약을 확인해 전환 계획, enum 마이그레이션, 집계 기준을 설계한다. UI의 수집 시각은 실제 수집 실행 이력에 연결한다. 쓰기 API에는 권한 검사, 입력 검증, 감사 이력과 동시 변경 처리를 포함한다. 카드, 목록, 매트릭스는 같은 필터와 기준시점에서 같은 수를 보여야 한다.
