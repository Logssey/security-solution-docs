# 보안 경계와 실행 정책

기준: [PRD](../01-requirements/PRD.md) SEC-01부터 SEC-08, [ADR-S002](adr/ADR-S002.md), [ADR-S004](adr/ADR-S004.md), [ADR-S005](adr/ADR-S005.md), [ADR-S006](adr/ADR-S006.md)

## 1. 신뢰 경계

| 경계 | 실행 정책 |
|---|---|
| 수집 연결 | 연결마다 조직, 계정, 저장소, 페이지, 네임스페이스와 콘텐츠 종류의 승인 범위를 저장한다. 범위 밖 자료를 0건 성공으로 보고하지 않는다. |
| 자격 증명 | 수집용 계정, 공급자 검증용 계정, 발견한 비밀은 권한과 접근 경로를 분리한다. 수집 및 검증 역할에는 외부 키 교체, 폐기, 재발급, 권한 변경 권한을 부여하지 않는다. |
| 탐지 입력 | 코드, 문서, 설정, 도구 출력은 비신뢰 데이터다. 파서 입력 크기와 형식을 제한하고, 화면은 텍스트로 렌더링한다. |
| 검증 호출 | 발급자와 유형별로 검증기, 허용 호스트와 엔드포인트, 요청 방법, 권한, 호출량을 승인 목록으로 관리한다. 발견한 URL과 kubeconfig의 exec 명령은 실행하지 않는다. |
| 내부 작업 | 큐에는 원문을 넣지 않는다. 작업자는 필요한 순간에 승인된 원천에서 값을 재취득하고 메모리에서만 사용한다. 원문 포함 오류와 도구 출력을 일반 로그에 남기지 않는다. |
| 대시보드 | API가 인증, 대상 범위 권한, 서버 측 마스킹과 변경 감사의 유일한 경계다. 브라우저는 원문을 받지 않는다. |

K8s 내부 Secret은 초기 범위에 포함한다. Kubernetes API 접근은 AWS 관리 API와 별도 인증 및 최소 RBAC를 사용한다. 수집 워커의 배치 위치는 클러스터 네트워크에 따라 정하되 동일한 수집 계약, 감사와 권한 검사를 적용한다. Pod exec, 노드 파일, etcd 직접 접근은 초기 수집 경로가 아니다.

대시보드 API와 수집 및 검증 워커는 별도 Java 프로세스로 운영한다. 워커만 승인된 원천과 검증 엔드포인트에 접근하고 MVP에서는 [ADR-S001](adr/ADR-S001.md)에 따라 Gitleaks 8.30.1을 후보 탐지에 사용한다. 탐지 도구에 수집원 연결 자격 증명을 전달하지 않는다. 스캐너 입력과 원문 포함 결과는 보호된 프로세스 파이프와 작업 메모리에서만 처리한다. 도구 실행 또는 결과 파싱이 실패하면 해당 범위를 실패 또는 부분 실패로 기록한다. API에는 원문 재취득과 스캐너 실행 권한을 주지 않는다.

## 2. 수집과 재검사

정식 정기·수동 수집과 탐지는 별도 Java 워커에서 실행한다. API의 `POST /api/v1/secrets/runs`는 작업만 등록하고 실행 상태를 조회하며 서버 시작이나 샘플 데이터 적재를 계기로 외부 스캔을 수행하지 않는다. 새 `/secrets` 화면은 비동기 경로를 사용한다. 전환 기간에 남아 있는 `/api/v1/credentials/scan`의 동기 Notion 실행 경로는 다른 사용처를 확인한 뒤 제거한다. 워커의 예약기와 작업 실행기, GitHub 파이프라인, AWS 메타데이터 수집과 AWS 값 읽기는 기본 비활성이고 각각의 설정으로 활성화한다.

연결은 승인 범위, 지원 콘텐츠, 이력 범위, 마지막 성공과 실패를 명시한다. 정식 목표는 각 연결의 승인 범위를 기본 6시간마다 다시 읽고, 원문이 있는 콘텐츠는 후보를 탐지하며 유형·구성요소가 충족된 키의 유효성과 지원되는 사용 메타데이터를 검사하는 것이다. 현재는 GitHub 현재 커밋 수집·탐지와 발견한 AWS 키의 검증 시도 이력, 별도 AWS IAM 접근키 메타데이터·Secrets Manager·SSM·S3 목록 개수 수집, 정확한 단일 AWS 자원 값의 수집·탐지 경로까지 구현됐다. IAM 수집의 승인 범위는 계정 전체의 현재 IAM 사용자 접근키 목록이며 Secret 값을 읽지 않는다. 수집된 ID는 보호키 HMAC과 마스킹 표시로만 남긴다. 다른 세 서비스의 목록 경로는 승인된 리전 또는 전역 목록의 개수·상태·안전한 누락 코드만 남기며 자원 이름과 ARN은 버린다. 모든 AWS 메타데이터 범위의 탐지·검증 단계는 `SKIPPED`로 기록한다. 일부 페이지 실패, 페이지 제한이나 루트 접근키 누락 가능성은 정상 0건으로 처리하지 않는다.

개발 환경은 명시적 `new` AWS 프로필에 연결된 IAM 사용자로 시험했다. [ADR-S006](adr/ADR-S006.md)의 읽기 전용 IAM 역할은 운영 배치 목표이며 이 개발 프로필을 운영 역할로 간주하지 않는다. AWS 워커 실행에는 작업 실행기와 `SECRET_AWS_COLLECTION_ENABLED`를 모두 켜고 `SECRET_AWS_PROFILE` 및 IAM 메타데이터 HMAC 키·버전을 설정해야 한다. 계정 전체 읽기 승인과 각 서비스 수집기의 활성화·실행은 별개다. 목록 경로의 Secrets Manager `ListSecrets`, SSM `DescribeParameters`, S3 `ListBuckets`는 값이나 객체 본문을 읽지 않는다. 목록 응답의 자원 이름·ARN·설명·태그와 페이지 토큰은 작업 메모리에서만 사용하고 일반 DB·API·로그에 남기지 않는다.

정확한 단일 AWS Secret·Parameter·S3 객체 본문을 읽으려면 `SECRET_AWS_CONTENT_READ_ENABLED=true`를 추가로 설정하고 `CURRENT_VALUE_ONLY` 범위를 연결에 승인해야 한다. 기본값 `false`에서는 값 SDK 호출이 0회이며 해당 범위는 안전한 미실행 코드로 남긴다. 경로 접두사, 와일드카드, 목록 범위를 값 읽기 대상으로 승격하지 않는다. 실제 값 경로는 Secrets Manager의 현재 버전, SSM의 복호화된 현재 값 또는 버킷 소유 계정과 ETag를 확인하고 `If-Match` 조건으로 요청한 S3 객체 한 건만 읽는다. `HeadObject` 응답에 버전 ID가 있을 때만 그 버전을 지정한다. 기본 크기 한도는 256 KiB, 절대 상한은 1 MiB이고 UTF-8 텍스트만 탐지기로 전달한다. S3 읽기는 응답 크기와 시간을 함께 제한한다. 한 범위의 실패는 다른 승인 범위의 결과와 분리한다. 이 코드 경로의 실제 AWS 값 호출 결과는 [구현 연동 현황](../04-integration/current-implementation-and-gaps.md)에 검증 범위를 따로 남긴다.

GitHub 또는 승인된 AWS 본문에서 발견한 키에 대한 AWS STS 검증은 별도의 `SECRET_AWS_VALIDATION_ENABLED` 선택 기능으로 기본값이 꺼져 있고, 합성 실험 저장소의 키는 호출하지 않고 `UNCHECKED/SYNTHETIC_FIXTURE`로 기록한다. 본문에서 후보를 찾았다는 이유만으로 저장 위치가 외부에 노출됐거나 키에 특정 권한이 있다고 판단하지 않는다. 지원되지 않는 유형과 원문 부재는 미실행 사유를 남기고 수동 검토에 올린다. 수집 실패 또는 부분 누락으로 검증하지 못한 대상은 지난 성공 판정을 현재 결과로 바꾸지 않는다.

각 작업에는 실행 ID, 대상, 예약 시각, 시작, 종료, 마지막 성공, 결과와 다음 예정 시각을 남긴다. 같은 대상과 예정 시각의 중복 작업은 하나로 합친다. 공급자별 호출 제한과 지수 백오프를 적용하고 무한 재시도를 금지한다. 429와 일시 장애는 지연 사유와 재시도 예정 시각을 남긴다. 재시도 실패가 지난 성공을 현재 성공으로 갱신하지 않는다. 운영 화면에는 대기량, 실패율, 지연과 부분 수집을 표시한다.

검증은 승인된 최소 요청으로 인증 가능성을 확인한다. 공급자 오류 응답은 검증기 자신의 인증 오류, 권한 부족, 대상 없음, 호출 제한, 네트워크 장애와 구분한다. 401이나 403만으로 일괄 무효 처리하지 않는다. 검증 목적으로 실제 데이터를 내려받거나 권한을 시험적으로 변경하지 않는다. 사용 기록은 검증 호출의 흔적과 실제 업무 사용을 구별한다.

## 3. 원문과 보존

발견한 비밀 원문은 영속 저장하지 않는다. 원문이 포함된 수집 결과와 도구 출력은 제한된 작업 메모리에서 처리하고, 전송 중 암호화와 접근 제한을 적용한다. 일반 DB 필드, 메시지 큐, 로그, 오류 응답, 임시 파일, 백업, AI 입력에는 원문을 쓰지 않는다. 정확한 AWS 본문은 동기 탐지·정규화가 끝나면 소유 `byte[]`를 0으로 덮는다. 그러나 AWS SDK가 Secrets Manager `SecretString`과 SSM 값을 Java 불변 `String`으로 만들기 때문에 메모리 전체의 즉시 소거는 보장할 수 없다. 이 잔여 위험을 전제로 워커의 메모리·프로세스 로그 접근을 제한하고 SDK HTTP wire logging을 켜지 않는다. 승인 참조의 ARN·Parameter 이름·S3 객체 키도 민감한 메타데이터라 DB와 백업의 접근을 제한한다. 마스킹과 비밀 제거는 API 직전만이 아니라 수집 및 작업 경계에서도 적용한다. 원문이 사라지거나 재취득 권한이 없으면 `SOURCE_UNAVAILABLE` 등을 기록하고 UNKNOWN 또는 UNCHECKED로 남긴다.

메타데이터, 감사 기록, 조치 증거는 종류별 보존 기간을 운영 설정에 명시한 후 저장한다. 백업은 복원 연습으로 무결성을 확인하며, 삭제 대상이 백업과 복구 후에도 다시 노출되지 않도록 삭제 정책을 적용한다. 식별용 보호키와 연결 자격 증명은 별도 키 관리 경계에서 회전하고 접근을 감사한다.

## 4. 운영 검증

출시 전에는 허용, 거부, 부분 누락 수집과 공급자별 오류 분기를 합성 데이터 및 승인된 테스트 계정으로 확인한다. 비밀 제거 검사는 성공, 실패, 재시도, 원천 파서 오류, 브라우저 응답과 백업 경로를 포함한다. 실행 ID로 수집, 탐지, 검증, 평가, 대응 변경을 연결하고 엔진, 룰, 검증기, 정책 버전을 남긴다. 실제 검증 결과가 없는 공급자와 유형은 지원 완료로 표시하지 않는다.
