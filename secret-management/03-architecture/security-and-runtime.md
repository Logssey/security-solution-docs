# 보안 경계와 실행 정책

기준: [PRD](../01-requirements/PRD.md) SEC-01부터 SEC-08, [ADR-S002](adr/ADR-S002.md), [ADR-S004](adr/ADR-S004.md), [ADR-S005](adr/ADR-S005.md), [ADR-S006](adr/ADR-S006.md).

## 신뢰 경계

| 경계 | 실행 정책 |
|---|---|
| 수집 연결 | 연결마다 조직·계정·저장소·페이지·네임스페이스·콘텐츠의 승인 범위를 저장한다. 범위 밖 자료를 정상 0건으로 보고하지 않는다. |
| 자격 증명 | 수집용 계정·공급자 검증용 계정·발견한 비밀의 권한과 접근 경로를 분리한다. 수집·검증 역할에 외부 키 변경 권한을 주지 않는다. |
| 탐지 입력 | 코드·문서·설정·도구 출력은 비신뢰 데이터다. 입력 크기·형식을 제한하고 화면은 텍스트로 렌더링한다. |
| 검증 호출 | 유형별 검증기·호스트·엔드포인트·요청·권한·호출량을 승인 목록으로 관리한다. 발견 URL과 kubeconfig exec 명령은 실행하지 않는다. |
| 내부 작업 | 큐에는 내부 대상 ID만 넣는다. 원문은 필요한 순간 승인 원천에서 재취득해 워커 메모리에서만 사용한다. |
| 대시보드 | API가 인증·대상 범위 권한·서버 마스킹·변경 감사의 유일한 경계다. 브라우저는 원문을 받지 않는다. |

K8s Secret은 Kubernetes API와 별도 인증·최소 RBAC로 읽는다. 워커 배치는 승인된 클러스터 네트워크에 맞춰 설정하되 수집 계약·감사·권한 검사를 동일하게 적용한다. Pod exec·노드 파일·etcd 직접 접근을 Secret 수집에 포함하지 않는다.

API와 워커는 별도 Java 프로세스다. 승인 원천과 검증 엔드포인트의 원문 접근은 워커에만 부여한다. Gitleaks 8.30.1의 입력·원문 포함 출력은 제한된 파이프·메모리에서 처리하며 수집원 연결 자격 증명을 탐지 도구에 전달하지 않는다. 실행·파싱 실패는 실패 또는 부분 실패로 기록하고 정상 0건으로 바꾸지 않는다.

## 작업과 수집 통제

정기·수동 수집 및 탐지는 별도 Java 워커에서 실행한다. `POST /api/v1/secrets/runs`는 영속 작업을 등록하고 실행 ID를 반환한다. API 서버 시작·샘플 적재·임의 DB 변경을 계기로 외부 스캔을 실행하지 않는다. 예약기·실행기·원천별 파이프라인·AWS 메타데이터·AWS 값 읽기는 각각 명시적 활성화 설정을 요구하며 기본 비활성이다.

기본 정기 주기는 6시간이고 워커의 도래 작업 확인 간격은 30초다. 두 주기는 독립적이며 수동 요청은 정기 예정 시각을 바꾸지 않는다. 작업은 행 잠금으로 선점하고 lease 만료를 복구한다. 같은 대상·목적·예정 시각의 중복 등록은 멱등 키로 방지한다. 실행 ID, 예약·시작·종료·마지막 성공·다음 예정·시도 번호와 상태를 보존한다.

각 연결은 승인 범위 revision·콘텐츠·이력 범위·마지막 성공·실패를 기록한다. 수집 단계가 성공한 원문만 탐지하고 구성요소·유형·승인이 충족된 후보만 능동 검증한다. 원천의 일부 실패는 다른 승인 범위 결과와 분리한다. 실패한 최신 시도가 과거 성공 시각을 갱신하지 않는다.

### AWS 읽기 경계

운영 워커는 읽기 전용 IAM 역할과 명시적 연결 참조를 사용하며 실행 전 STS 계정을 승인 계정과 대조한다. 환경별 자격 증명 공급은 연결 설정이며 개인 로컬 프로필을 운영 권한으로 간주하지 않는다. 작업 실행기와 `SECRET_AWS_COLLECTION_ENABLED`를 모두 활성화하고 IAM 메타데이터 식별용 HMAC 보호키·버전을 설정한다.

IAM 접근키 목록은 현재 사용자 접근키·최근 사용 메타데이터만 읽으며 Secret 값을 읽지 않는다. 접근키 ID는 HMAC·마스킹으로만 남긴다. 루트 키 존재·확인 불가는 누락으로 기록한다. Secrets Manager `ListSecrets`, SSM `DescribeParameters`, S3 `ListBuckets`는 항목 수·상태·안전한 누락 코드만 남기고 이름·ARN·설명·태그·페이지 토큰은 버린다. 메타데이터 범위의 탐지·검증은 SKIPPED다. 계정 전체 읽기 승인이 모든 수집기의 실행 또는 값 읽기를 뜻하지 않는다.

정확한 단일 AWS 본문을 읽으려면 `SECRET_AWS_CONTENT_READ_ENABLED=true`와 `CURRENT_VALUE_ONLY` 범위를 별도 승인한다. 기본 false에서는 값 SDK 호출을 하지 않는다. 접두사·와일드카드·목록 승인을 값 읽기로 승격하지 않는다. Secrets Manager 현재 버전, SSM 복호화 현재 값 또는 소유 계정·ETag가 확인된 S3 객체 한 건만 읽는다. S3는 `If-Match`를 적용하고 HeadObject에 버전 ID가 있으면 그 버전을 지정한다. 기본 크기 한도 256 KiB, 절대 상한 1 MiB의 UTF-8 텍스트만 동기 탐지하며 S3 응답 시간·크기도 제한한다.

### 능동 검증과 재시도

AWS STS 검증은 본문 수집과 별도인 `SECRET_AWS_VALIDATION_ENABLED`로 활성화하며 기본 false다. 승인된 합성 fixture 원천의 후보는 능동 호출 없이 UNCHECKED/SYNTHETIC_FIXTURE다. 발견 사실만으로 외부 노출·권한·심각도를 판단하지 않는다. 원문 부재·미지원·불완전 구성은 미검증 사유를 남긴다.

유형별 최소 승인 요청으로 인증 가능성을 확인한다. 검증기 자신의 인증 오류·대상 권한 부족·대상 없음·호출 제한·네트워크 장애를 구분하며 401·403을 일괄 INVALID로 해석하지 않는다. 실제 데이터를 내려받거나 키·권한을 변경해 검증하지 않는다. 검증 호출의 흔적과 실제 업무 사용 기록을 구별한다.

공급자별 호출량·지수 백오프·최대 재시도·실행 기한을 승인된 설정으로 제한한다. 호출 한도가 없으면 능동 호출을 시작하지 않는다. 429·일시 장애는 지연 사유·다음 시도를 기록하고 무한 재시도를 금지한다. 운영 지표에는 대기량·실패율·지연·부분 수집·재취득 실패를 포함한다.

## 원문과 보존

발견한 비밀 원문은 영속 보관하지 않는다. 일반 DB·큐·로그·오류 응답·임시 파일·백업·AI 입력으로 전달하지 않는다. 전송 중 암호화와 접근 제한을 적용하고 마스킹·비밀 제거는 수집·작업·API 경계에서 수행한다. 원천 삭제·권한 변경으로 재취득할 수 없으면 SOURCE_UNAVAILABLE 등 사유와 UNKNOWN 또는 UNCHECKED를 기록하며 무효·해결로 취급하지 않는다.

정확한 AWS 본문은 동기 탐지·정규화 후 소유 byte 배열을 0으로 덮는다. AWS SDK가 SecretString·SSM 값을 Java 불변 String으로 만들 수 있으므로 메모리 전체의 즉시 소거는 보장하지 않는다. 이를 전제로 워커 메모리·프로세스 접근을 제한하고 SDK HTTP wire logging을 금지한다. 승인 참조의 ARN·Parameter 이름·S3 객체 키도 민감한 메타데이터로 다뤄 DB·백업 접근을 제한하며 일반 화면·API·로그에는 안전한 범위 별칭을 사용한다.

메타데이터·감사·조치 증거는 종류별 보존 기간을 운영 설정에 명시한다. 백업 복원 시 삭제 정책을 재적용한다. 식별 보호키와 연결 자격 증명은 별도 관리·회전하고 접근을 감사한다. 출처·보관 정책·담당자·판정 변경은 변경 전후·수행자·시각·버전을 추가 전용으로 남긴다.

## 판정·해결 통제

모든 변경 명령은 서버가 현재 권한·capability·기대 버전·정책과 근거를 재검사한다. 과거 화면의 버튼 상태를 권한 근거로 사용하지 않는다. 비정상 위치 판정·대응 건 생성/연결·감사는 원자 저장한다. ABNORMAL이지만 현재 건에 연결되지 않은 위치는 무결성 복구 대상으로 숨기지 않고 조치 요청 대기열에 유지한다.

외부 조치 기록·현재 위치 미발견·공급자 키 폐기는 독립 증거다. 필수 검사 실패·UNKNOWN·미연결 노출·키 수명주기 미확인은 해결을 막는다. 건 전체 조정자는 모든 관련 위치와 미연결 노출에 대한 권한이 있어야 하며 제한된 부분 목록으로 전체 해결을 승인하지 못한다.

AI는 선택형 가이드 보조다. 제한된 enum만 전송하고 키 원문·지문·경로·자유 메모를 제외한다. 공급자 응답은 서버에서 형식·길이를 검증하며 오류·한도 초과·비활성에서는 기본 가이드를 반환한다. AI는 유효성·심각도·노출·건 상태를 결정하지 않는다. 외부 전송·보관 정책 승인, 명시적 활성화, 서버 허용 목록의 TEST 출처와 키별 합성 근거를 모두 요구한다. 운영 출처·합성 미확인·실키 의심 또는 확인 건은 기본 가이드만 제공한다.

## 검증 기준

허용·거부·부분 누락, 공급자별 오류, 재시도·파서 실패와 동시 변경을 합성 데이터 및 승인 시험 계정으로 확인한다. 비밀 제거 검사는 도구 출력·오류·브라우저 응답·백업을 포함한다. 실행 ID로 수집·탐지·검증·평가·대응을 연결하고 엔진·규칙·검증기·정책 버전을 남긴다. 지원은 검증된 유형·범위로 한정하며 API 코드 존재만으로 지원 완료를 선언하지 않는다.
