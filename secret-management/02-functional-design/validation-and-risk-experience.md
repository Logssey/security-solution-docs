# 현재 인증과 노출 심각도 확인 화면

기준: [심각도 정책](severity-policy.md), [검증 계약](../03-architecture/credential-validation.md), [평가 계약](../03-architecture/risk-assessment-contract.md), [API 계약](../03-architecture/api-contract.md).

사용자는 발견한 키가 무엇인지, 어디에 있는지, 현재 인증 가능한지, 왜 위험하거나 아직 판단할 수 없는지, 다음에 무엇을 해야 하는지 순서대로 확인한다. 검증 실행이나 모든 평가 입력의 수동 작성을 노출 판단·담당자 지정·외부 조치의 일괄 선행 조건으로 두지 않는다.

## 1. 키 상세의 정보 구조

`/secrets/{id}`의 제목·마스킹 이름·유형·출처 아래에 다음 정보를 둔다. **왜 확인해야 하는지 → 어디에 있는지 → 무엇을 할 수 있는지**를 먼저 읽게 한다. 발견 위치와 탐지 이유는 검증 기능의 지원 여부와 관계없이 유지한다.

| 영역 | 기본 정보 | 행동 |
|---|---|---|
| 발견 요약 | 키의 용도에 따른 잠재 영향과 실제 확인 사실을 구분한 한 줄 이유, 최근 원천 검사 | 허용된 다음 행동 하나 |
| 위치 시각화 | 발견 플랫폼 → 문서·파일 위치 → 키 → 확인된 영향 자원. 현재 발견·비교 가능한 미발견·확인 불가와 메타데이터를 구분 | 소스·위치 선택 |
| 발견 위치 표 | 저장소·브랜치·파일·줄 또는 안전한 자원 좌표, 현재 존재·유효성·심각도·담당·관련 대응 | 위치 상세와 현재 대응 열기 |
| 조치 확인 | 필수 대응 위치의 잔존·미발견·확인 불가와 키 사용 종료 확인 | 남은 해결 조건과 재검사 |
| 보조 확인 | 유효성의 결과·미실행 이유·실제 확인 시각과 진행 중 요청, 위치별 위험 판단 | `유효성 확인`, 판단 이유 또는 이력 |

유효성은 키 수준의 사실이며 심각도는 발견 위치의 사실이다. 위치마다 다른 심각도를 키 하나의 확정 등급처럼 표시하지 않는다. 키 상세의 대표 심각도에는 `현재 대응 건 기준`과 출처·확인 범위를 붙인다. 권한이 제한되면 전체 최고 등급을 추정하지 않고 `일부 위치만 확인 가능`을 표시한다.

하위 탭은 `발견 위치`, `판단 근거`, `사용·검증 이력`, `대응 기록`으로 구분한다. 지원되지 않는 사용 조회를 탭 추가만으로 실행 가능한 기능처럼 표시하지 않는다. 탭·출처·선택 위치·위치 페이지는 URL 상태로 보존하고 직접 링크·새로고침·뒤로 가기에서 복원한다. 이력 버튼은 탭을 바꾸는 동시에 해당 제목으로 스크롤·초점을 이동해 결과를 보여준다. 동일 데이터를 탭 아래와 페이지 끝에 중복 누적하지 않는다. 긴 유효성 설정·차단 사유 목록을 모든 탭의 공통 상단에 펼치지 않는다.

## 2. 유효성의 기본 표시

| 사실 | 배지·설명 | 시각·행동 |
|---|---|---|
| 검증기 미등록 | `검증 미지원` · 유형별 지원 한계 | 확인 시각 `—`, 불가능한 실행 버튼 대신 지원 범위 |
| 검증 비활성 | `검증 꺼짐` · 연결의 검증 설정 | 확인 시각 `—`, 권한 있으면 검증 설정으로 이동 |
| 합성 근거 일치 | `검증 생략` · 합성 시험 키 | 공급자 확인 시각 `—`, 합성 근거의 확인 시각은 별도 |
| 일부 구성 누락 | `구성 부족` · 필요한 구성요소 | 공급자 확인 시각 `—`, 발견 위치·탐지 이유 유지 |
| 지원·승인되었으나 미시도 | `미검증` · 아직 확인하지 않음 | 확인 시각 `—`, `유효성 확인` |
| 대기·실행 중 | `확인 대기` 또는 `확인 중` | 요청 시각·진행 상태, 중복 요청 차단 사유 |
| 인증 성공 | `유효` · 공급자 인증 확인 | 실제 확인 시각과 최신성 |
| 명확한 인증 거부 | `사용 불가` · 공급자 인증 거부 | 실제 확인 시각. 원인 근거 없이 `폐기됨`·`만료됨`을 붙이지 않음 |
| 시도 후 결론 불가 | `확인 불가` · 통신 오류·호출 제한 등 구체 사유 | 최근 시도 시각, 다음 재시도 또는 사용자가 할 행동 |
| 이전 결과의 확인 기한 경과 | `다시 확인 필요` · 이전 유효/사용 불가와 당시 시각 | 과거 결과를 현재 확인처럼 강조하지 않음 |
| 조치 이후 미확인 | `조치 후 미검증` | 조치 이전 결과와 현재 재확인 대기를 분리 |

기본 항목명은 `현재 인증 상태`, `확인 결과`, `실제 확인 시각`으로 쓴다. 공급자에 요청하지 않은 항목의 시각은 `미확인` 대신 `—`로 표시하고 미실행 이유를 바로 옆에 설명한다. `최근 시도 시각`은 성공 여부와 관계없이 시도가 종료된 시각이며 `마지막 인증 성공`은 실제 VALID 관측 시각이다. 둘을 같은 컬럼으로 재사용하지 않는다.

`검증 근거`라는 단독 제목 대신 `확인 결과`를 사용한다. 세부 근거 펼침에는 안전한 검증 방법·검증기 버전·실행 ID·관측 시각·사유 코드를 제공한다. 계정·프로필·키 원문·공급자 응답 본문은 제공하지 않는다.

## 3. 유효성 확인 요청

연결 관리에서 선택한 연결의 `키 검증 설정`을 누르면 단일 패널을 연다. 연결의 검증 허용과 검증할 키 발급 서비스 GitHub·AWS·Notion을 편집하고, 수집 플랫폼과 발급 서비스의 차이를 짧게 안내한다. 처음 등록하는 연결은 발급 서비스를 명시적으로 선택한다. 이미 저장된 정책은 실제 선택을 보여준다. profile·revision·endpoint는 서버가 관리한다.

활성화 저장에는 키 발급 서비스 하나 이상을 요구하고 선택할 항목을 설명한다. 서버 검증기 꺼짐·권한 부족·설정 충돌은 각각의 이유와 다음 행동을 제공한다. 저장 성공에는 `검증 설정을 저장했어요`와 범위별 검증 허용으로 이어지는 링크를 표시한다. 실제 인증 요청의 접수·실행·결과는 키 상세와 실행 기록에서 표시한다.

범위의 `키 유효성 검증 설정`은 연결의 활성화와 허용 발급 서비스를 함께 보여주고 해당 연결 설정으로 바로 이동할 수 있게 한다. 연결 정책 패널의 URL 선택은 기존 스캔 connectionId·runId와 독립된 validationConnectionId로 관리한다. 패널을 닫으면 이전 연결·실행 선택으로 돌아간다. 과거 원천 보호 생략은 당시 미실행 사유로 설명하고 현재 조건과 구분한다.

1. 사용자는 발견 위치를 선택한다. 한 곳만 적격이면 자동 선택하고 실제 선택 결과를 표시한다. 권한 밖 위치의 존재나 수를 선택기에 노출하지 않는다.
2. 확인창은 발급자·유형·현재 ACL과 승인 일치를 통과한 `sourceDetails` 또는 `safeLocationLabel`, `인증 가능 여부만 확인하며 키를 변경하지 않습니다`, 호출 승인·최신성·생략 조건을 짧게 제공한다. 원본 승인 URI·인증 참조는 표시하지 않으며 새로운 승인 범위를 이 확인창에서 조용히 추가하지 않는다.
3. 요청 후에는 실행 ID·대기/진행 상태를 같은 영역에 표시한다. HTTP 접수 성공을 키 유효성 확인 성공으로 표시하지 않는다.
4. 동일 요청 재시도는 같은 요청을 보여준다. 다른 활성 작업이 있으면 해당 사용자가 볼 수 있는 진행 상황과 재시도 가능 시점을 제공한다.
5. 완료 시 해당 영역과 최신 읽기 기준을 갱신한다. 필터·탭·스크롤 위치를 보존하고 새로운 결과와 이력 추가를 알린다.

`유효성 확인`, 연결 관리의 `연결 테스트`, 대응의 `조치 후 재검사`는 목적·실행 대상·성공 의미가 다른 버튼이다. 연결 테스트 성공을 발견 키의 VALID로 표시하지 않는다. 파일 미발견을 키의 INVALID로 표시하지 않는다.

## 4. 위치별 심각도와 근거

발견 위치 행은 `위치`, `현재 존재`, `노출 판단`, `유효성·확인 시각`, `심각도`, `조치 담당`, `다음 작업`을 제공한다. 유효성과 심각도는 서로를 대체하지 않는다. 검증 대상과 선택 위치가 다르면 대상을 명확히 따로 표시하고, 기본은 같은 `occurrence` 선택을 공유한다. 유효성·구성·발급자를 같은 의미의 중복 배지로 반복하지 않는다.

`판단 이유`는 선택 위치의 `판단 근거` 탭 또는 단일 패널로 연다. 한 번에 패널 하나만 유지하며 페이지 맨 아래에 상세를 쌓지 않는다. 키보드 초점 진입·닫기·호출 버튼으로의 복귀를 지원하고 위치 ID를 URL 상태로 보존한다.

패널은 아래 순서로 표시한다.

1. 발견 좌표와 현재 존재, 탐지한 규칙, 최근 원천 검사 시각. 파일 원문이나 키 원문은 표시하지 않는다.
2. 확인된 노출 판단·관련 대응·한 줄 위험 이유와 실제 가능한 다음 행동. 미평가여도 기존 대응과 담당 지정·조치·재검사를 찾을 수 있다.
3. 유효성 결과·실제 확인 시각·미실행 이유와 현재 위치의 심각도 요약.
4. `평가 근거 자세히`에 적용 규칙·정책·평가 시각·여섯 축·부족 근거를 펼친다. 위험 재계산·자료 제출·등급 예외는 해당 보조 영역에서만 수행한다.
5. 이전 평가·수동 조정 이력과 확인 한계.

자동 결과와 실제 적용 결과가 같으면 한 번만 표시한다. 서로 다르거나 하향 보류가 있는 경우에만 두 결과와 차이를 설명한다. 규칙 ID·버전·내부 사유 코드를 기본 제목으로 쓰지 않는다. 모든 축이 미확인인 동일 크기 카드 여섯 개로 현재 사실과 다음 행동을 밀어내지 않는다.

반복 검사로 같은 규칙의 탐지 기록이 늘어나도 기본 패널의 길이는 늘리지 않는다. 현재 사실을 먼저 표시하고 규칙별 최신 관측을 최대 세 개까지 보여준다. 나머지 관측은 닫힌 `최근 탐지 기록`에서 확인한다. 조회 한도가 있는 기록 수를 전체 이력 수처럼 표시하지 않는다. 해결 조건은 관련 대응이 있는 위치에만 보조 상세로 제공한다.

기존 노출 판정에 현재 범위 revision 등 최신 평가에 필요한 근거가 없으면 `기존 노출 판정 · 최신 근거 재확인 필요`로 구분한다. 현재 심각도 미평가와 과거 판정·진행 중 대응은 함께 존재할 수 있다. 새 위험 계산이 UNKNOWN이라는 이유로 과거 노출·담당·대응 기록을 없애지 않고, 과거 판정이 현재 다시 검증됐다고도 표시하지 않는다.

영향 범위가 아직 UNKNOWN이어도 확인된 고위험 권한이 있으면 `확인된 권한`에 안전한 기능 설명을 표시한다. 예: `운영 배포 권한 확인 · 전체 대상 범위는 확인 필요`. 이를 완전한 영향 분석이나 자동 확정 등급으로 설명하지 않지만, 이미 확보한 경고 근거를 미평가 배지 하나로 숨기지 않는다.

정상 보관의 R00은 `보관 허용 · 심각도 적용 대상 아님`으로 표시하고 LOW나 미평가 건수에 넣지 않는다. R99는 `미평가 — 접근 대상·권한 확인 필요`처럼 부족한 항목을 설명한다. `NOT_CONFIRMED`는 `확인된 중대한 사고 근거 없음`이며, 조사하지 않았으면 `사고 여부 미조사`를 함께 표시한다. `악용 없음`으로 줄이지 않는다.

최근 계산이 R99지만 기존 확정 등급을 하향 보류하는 경우에는 `최근 평가: 미평가`와 `적용 등급: 치명적 · 기존 판단 유지 · 재검토 필요`를 따로 표시한다. 각각의 규칙·시각·원평가 링크와 보류 사유를 제공한다. 최신 미평가에 과거 CRITICAL을 같은 결과처럼 붙이거나, 등급 근거가 현재 다시 확인됐다고 설명하지 않는다. 정상 보관 교정 후의 보류 해제는 현재 R00과 반증을 근거로 한 독립 검토이며, 해제 자체가 키 폐기·대응 건 해결은 아니다.

## 5. 자료 보완과 수동 판단

권한·대상 자동 조회가 충분하면 시스템이 입력을 채우고 규칙을 평가한다. 사람에게 여섯 축 전체를 매번 입력시키지 않는다. 부족한 축만 기존 조사 과제로 연결하고 질문·담당자·기한·자료의 확인 수준을 보여준다.

지정 조치 담당자는 허용된 위치에 자료를 제출할 수 있다. SECURITY는 일반 자료를 근거·적용 범위·관측 시각·유효기간과 함께 직접 수용할 수 있으며 매번 다른 사람의 확인을 요구하지 않는다. 수동 수용은 `담당자 확인`으로 표시하고 `공급자 자동 확인`으로 바꾸지 않는다. 실제 등급을 임의 지정하거나 기존 높은 등급을 낮추는 예외는 평가 계약의 별도 승인 조건을 적용한다.

원문 붙여넣기·공급자 전체 응답·임의 URL·자유 파일 업로드는 받지 않는다. 기존 허용 형식의 티켓/변경 참조와 구조화된 사실만 사용한다. 평가 버튼을 누른 사실, 자료 제출 또는 조사 종료를 위험 감소·키 폐기·해결로 표시하지 않는다.

## 6. 현황·목록·이력의 일관성

현황은 같은 시점의 현재 대응 건을 기준으로 심각도를 집계하고 미평가 위치 수·근거 오래됨·일부 권한 제한을 함께 표시한다. 등급이 없는 항목을 LOW로 채우지 않는다. 필터만 바뀌거나 결과 조회가 실패한 것을 위험 감소로 표시하지 않는다.

검증 이력은 요청 목적·방법·결과·사유·실제 확인/시도 시각을, 평가 이력은 위치·규칙·입력 요약·결과·근거·판정자를 시간순 페이지로 제공한다. 외부 호출이 없는 심각도 재평가는 스캔 성공 횟수에 합산하지 않는다. 검증/평가 상세는 독립 탐색 또는 단일 패널을 사용하고 기존 스캔 상세를 페이지 하단에 다시 삽입하지 않는다.

## 7. Notion 인증·권한·조치의 표시

Notion 키 상세는 공통 위치 시각화·발견 위치 표·판단 근거·사용 및 검증 이력·대응 기록 구조 안에서 정보를 제공한다. 상단에는 현재 인증 결과·실제 확인 시각·다음 행동을 표시하고 주체·권한·수명 근거는 출처와 확인 범위를 함께 제공한다. 기본 인증 버튼은 `유효성 확인`이다. Notion 발급 토큰의 권한 보조는 관측기 등록 전 미지원으로 표시한다. 별도 관측기가 등록된 경우에만 `페이지 접근 확인` 행동과 승인 대상을 제공하며 인증 성공을 권한 보조 지원으로 표시하지 않는다.

| 항목 | 표시할 내용 |
|---|---|
| 현재 인증 | 인증 확인·현재 인증 거부·확인 불가·미검증과 구체 사유. 진행 중이면 현재 결과와 요청 상태를 함께 표시 |
| 마지막 인증 성공 | 실제 VALID 시각. 이후 거부·오류·조치 후 대기와 함께 표시 |
| 확인한 주체 | 봇·소유 범위·워크스페이스의 확인 수준. 열람 가능한 보호 별칭만 제공 |
| 권한·접근 | 설정 자료에서 확인한 capability와 승인 페이지·본문의 실제 읽기 관측을 분리. 각 대상·시각·완전성을 표시 |
| 만료 | 해당 키에 연결된 만료 근거와 출처. 근거 TTL·다음 검사 기한은 각각 별도 항목 |
| 폐기·교체 | 신고·검토 수준, 알려진 수행 시각 또는 `수행 시각 미상`, 이후 인증 결과와 교체 키의 허용 링크 |

검증 이력은 `인증 성공 → 폐기 신고 → 인증 거부 확인`처럼 관측과 조치 기록을 각각의 시각·출처로 보여준다. 같은 bot/workspace의 새 키는 별도 키로 표시하고 확인된 교체 관계만 관련 항목으로 연결한다. 폐기 신고 뒤 정상 인증이 관측되면 `폐기 조치 재확인 필요`, 일시 오류이면 `폐기 신고 · 인증 확인 불가`를 표시한다. 오래된 정상 응답은 당시 기록으로 보존한다.

사용자의 조치 신고는 저장 직후 이력에 표시하며 검토 대기와 다음 행동을 제공한다. 독립 검토는 기존 수명주기 근거를 적용할 때 수행하고 자동 인증 관측마다 요구하지 않는다. 401과 신고만 있는 경우는 `폐기 신고 · 인증 거부 확인`으로 표현한다. 위치 제거·수명 확인·해결 조건은 각각의 현재 근거와 기존 대응 정책으로 표시한다.

## 8. 판단 근거와 다음 행동

상세 상단에는 마스킹 이름·발급자·유형, 시크릿 노출 심각도, 현재 인증 상태, 가장 중요한 이유 한 문장과 실제 가능한 다음 행동 하나를 둔다. 기존 색상 박스 안의 강조 형식을 유지하고 왼쪽 두꺼운 색상 막대나 긴 설명의 반복 카드를 추가하지 않는다. 위치 시각화와 발견 좌표는 평가 지원 여부와 관계없이 유지한다. 미확인 자원 연결은 확정 영향선으로 그리지 않고 수집용 계정을 발견 키의 영향 경로에 넣지 않는다.

`판단 근거`는 현재 판단과 평가 이력을 구분한다. 여섯 축은 읽기 사실로 제공하고 자동 후보·담당자 확인·미확인·오래됨·충돌을 각 근거와 함께 표시한다. 제외된 과거 근거는 근거 이력에서 설명하고 새 적격 근거로 확인된 축에 이전 STALE 질문을 반복하지 않는다. 시스템이 이미 확인한 값을 사람이 다시 고르는 필수 폼으로 만들지 않는다. 부족한 질문을 선택하면 해당 자료 제출·정책·조사·권한 후보 검토의 기존 화면으로 이동하며 저장 후 같은 위치·탭으로 돌아온다.

현재 판단이 오래됐거나 미평가여도 기존 노출·대응·담당자·재검사 동선을 유지한다. 처리 우선순위와 영업시간 기준 확인 기한은 심각도 옆의 별도 업무 정보다. 등급 전환·최초 관측·우선 신호 관측 중 기산 근거를 표시하고 근거가 없으면 기한 미확인으로 둔다. 현재 인증은 riskExperience.authentication의 현재성 결과를 쓰고 과거의 마지막 확정값은 별도 이력으로 표시한다. 초기 공휴일 캘린더 미연결과 운영시간 밖의 다음 확인 시간을 표시하며 실제 야간 대응을 보장하지 않는다.

## 9. 사용 이력과 AI 조사 요약

사용 이력은 IAM 최근 사용 메타데이터, 관리 이벤트 조회, 구조화 수동 자료를 구분한다. 조회 기간·계정/리전의 안전한 범위·관리 이벤트 한계·커버리지와 정확한 키 결합 여부를 함께 보여준다. 0건·부분 실패·미요청·미지원은 서로 다른 상태다. 자체 검증·업무 사용 분류에도 연결 근거를 제공하고 로그인 성공이나 시간·IP 유사성만으로 분류하지 않는다. 수동 제출·수용·철회는 원관측과 별도 이력이다.

기존 `tab=validation` 경로는 `사용·검증 이력`으로 유지하고 `historyView=usage|validation`으로 전환한다. 사용 이력은 선택 occurrence를 공유하고 usageView=records|request|material, usageObservation, usagePage를 URL에 보존한다. 자료 상세는 현재 이력 영역을 교체하며 새 패널이나 페이지 끝의 누적 상세를 만들지 않는다. 이미 알려진 AWS 행위는 읽기 쉬운 행위명으로 표시하고 미등록 행위는 일반 행위 종류로 설명한다. 등록할 근거가 없으면 권한에 맞는 기존 조사·대응 화면으로 바로 연결한다.

AI 조사 요약은 판단 근거 탭의 보조 영역이다. 기본 설명과 필수 다음 행동을 먼저 보여주고 명시적 요청만 외부 호출을 등록한다. 대기·실행·기본 설명 대체·오래된 결과·재요청 가능 시각을 같은 영역에서 갱신하며 페이지 아래에 쌓지 않는다. 결과에는 기본/AI 출처·캐시 여부·생성 시각·기준 평가와 안전한 실패 사유를 표시한다. AI가 없어도 근거 확인과 대응을 계속할 수 있다.

판단 상세 URL은 선택 `occurrence`를 유지하고 `locationTab=risk`로 연다. `riskView=current`가 기본이며 `evidence`는 자료 보완, `history`는 과거 평가로 이동한다. 부족 질문은 현재 필요한 기존 폼으로 연결하고 원문·ACL 동시성 미확인은 원문 관찰 시점의 공유 근거와 효력 기간을 확인하게 한다. 현재 정보가 그대로인 재스캔을 필수 해결책처럼 반복 요구하지 않는다. 자료 보완의 기간 입력은 API의 반개구간·관측 시각·만료 제약을 따르며 역사적 사고 근거에는 현재 효력 기간을 강제하지 않는다.
