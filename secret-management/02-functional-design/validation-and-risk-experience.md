# 유효성 검증과 심각도 확인 화면

기준: [심각도 정책](severity-policy.md), [검증 계약](../03-architecture/credential-validation.md), [평가 계약](../03-architecture/risk-assessment-contract.md), [API 계약](../03-architecture/api-contract.md).

사용자는 발견한 키가 무엇인지, 어디에 있는지, 현재 인증 가능한지, 왜 위험하거나 아직 판단할 수 없는지, 다음에 무엇을 해야 하는지 순서대로 확인한다. 검증 실행이나 모든 평가 입력의 수동 작성을 노출 판단·담당자 지정·외부 조치의 일괄 선행 조건으로 두지 않는다.

## 1. 키 상세의 정보 구조

`/secrets/{id}`의 제목·마스킹 이름·유형·출처 아래에 다음 정보를 둔다. **왜 확인해야 하는지 → 어디에 있는지 → 무엇을 할 수 있는지**를 먼저 읽게 한다. 발견 위치와 탐지 이유는 검증 기능의 지원 여부와 관계없이 유지한다.

| 영역 | 기본 정보 | 행동 |
|---|---|---|
| 발견 요약 | 키의 용도에 따른 잠재 영향과 실제 확인 사실을 구분한 한 줄 이유, 최근 원천 검사 | 허용된 다음 행동 하나 |
| 위치 시각화 | 키 → 발견 소스 → 열람 가능한 위치. 현재 발견·비교 가능한 미발견·확인 불가와 메타데이터를 구분 | 소스·위치 선택 |
| 발견 위치 표 | 저장소·브랜치·파일·줄 또는 안전한 자원 좌표, 현재 존재·유효성·심각도·담당·관련 대응 | 위치 상세와 현재 대응 열기 |
| 조치 확인 | 필수 대응 위치의 잔존·미발견·확인 불가와 키 사용 종료 확인 | 남은 해결 조건과 재검사 |
| 보조 확인 | 유효성의 결과·미실행 이유·실제 확인 시각과 진행 중 요청, 위치별 위험 판단 | `유효성 확인`, 판단 이유 또는 이력 |

유효성은 키 수준의 사실이며 심각도는 발견 위치의 사실이다. 위치마다 다른 심각도를 키 하나의 확정 등급처럼 표시하지 않는다. 키 상세의 대표 심각도에는 `현재 대응 건 기준`과 출처·확인 범위를 붙인다. 권한이 제한되면 전체 최고 등급을 추정하지 않고 `일부 위치만 확인 가능`을 표시한다.

하위 탭은 `발견 위치`, `검증 이력`, `대응 기록`으로 구분한다. 탭·출처·선택 위치·위치 페이지는 URL 상태로 보존하고 직접 링크·새로고침·뒤로 가기에서 복원한다. 이력 버튼은 탭을 바꾸는 동시에 해당 제목으로 스크롤·초점을 이동해 결과를 보여준다. 동일 데이터를 탭 아래와 페이지 끝에 중복 누적하지 않는다. 긴 유효성 설정·차단 사유 목록을 모든 탭의 공통 상단에 펼치지 않는다.

## 2. 유효성의 기본 표시

| 사실 | 배지·설명 | 시각·행동 |
|---|---|---|
| 검증기 미등록 | `검증 미지원` · 유형별 지원 한계 | 확인 시각 `—`, 불가능한 실행 버튼 대신 지원 범위 |
| 검증 비활성 | `검증 꺼짐` · 연결의 검증 설정 | 확인 시각 `—`, 권한 있으면 검증 설정으로 이동 |
| 합성 근거 일치 | `검증 생략` · 합성 시험 키 | 공급자 확인 시각 `—`, 합성 근거의 확인 시각은 별도 |
| 일부 구성 누락 | `구성 부족` · 필요한 구성요소 | 공급자 확인 시각 `—`, 발견 위치·탐지 이유 유지 |
| 지원·승인되었으나 미시도 | `미검증` · 아직 확인하지 않음 | 확인 시각 `—`, `유효성 확인` |
| 대기·실행 중 | `확인 대기` 또는 `확인 중` | 요청 시각·진행 상태, 중복 요청 차단 사유 |
| 인증 성공 | `유효` · 공급자 인증 확인 | 실제 확인 시각과 최신성 |
| 명확한 인증 거부 | `사용 불가` · 공급자 인증 거부 | 실제 확인 시각. 원인 근거 없이 `폐기됨`·`만료됨`을 붙이지 않음 |
| 시도 후 결론 불가 | `확인 불가` · 통신 오류·호출 제한 등 구체 사유 | 최근 시도 시각, 다음 재시도 또는 사용자가 할 행동 |
| 이전 결과의 확인 기한 경과 | `다시 확인 필요` · 이전 유효/사용 불가와 당시 시각 | 과거 결과를 현재 확인처럼 강조하지 않음 |
| 조치 이후 미확인 | `조치 후 미검증` | 조치 이전 결과와 현재 재확인 대기를 분리 |

기본 항목명은 `유효성`, `확인 결과`, `실제 확인 시각`으로 쓴다. 공급자에 요청하지 않은 항목의 시각은 `미확인` 대신 `—`로 표시하고 미실행 이유를 바로 옆에 설명한다. `최근 시도 시각`은 성공 여부와 관계없이 시도가 종료된 시각이며 `마지막 인증 성공`은 실제 VALID 관측 시각이다. 둘을 같은 컬럼으로 재사용하지 않는다.

`검증 근거`라는 단독 제목 대신 `확인 결과`를 사용한다. 세부 근거 펼침에는 안전한 검증 방법·검증기 버전·실행 ID·관측 시각·사유 코드를 제공한다. 계정·프로필·키 원문·공급자 응답 본문은 제공하지 않는다.

## 3. 유효성 확인 요청

1. 사용자는 발견 위치를 선택한다. 한 곳만 적격이면 자동 선택하고 실제 선택 결과를 표시한다. 권한 밖 위치의 존재나 수를 선택기에 노출하지 않는다.
2. 확인창은 발급자·유형·현재 ACL과 승인 일치를 통과한 `sourceDetails` 또는 `safeLocationLabel`, `인증 가능 여부만 확인하며 키를 변경하지 않습니다`, 호출 승인·최신성·생략 조건을 짧게 제공한다. 원본 승인 URI·인증 참조는 표시하지 않으며 새로운 승인 범위를 이 확인창에서 조용히 추가하지 않는다.
3. 요청 후에는 실행 ID·대기/진행 상태를 같은 영역에 표시한다. HTTP 접수 성공을 키 유효성 확인 성공으로 표시하지 않는다.
4. 동일 요청 재시도는 같은 요청을 보여준다. 다른 활성 작업이 있으면 해당 사용자가 볼 수 있는 진행 상황과 재시도 가능 시점을 제공한다.
5. 완료 시 해당 영역과 최신 읽기 기준을 갱신한다. 필터·탭·스크롤 위치를 보존하고 새로운 결과와 이력 추가를 알린다.

`유효성 확인`, 연결 관리의 `연결 테스트`, 대응의 `조치 후 재검사`는 목적·실행 대상·성공 의미가 다른 버튼이다. 연결 테스트 성공을 발견 키의 VALID로 표시하지 않는다. 파일 미발견을 키의 INVALID로 표시하지 않는다.

## 4. 위치별 심각도와 근거

발견 위치 행은 `위치`, `현재 존재`, `노출 판단`, `유효성·확인 시각`, `심각도`, `조치 담당`, `다음 작업`을 제공한다. 유효성과 심각도는 서로를 대체하지 않는다. 검증 대상과 선택 위치가 다르면 대상을 명확히 따로 표시하고, 기본은 같은 `occurrence` 선택을 공유한다. 유효성·구성·발급자를 같은 의미의 중복 배지로 반복하지 않는다.

`판단 이유`는 현재 선택 위치 한 곳의 패널로 연다. 한 번에 패널 하나만 유지하며 페이지 맨 아래에 상세를 쌓지 않는다. 키보드 초점 진입·닫기·호출 버튼으로의 복귀를 지원하고 위치 ID를 URL 상태로 보존한다.

패널은 아래 순서로 표시한다.

1. 발견 좌표와 현재 존재, 탐지한 규칙, 최근 원천 검사 시각. 파일 원문이나 키 원문은 표시하지 않는다.
2. 확인된 노출 판단·관련 대응·한 줄 위험 이유와 실제 가능한 다음 행동. 미평가여도 기존 대응과 담당 지정·조치·재검사를 찾을 수 있다.
3. 유효성 결과·실제 확인 시각·미실행 이유와 현재 위치의 심각도 요약.
4. `평가 근거 자세히`에 적용 규칙·정책·평가 시각·여섯 축·부족 근거를 펼친다. 위험 재계산·자료 제출·등급 예외는 해당 보조 영역에서만 수행한다.
5. 이전 평가·수동 조정 이력과 확인 한계.

자동 결과와 실제 적용 결과가 같으면 한 번만 표시한다. 서로 다르거나 하향 보류가 있는 경우에만 두 결과와 차이를 설명한다. 규칙 ID·버전·내부 사유 코드를 기본 제목으로 쓰지 않는다. 모든 축이 미확인인 동일 크기 카드 여섯 개로 현재 사실과 다음 행동을 밀어내지 않는다.

기존 노출 판정에 현재 범위 revision 등 최신 평가에 필요한 근거가 없으면 `기존 노출 판정 · 최신 근거 재확인 필요`로 구분한다. 현재 심각도 미평가와 과거 판정·진행 중 대응은 함께 존재할 수 있다. 새 위험 계산이 UNKNOWN이라는 이유로 과거 노출·담당·대응 기록을 없애지 않고, 과거 판정이 현재 다시 검증됐다고도 표시하지 않는다.

영향 범위가 아직 UNKNOWN이어도 확인된 고위험 권한이 있으면 `확인된 권한`에 안전한 기능 설명을 표시한다. 예: `운영 배포 권한 확인 · 전체 대상 범위는 확인 필요`. 이를 완전한 영향 분석이나 자동 확정 등급으로 설명하지 않지만, 이미 확보한 경고 근거를 미평가 배지 하나로 숨기지 않는다.

정상 보관의 R00은 `보관 허용 · 심각도 적용 대상 아님`으로 표시하고 LOW나 미평가 건수에 넣지 않는다. R99는 `미평가 — 접근 대상·권한 확인 필요`처럼 부족한 항목을 설명한다. `NOT_CONFIRMED` 악용은 `확인된 악용 근거 없음`이며, 조사하지 않았으면 `악용 여부 미조사`를 함께 표시한다. `악용 없음`으로 줄이지 않는다.

최근 계산이 R99지만 기존 확정 등급을 하향 보류하는 경우에는 `최근 평가: 미평가`와 `적용 등급: 치명적 · 기존 판단 유지 · 재검토 필요`를 따로 표시한다. 각각의 규칙·시각·원평가 링크와 보류 사유를 제공한다. 최신 미평가에 과거 CRITICAL을 같은 결과처럼 붙이거나, 등급 근거가 현재 다시 확인됐다고 설명하지 않는다. 정상 보관 교정 후의 보류 해제는 현재 R00과 반증을 근거로 한 독립 검토이며, 해제 자체가 키 폐기·대응 건 해결은 아니다.

## 5. 자료 보완과 수동 판단

권한·대상 자동 조회가 충분하면 시스템이 입력을 채우고 규칙을 평가한다. 사람에게 여섯 축 전체를 매번 입력시키지 않는다. 부족한 축만 기존 조사 과제로 연결하고 질문·담당자·기한·자료의 확인 수준을 보여준다.

지정 조치 담당자는 허용된 위치에 자료를 제출할 수 있다. SECURITY는 일반 자료를 근거·적용 범위·관측 시각·유효기간과 함께 직접 수용할 수 있으며 매번 다른 사람의 확인을 요구하지 않는다. 수동 수용은 `담당자 확인`으로 표시하고 `공급자 자동 확인`으로 바꾸지 않는다. 실제 등급을 임의 지정하거나 기존 높은 등급을 낮추는 예외는 평가 계약의 별도 승인 조건을 적용한다.

원문 붙여넣기·공급자 전체 응답·임의 URL·자유 파일 업로드는 받지 않는다. 기존 허용 형식의 티켓/변경 참조와 구조화된 사실만 사용한다. 평가 버튼을 누른 사실, 자료 제출 또는 조사 종료를 위험 감소·키 폐기·해결로 표시하지 않는다.

## 6. 현황·목록·이력의 일관성

현황은 같은 시점의 현재 대응 건을 기준으로 심각도를 집계하고 미평가 위치 수·근거 오래됨·일부 권한 제한을 함께 표시한다. 등급이 없는 항목을 LOW로 채우지 않는다. 필터만 바뀌거나 결과 조회가 실패한 것을 위험 감소로 표시하지 않는다.

검증 이력은 요청 목적·방법·결과·사유·실제 확인/시도 시각을, 평가 이력은 위치·규칙·입력 요약·결과·근거·판정자를 시간순 페이지로 제공한다. 외부 호출이 없는 심각도 재평가는 스캔 성공 횟수에 합산하지 않는다. 검증/평가 상세는 독립 탐색 또는 단일 패널을 사용하고 기존 스캔 상세를 페이지 하단에 다시 삽입하지 않는다.
