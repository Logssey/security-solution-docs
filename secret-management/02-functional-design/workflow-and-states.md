# 상태와 집계 규칙

기준: [PRD](../01-requirements/PRD.md), [ADR-S010](../03-architecture/adr/ADR-S010.md). 처리 단위, 독립 상태 축, 파생 대기열과 집계의 불변 조건을 정의한다. 상태 변경은 이력으로 보존하며 새 판단으로 과거 사실을 덮어쓰지 않는다.

## 1. 용어와 처리 단위

| 단위 | 뜻과 중복 제거 기준 |
|---|---|
| Connection / Scope | 연결과 승인된 읽기 범위. 연결 성공, 범위 승인, 보관 허용은 각각 다른 사실 |
| CredentialSet | 같은 인증에 쓰이는 구성요소 묶음. 완전한 동일성을 증명한 키만 하나로 묶고 불완전 후보는 접두사·마스킹 문자열만으로 합치지 않음 |
| Occurrence | 해당 키의 발견 위치 또는 발급처 메타데이터 관측 위치. 원천 객체·버전을 보존하며 여러 엔진이 찾았어도 같은 위치는 한 번만 셈 |
| Finding | 위치·실행·탐지 엔진·룰과 근거를 연결한 결과. Finding 수는 키 수·위치 수·노출 건수가 아님 |
| ValidationAttempt | 특정 시점·방법의 유효성 확인 시도. 과거 성공과 최근 실패를 각각 보존 |
| InvestigationTask | 위치 또는 범위의 부족한 사실을 확인하는 과제. 사람이 추가 확인을 요청할 때 담당·기한·필요 근거를 지정하며, 자동 실키 경고의 담당·기한 미설정은 배정 대기로 보존. 완료 버튼이 정상 판정이나 해결을 뜻하지 않음 |
| Assessment | 영향·심각도와 확인 근거·정책 버전. 미평가는 LOW가 아님 |
| ResponseCase | 한 키·같은 대응 출처의 확인된 비정상 노출을 조정하는 건. 같은 출처의 현재 건은 키당 최대 하나이며 여러 위치를 연결 |
| 위치별 조치 주기 | 대응 건에 연결된 위치의 담당·외부 조치·기록 마침·재검증 이력. 한 위치의 성공을 다른 위치에 적용하지 않음 |

발견 원천과 키 발급자는 다르다. Notion에서 AWS 키를 찾았다면 원천은 Notion, 발급자는 AWS다. 물리 테이블·필드는 [데이터 계약](../03-architecture/data-contract.md), 주소·응답은 [API 계약](../03-architecture/api-contract.md)을 따른다.

## 2. 서로 독립적인 상태 축

| 축 | 내부 값 | 사용자에게 전달할 사실 |
|---|---|---|
| 대응 출처 | `UNCLASSIFIED / TEST / PRODUCTION` | 범위 설정 필요 / 시험 / 운영. 승인 범위의 집계 출처이며 키 사용 환경·안전 여부가 아님 |
| 사용 환경 | `PROD / DEV / UNKNOWN` 등 | 실제 사용처가 확인된 환경. 출처·저장소 이름에서 추정하지 않음 |
| 구성 | `CONFIRMED / CANDIDATE / METADATA_ONLY` | 구성 확인 / 불완전 후보 / 메타데이터. CONFIRMED는 실제 사용 가능한 키라는 검증 결과가 아님 |
| 현재 존재 | `PRESENT / MISSING / UNKNOWN` | 마지막 비교 가능한 검사에서 발견 / 미발견 / 확인 불가. 실패나 미지원은 MISSING이 아님 |
| 유효성 | `VALID / INVALID / UNKNOWN / UNCHECKED` | 유효 / 사용 불가 / 확인 불가 / 미검증. INVALID의 이유가 폐기·만료인지는 별도 증거가 필요 |
| 위치별 노출 | `ABNORMAL / NORMAL / UNKNOWN` | 노출 확인 / 승인 보관 / 확인 필요. 수집 허가·유효성과 독립 |
| Finding 교정 | `FALSE_POSITIVE` 또는 교정 없음 | 실제 자격 증명이 아닌 탐지 오류. NORMAL·INVALID와 구분 |
| 보관 정책 적용 | `ALLOWED / DENIED / UNKNOWN` | 명시적 허용 일치 / 금지 규칙 일치 / 정책 확인 필요. DENIED는 보안 확인 전 자동 ABNORMAL이 아님 |
| 심각도 | `CRITICAL / HIGH / MEDIUM / LOW` 또는 미평가 | 정책과 근거가 있는 영향 등급. 키 모양·접두사·TEST 표식만으로 부여하지 않음 |
| 조치 단계 | `OPEN / IN_PROGRESS / REVALIDATION_PENDING / RESOLVED` | 담당자·조치 준비 / 조치 중 / 재검사 대기 / 해결. 현황에서는 앞 두 단계를 대응 중으로 묶어 표시 가능 |
| 예외 | `RISK_ACCEPTED` | 만료·범위가 있는 위험 수용. 안전·해결·오탐과 구분 |
| 해결 확인 범위 | `FULL / LIMITED / SIMULATION` | 승인·지원 범위 확인 / 한계 있는 확인 / 합성 시험 종료. RESOLVED 여부와 확인의 한계를 함께 표시 |
| 최신성·커버리지 | 최근 시도, 마지막 성공, 적용 범위·버전, 조치 후 검사 여부 | 오래된 사실과 현재 확인 불가를 구분. 범위 누락이 과거 판정·대응 사실을 지우지 않음 |

VALID는 인증 가능성의 확인이며 사용·악용·영향을 입증하지 않는다. METADATA_ONLY는 키 값 발견·노출·권한 확인이 아니다. 같은 키에 NORMAL 위치와 ABNORMAL 위치가 공존할 수 있으며 키 전체에 노출 상태 하나를 덮어씌우지 않는다.

유효성 사유는 `EXPIRED_CONFIRMED`, `REVOKED_CONFIRMED`, `INACTIVE_CONFIRMED`, `INVALID_UNSPECIFIED`, `UNSUPPORTED_TYPE`, `INCOMPLETE_CREDENTIAL`, `SOURCE_UNAVAILABLE`, `PERMISSION_LIMITED`, `RATE_LIMITED`, `NETWORK_ERROR`, `PROVIDER_ERROR`, `VALIDATOR_AUTH_ERROR` 등 허용 코드와 시각으로 보존한다. 사유 불명 인증 실패와 TruffleHog unverified를 폐기 또는 INVALID로 임의 변환하지 않는다. 검증 비활성과 합성 시험 차단 사유도 해당 시점의 기록으로 보존한다.

## 3. 파생 대기열과 현황 집계

사용자가 보는 작업 묶음은 기존 사실에서 파생한다. 버튼으로 임의 이동시키는 새 위험 상태가 아니다.

범위 설정·위치 판단·대응·검사 복구는 병행할 수 있는 업무다. 완료 조건과 영향에 따른 직접 저장·독립 검토는 [사용자 작업과 승인 기준](task-and-approval-policy.md)을 따른다. 목록에서 빠지려면 해당 진입 사유가 해소돼야 하며 저장 성공만으로 모든 사유를 지우지 않는다.

| 표시·내부 대기열 | 단위 | 포함 기준 |
|---|---|---|
| 대응 대상 `ACTION_REQUIRED` | ResponseCase | 남은 작업이 있는 현재 OPEN / IN_PROGRESS / REVALIDATION_PENDING 건. 현황은 `대응 중 = OPEN + IN_PROGRESS`, `재검사 대기 = REVALIDATION_PENDING`으로 분리 |
| 확인 필요 `NEEDS_DECISION` | Occurrence | 실제 값 후보의 부족·상충 근거, 재판정 필요 위치. 부족한 사실을 명시하고 사람의 추가 확인 요청은 담당·기한 필수. 자동 실키 경고의 미설정은 배정 대기 |
| 인벤토리 `NORMAL_INVENTORY` | CredentialSet | 메타데이터 관측(METADATA_ONLY), 같은 출처의 모든 허용 위치가 유효 Finding·활성 ALLOWED 정책·NORMAL인 승인 보관(AUTHORIZED_STORAGE), 현재 유효한 공급자 폐기·교체 근거가 있는 과거 기록(RETIRED_HISTORY)을 구분. 과거 기록은 같은 출처의 활성 대응·판정 대기·현재 존재/판정 UNKNOWN이 없어야 하며 수동 승인·단순 INVALID·만료 추정은 포함하지 않음. 일부 위치 필터로 다른 확인 필요 위치를 가려 포함시키거나 숨은 증거로 상태를 만들지 않음 |
| 건 연결 대기 `NEEDS_CASE_LINK` | Occurrence | 유효 ABNORMAL 판정이 있으나 같은 키·출처의 현재 건에 연결되지 않은 위치. 권한 경계를 포함한 연결 무결성을 보안 조정자가 복구하며 해결 조건에서는 제외하지 않음 |
| 검사 누락 `coverage-gaps` | Scope | 실패·부분 실패·미지원·비교 불가 등 완전한 현재 검사가 없는 승인 범위. 대기·진행 중과 종료 후 누락은 구분 |
| 범위 설정 `UNCLASSIFIED` | Scope | 출처 미분류·근거 재확인·보관 정책 미설정/만료/불일치·변경 검토 대기. `setupReasonCodes[]`로 사유를 독립 표시. 사유가 모두 해소돼야 제외되며 위치의 확인 필요·대응과 함께 존재 가능 |

인벤토리는 그 키가 전반적으로 안전하다는 이름이 아니다. 내부 대기열명 NORMAL_INVENTORY를 사용자에게 정상 보증처럼 표시하지 않는다. 모든 키를 찾는 전체 인벤토리는 위 작업 묶음과 별개다. 허용·비정상 위치가 함께 있는 키의 허용 위치도 키 상세에서 계속 조회할 수 있다.

한 건에 여러 위치가 있어도 대응 건은 한 번만 센다. 여러 사실이 공존할 수 있으므로 같은 키의 확인 필요 위치와 대응 건이 동시에 나타날 수 있고, 그 건의 최신 검사가 실패하면 검사 누락에도 나타난다. 따라서 **확인 필요 위치 수 + 대응 건 수 + 검사 누락 범위 수**를 더해 총 키 수·총 위험 수로 만들지 않는다. 담당자 미지정·기한 초과·검증 미완료는 중복 가능한 보조 지표다.

주요 집계는 같은 기준시점·적용 필터·권한에서 서버가 계산한다. 권한을 적용한 뒤 중복 제거·페이지 처리하며 제한 위치의 정확한 수나 이름을 카드·필터 조합으로 유출하지 않는다. 목록 20행을 세어 전체 현황처럼 표시하지 않는다. 집계 근거를 확인할 수 없으면 확인 불가 상태로 두고 0건을 만들지 않는다.

### 3.1. 대표 다음 행동 코드

`nextActionCode`는 다음 표의 서버 허용 코드로 제공한다. 위험 점수나 새 업무 상태가 아니며, 같은 사실과 같은 권한에는 같은 코드를 반환한다. 대상 ID·다음 화면은 서버가 권한을 검사한 내부 대상으로 한정하고, 원천 URL이나 자유 문장을 동작으로 실행하지 않는다.

| 코드 | 의미와 허용 사용자 |
|---|---|
| `OPEN_REVIEW_CONTEXT` | 부족하거나 바뀐 위치 근거 확인. 해당 위치 SECURITY |
| `ASSIGN_INVESTIGATION` | 자동 조사 과제의 담당·기한 미설정 또는 담당 권한 상실을 보완. 해당 연결 SECURITY |
| `PROVIDE_EVIDENCE` | 할당된 조사 질문 또는 수명주기 확인에 필요한 안전한 근거 제출·확인. 과제 담당의 허용 제출과 SECURITY 최종 확인을 구분 |
| `OPEN_CASE` | 현재 대응 건과 해당 사용자의 허용 위치 작업을 열기. SECURITY 또는 할당 위치 REMEDIATOR |
| `ASSIGN_REMEDIATOR` | 대응 위치의 적격 조치 담당자 지정. 해당 위치 SECURITY |
| `RECORD_ACTION` | 담당 위치의 실질 외부 조치 기록. 지정되고 해당 위치에 권한 있는 REMEDIATOR |
| `REVALIDATE_LOCATION` | 기록 마침 조건을 충족한 지원 위치의 비동기 재검사 요청. 지정되고 해당 위치에 권한 있는 REMEDIATOR |
| `REPAIR_SCOPE` | 수집 실패·누락·설정 문제 확인과 복구 경로 열기. 해당 범위 OPERATIONS 또는 허용된 SECURITY. 자체 스캔 시작을 뜻하지 않음 |
| `CHECK_RESOLUTION` | 위치 제거·키 수명주기·전체 필수 범위의 해결 근거 확인. 전체 해결 대상에 SECURITY 권한이 있는 보안 조정자 |
| `VIEW_INVENTORY` | 허용된 키·위치의 승인 보관·메타데이터·과거 기록 열기. 해당 사실의 열람 권한 보유자 |
| `LINK_EXISTING_ASSESSMENT` | 이미 확정한 ABNORMAL 위치를 판정 반복 없이 같은 키·출처의 현재 건에 연결. 해당 위치와 건에 권한을 가진 SECURITY |
| `SET_SCOPE_ORIGIN` | 범위 출처와 변경 영향을 확인해 직접 저장 또는 검토 요청. 해당 Scope의 SECURITY 또는 OPERATIONS의 허용 제안 |
| `CONFIGURE_STORAGE_POLICY` | 해당 범위에 맞는 보관 정책 보완. SECURITY의 정책 관리 또는 허용된 담당자 요청 |
| `REVIEW_SCOPE_CHANGE` | 독립 검토가 필요한 제안의 근거·영향 확인. 제안자와 다른 해당 범위 SECURITY |
| `REQUEST_AUTHORIZED_ACTION` | 열람·업무 요청 권한이 있는 대상의 내부 담당 요청. 권한 부여·실제 보안 결정은 수행하지 않음 |
| `WAIT_FOR_AUTHORIZED_ACTOR` | 다른 담당자의 작업·현재 실행을 기다림. 대기 사유·요청/실행 시각·허용 링크와 담당 역할을 표시. 미지정이면 적격 담당자 지정 또는 내부 요청을 보조 행동으로 제공 |

### 3.2. 다중 사실과 역할별 선택 순서

서버는 먼저 대상에 대한 권한·할당·지원 기능을 검사하고 실행 불가능한 행동을 후보에서 제외한다. 그 뒤 같은 행에서 아래 순서를 적용한다. 부족한 사실과 보조 행동은 `facts[]`·차단 이유에 계속 남기며 대표 행동 하나로 사실을 덮지 않는다.

1. 이미 확인된 노출에 현재 건이 없으면 적격 SECURITY에게 `LINK_EXISTING_ASSESSMENT`, 연결된 건이 있으면 위치의 미지정 담당에 `ASSIGN_REMEDIATOR`, 실제 조치가 남았으면 할당 REMEDIATOR에게 `RECORD_ACTION`을 우선한다. 위치별 기록 마침·재조치 재개 등 세부 판단이 필요한 때는 `OPEN_CASE`로 보낸다.
2. 외부 조치를 마친 지원 위치는 `REVALIDATE_LOCATION`, 재검사에서 필수 범위 오류가 확인되고 사용자가 복구 권한을 가지면 `REPAIR_SCOPE`, 키 수명주기 등 추가 증거가 필요하면 `PROVIDE_EVIDENCE`, 필수 근거가 모두 준비되면 `CHECK_RESOLUTION`을 선택한다. 재검사 작업이 대기·실행 중이면 중복 요청 대신 대기 상태와 실행 링크를 제공한다.
3. 아직 노출을 결정하지 않은 위치는 배정이 필요한 자동 조사에 `ASSIGN_INVESTIGATION`, 자신의 열린 조사 질문에 `PROVIDE_EVIDENCE`, 새 근거 또는 판정이 필요한 SECURITY에게 `OPEN_REVIEW_CONTEXT`를 선택한다. 보안 담당자의 새 결정으로 확인된 노출을 만들기 전에는 조치 담당자에게 노출 조치를 강제하지 않는다.
4. 범위 행은 검사 복구에 `REPAIR_SCOPE`, 출처 미분류에 `SET_SCOPE_ORIGIN`, 정책 보완에 `CONFIGURE_STORAGE_POLICY`, 적격 검토자에게 `REVIEW_SCOPE_CHANGE`를 사용한다. 제안자는 대기 내용 또는 허용된 담당 요청을 본다. 인벤토리 행은 `VIEW_INVENTORY`를 사용한다. 자동 생성 과제의 담당·기한 미설정은 실제 배정·정책 보완을 먼저 안내한다.

확정 노출과 검사 누락이 같은 위치에 공존하면 권한 있는 사용자의 **노출 조치**를 주 행동으로, 범위 복구를 보조로 둔다. 조치가 끝났고 검사 실패가 다음 증거를 막는 때는 복구가 주 행동이 된다. 사용자가 노출 조치를 할 수 없지만 복구 등 보조 행동은 할 수 있으면 그 허용 행동을 제시한다. 가능한 행동이 전혀 없으면 `WAIT_FOR_AUTHORIZED_ACTOR`와 안전한 대기 이유를 반환하고 다른 담당자의 권한을 대신 부여하지 않는다. 서로 다른 건·위치·범위를 하나의 혼합 위험 순위로 비교하지 않는다.

## 4. 대응 건과 위치별 조치

위치의 판정, 조치 주기, 현재 존재와 키 수명주기 증거는 따로 기록한다. 건 단계는 이 사실을 요약하지만 위치별 차이를 없애지 않는다.

| 사건 | 위치와 건의 처리 |
|---|---|
| 근거 있는 노출 확인 | 판정 + 같은 키·출처의 현재 건 생성 또는 위치 연결을 원자적으로 확정. 새 건은 OPEN |
| 담당자 지정·가이드 조회·체크리스트 점검 | 준비·보조 기록만 남김. 실질 외부 조치나 해결로 세지 않음 |
| 첫 실질 외부 조치 기록 | 해당 위치의 조치 주기와 건을 OPEN→IN_PROGRESS로 전환. 별도 빈 시작 버튼은 요구하지 않음 |
| 위치의 기록 마침과 재검증 제출 | 그 위치를 재확인 대상으로 고정. 미완료 위치가 있으면 건은 IN_PROGRESS, 모든 필수 위치가 제출되면 REVALIDATION_PENDING |
| 재검증 PRESENT·MISSING·UNKNOWN | 위치별 결과와 비교 범위·시각 기록. 어떤 결과도 그 자체로 건을 RESOLVED로 바꾸지 않음 |
| PRESENT 후 재조치 | 담당자의 의미 있는 재조치 요청으로 해당 위치의 새 주기를 열고 건은 IN_PROGRESS. 이전 조치·재검증 보존 |
| 재검사 대기 중 새 ABNORMAL 위치 연결 | 새 위치의 미완료 주기와 함께 건을 같은 트랜잭션에서 IN_PROGRESS로 변경 |
| 해결 요청 | 서버가 모든 필수 위치·미연결 노출·불확실성·조치 후 검사·키 수명주기 증거를 재확인한 후 보안 담당자가 확정 |
| 해결 이후 새 노출 | 이전 건은 유지하고 새 OPEN 건을 연결. 과거 해결을 조용히 취소하지 않음 |

동일한 키 폐기·교체 증거는 키 단위 사실로 연결할 수 있으나 각 위치의 제거와 재검사를 대신하지 못한다. 반대로 위치 하나의 MISSING을 키 폐기의 증거로 사용하지 않는다. 일부 위치의 불확실성·권한 문제가 다른 확정 노출 위치의 긴급 조치를 일괄 잠그지 않지만 전체 해결에는 남은 차단 사유를 검사한다. 다중 위치·권한·동시 요청의 상세 조건은 [대응 정책](response-policy.md)을 따른다.

## 5. 해결·예외와 수치의 경계

네 내부 조치 단계와 전체 위험 수용은 같은 현재 건 모집단에서 배타적으로 센다.

```text
현재 대응 건 수 = OPEN + IN_PROGRESS + REVALIDATION_PENDING + RESOLVED + 전체 RISK_ACCEPTED
대응 중 = OPEN + IN_PROGRESS
```

위 수식은 모든 관련 위치에 SECURITY 권한이 있는 보안 조정자의 같은 모집단에서 적용한다. RISK_ACCEPTED는 action_status를 덮어쓰는 다섯 번째 저장 단계가 아니라 유효 예외의 범위·만료·버전을 현재 검사한 파생 표시다. 일부 위치만 위험 수용하거나 남은 위험이 예외 밖이면 건은 원래 미해결 단계에 남는다. 일부 위치만 보는 사용자는 원래 조치 단계와 restrictedCoverage를 보며 숨은 예외의 승인·만료로 단계가 바뀌지 않는다. 인벤토리, 오탐·범위 교정 종료와 대응 건 없는 폐기·만료 이력은 이 모집단에 포함하지 않는다. 해결된 현재 건은 새 노출로 새 현재 건이 생기면 이력으로 남기고 새 건만 현재 모집단에 센다.

FULL은 선언된 지원·승인 범위의 모든 필수 확인이 성공했다는 뜻이며 모든 가능한 복사본·과거 악용 부재를 보증하지 않는다. LIMITED는 지원 밖 이력 또는 승인된 수동 확인 등 남은 한계를 적는 수준이며 확인된 미해결 노출·필수 검사 실패를 우회하지 못한다. SIMULATION은 키별 승인 fixture 일치가 확인된 시험 건의 제거·재검사 종료다. 실키 가능성이 있는 시험 키에는 허용하지 않는다. 자세한 해결 근거와 교정 종료는 [대응 정책](response-policy.md)에 둔다.

기본 화면·통합 현황·CSV 운영 수치는 PRODUCTION이다. TEST는 명시적인 시험 보기의 표시를 유지하고 별도로 집계한다. 시험 출처의 실키 의심 경고와 UNCLASSIFIED 범위는 운영 화면에서 별도 주의 항목으로 제공하되 운영 건수에 더하지 않는다. 화면에서 TEST 단어를 숨기는 행위로 출처 구분을 없애지 않는다.

## 6. 실패·시차와 이력 보존

예를 들어 06:00 유효 확인 뒤 09:05 키 폐기 기록이 있고 09:10 재검사가 실패했다면 세 사실을 모두 보존한다. 06:00 결과를 현재 유효라고 단정하거나 09:05 자기 신고를 폐기 확인으로 바꾸지 않는다. 화면은 조치 이후 확인 불가와 마지막 성공 시각을 함께 표시한다. 마지막 실질 조치 뒤의 공급자 관측이 없으면 현재 유효성은 UNCHECKED·POST_ACTION_VALIDATION_REQUIRED이며 이전 관측 결과·시각은 별도 이력이다. 성공하지 못한 재검사로 PRESENT를 MISSING으로 바꾸거나 마지막 성공 시각을 갱신하지 않는다.
