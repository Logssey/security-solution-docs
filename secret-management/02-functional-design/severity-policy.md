# 심각도 판정 정책

기준: [PRD](../01-requirements/PRD.md) FR-07, FR-10, [ADR-S007](../03-architecture/adr/ADR-S007.md). 이 문서는 제품의 판정 규칙이다. 외부 솔루션의 공식 산식이 아니다. 평가와 저장 기록의 정책 버전은 `severity-v2`다.

아래 규칙은 명시된 순서로 적용하며 각 평가에 정책 버전·규칙 ID·근거를 보존한다. 다른 기능의 관리 안내 등급이나 공급자별 임의 점수로 대체하지 않는다.

## 1. 평가 단위와 입력

비정상 노출이 확인된 `Occurrence`마다 평가한다. 승인된 비밀 저장소에 정상 보관된 사실, AWS IAM 목록에서 `METADATA_ONLY`로 존재를 확인한 사실 또는 Secrets Manager·SSM·S3 목록에서 항목 수를 확인한 사실만으로는 대응 건이나 심각도를 만들지 않는다. `METADATA_ONLY`는 아래 표의 `CONFIRMED` 또는 `CANDIDATE`로 자동 변환하지 않는다. 공급자, 저장 위치, 발급 주체는 서로 다른 속성이다.

정확히 승인된 AWS Secret·Parameter·S3 객체의 본문에서 자격 증명 후보를 탐지해도 그 저장 위치가 외부에 노출됐다는 뜻은 아니다. 별도의 접근 범위와 저장 정책 근거가 없으면 노출 상태·범위를 `UNKNOWN`으로 두고 권한·영향을 추정하지 않는다.

평가기는 아래 정규화된 입력과 각 입력의 증거 ID, 출처, 관측 시각을 받는다. 추측한 값이나 파일명만으로 확인 상태를 채우지 않는다.

| 입력 | 허용 값 | 판정에 필요한 근거 |
|---|---|---|
| 노출 상태 | `ABNORMAL`, `NORMAL`, `UNKNOWN` | 저장 위치에 대한 승인 정책과 실제 접근 범위 |
| 노출 범위 | `BROAD`, `BOUNDED`, `UNKNOWN` | 공개, 조직 전체 또는 불특정 외부인이 접근할 수 있으면 `BROAD`. 이름이 확인된 제한된 주체만 접근할 수 있으면 `BOUNDED` |
| 자격 증명 확인 | `CONFIRMED`, `CANDIDATE` | 완전한 구성요소와 공급자 형식 또는 승인된 검증의 증거. 문자열 탐지만으로 유효성을 증명하지 않음 |
| 영향 범위 | `ADMIN`, `IMPORTANT`, `LIMITED`, `MINIMAL`, `UNKNOWN` | 확인된 권한, 적용 대상과 자원 중요도. 아래 분류 기준 적용 |
| 중대한 악용 | `CONFIRMED`, `NOT_CONFIRMED` | 비인가 사용과 중요 자원 또는 민감 데이터 영향의 독립 증거. 로그 부재는 악용 부정의 증거가 아님 |
| 유효성 | `VALID`, `INVALID`, `UNKNOWN`, `UNCHECKED` | 별도 검증 결과와 시각. 심각도 규칙의 단독 입력으로 사용하지 않음 |

`BROAD`에는 공개 저장소와 문서, 누구나 접근 가능한 URL, 조직 전체에 열린 위치, 승인된 접근 명단 밖의 불특정 외부인이 포함된다. `BOUNDED`는 접근 주체가 식별되고 실제 권한 범위가 제한된 경우에만 사용한다. Notion, CI/CD, 클라우드, 저장소 모두 같은 노출 범위 정의를 쓴다. 접근 권한을 조회할 수 없으면 `UNKNOWN`이다.

영향 범위는 자격 증명에 실제로 적용될 수 있다고 확인된 권한과 대상 중 가장 큰 영향으로 정한다.

| 영향 범위 | 확인 조건 |
|---|---|
| `ADMIN` | 운영 환경 또는 조직 전체에서 권한 부여, 자격 증명 발급, 보안 설정 변경, 관리자 수준의 자원 제어가 가능한 권한과 대상이 확인됨 |
| `IMPORTANT` | 운영 서비스 배포나 데이터 변경, 민감 데이터 열람, 중요 자원 제어 중 하나가 확인됨. `ADMIN`에는 해당하지 않음 |
| `LIMITED` | 영향을 받는 자원과 권한이 특정되었고 위 두 범주에 해당하지 않지만 실질적인 접근 또는 변경 가능성이 남음 |
| `MINIMAL` | 비운영 또는 승인된 테스트 자원만 접근 가능하고 민감 데이터와 운영 권한이 없으며, 대상과 권한이 모두 제한됨을 증거로 확인함 |
| `UNKNOWN` | 권한, 대상, 자원 중요도 또는 제한 통제 중 필요한 정보를 확인할 수 없거나 증거가 충돌함 |

발급자 API에서 인증에 성공했다는 사실은 `ADMIN`이나 `IMPORTANT`의 증거가 아니다. 명목상 권한만 확인했고 조직 정책, 권한 경계, 대상 제한이 평가에 영향을 줄 수 있는데 확인하지 못하면 `UNKNOWN`으로 둔다. `MINIMAL`은 비운영이라는 이름, 테스트 파일 경로 또는 낮은 중요도 태그만으로 부여하지 않는다.

자원 중요도는 연결 등록 시 관리되는 자산 분류에서 가져온다. 운영, 민감 데이터, 중요 서비스, 테스트 전용 여부가 확인되지 않으면 자원 이름에서 추론하지 않는다. 권한 해석기는 공급자와 토큰 유형별로 지원하는 권한 목록, 제한 통제, 대상 조회 방법과 매핑 버전을 선언한다. 지원 목록 밖의 권한이 있거나 적용 대상을 완전히 확인하지 못하면 낮은 영향 범주로 확정하지 않고 `UNKNOWN`으로 둔다. 따라서 R03부터 R07까지의 자동 적용 범위는 어댑터가 증거를 수집할 수 있는 토큰 유형에 한정된다.

## 2. 자동 판정 규칙

아래 순서로 평가하고 최초로 일치하는 규칙의 결과를 사용한다. R01의 사고 증거는 노출 범위나 현재 유효성 조회가 불가능해도 적용한다. 그 밖의 등급 규칙은 비정상 노출과 자격 증명 확인이 필요하다. 적용할 수 없는 조건은 거짓으로 추정하지 않는다.

| 순서와 규칙 ID | 조건 | 결과 |
|---|---|---|
| R00 | 노출 상태가 `NORMAL` | 심각도 없음, 인벤토리로 유지 |
| R01 | 노출 상태가 `ABNORMAL`이고 해당 노출과 연관된 중대한 악용이 `CONFIRMED` | CRITICAL |
| R02 | `ABNORMAL`, `CONFIRMED`, `BROAD`, `ADMIN` | CRITICAL |
| R03 | `ABNORMAL`, `CONFIRMED`, `BOUNDED`, `ADMIN` | HIGH |
| R04 | `ABNORMAL`, `CONFIRMED`, 노출 범위 확인, `IMPORTANT` | HIGH |
| R05 | `ABNORMAL`, `CONFIRMED`, 노출 범위 확인, `LIMITED` | MEDIUM |
| R06 | `ABNORMAL`, `CONFIRMED`, `BROAD`, `MINIMAL` | MEDIUM |
| R07 | `ABNORMAL`, `CONFIRMED`, `BOUNDED`, `MINIMAL` | LOW |
| R99 | 위 규칙에 일치하지 않음 | 미평가, 누락 또는 충돌 사유 기록 |

`CANDIDATE`는 R01을 제외하고 R99로 보낸다. R01에는 사고 조사에서 자격 증명과 노출 위치의 연관성을 별도로 확인한 증거가 필요하다. `UNKNOWN`은 `BOUNDED`, `MINIMAL`, 악용 없음의 대체값이 아니다. 미평가는 다섯 번째 위험 등급이 아니라 판정 보류 상태다.

유효성은 대응 시점의 사용 가능성을 나타내고 심각도는 확인된 노출과 잠재 또는 발생한 영향을 나타낸다. `VALID`만으로 등급을 올리지 않으며, `INVALID`나 검사 실패만으로 과거 사고 등급을 낮추지 않는다. 현재 키가 폐기되었더라도 사고 당시 악용이 확인되면 R01의 평가와 이력을 유지한다.

## 3. 공급자별 입력 정규화

공급자 어댑터는 확인한 권한, 실제 대상, 환경과 제한 통제를 함께 출력한다. 왼쪽 인증 조회만 성공하면 영향 범위는 `UNKNOWN`이다.

| 발급자 유형 | 인증만 확인하는 예 | 영향 범위를 확인하는 추가 근거 |
|---|---|---|
| AWS IAM, STS | `GetCallerIdentity`의 주체 정보 | 적용 정책, 권한 경계와 조직 제한, 대상 계정과 자원, 운영 자원 중요도. 조회할 수 없는 제한은 권한이 없는 것으로 추정하지 않음 |
| GitHub PAT, App | 사용자 조회 또는 설치 토큰 인증 | 토큰 권한과 접근 가능한 조직 및 저장소, 저장소별 실제 역할, 운영 배포 또는 민감 데이터 연결 |
| Notion 연결 토큰 | `users/me`의 bot 또는 사용자 확인 | 연결에 공유된 페이지 및 데이터베이스, 통합 기능, 페이지별 실제 접근 범위와 민감도 |
| CI/CD 및 기타 SaaS | 공급자 인증 성공 | 토큰 범위, 프로젝트 또는 파이프라인 역할, 배포 대상, 운영 환경과 적용되는 제한 |

증거 조회가 지원되지 않거나 권한 부족으로 실패하면 인증 성공과 별개로 영향 범위를 `UNKNOWN`으로 기록한다. API 오류를 낮은 권한의 증거로 바꾸지 않는다. 조회 계약과 지원 범위는 [검증기 계약](../03-architecture/source-and-validator-contract.md)에 따른다.

어댑터의 권한 매핑에는 공급자, 토큰 유형, 매핑 버전, 읽은 권한과 대상 필드, 적용한 제한, 자산 분류 버전, 최종 영향 범주를 남긴다. 권한 전체를 확인할 수 없는 유형은 인증 상태만 표시하고 영향 범주는 `UNKNOWN`으로 둔다.

## 4. 근거, 재평가와 대응 건 표시

평가에는 `policyVersion`, `ruleId`, 정규화된 입력값, 사용한 증거 ID와 관측 시각, 누락 사유, 평가 시각, 자동 또는 수동 판정자를 기록한다. 증거에는 원문 자격 증명을 저장하지 않는다. 입력이 갱신되면 새 평가를 추가하고 이전 결과를 덮어쓰지 않는다. 동일한 정책 버전과 동일한 입력은 같은 자동 결과를 내야 한다.

수동 판정은 자동 결과와 별도로 저장한다. 상향에는 추가 영향 증거를, 하향에는 이전 높은 등급 근거가 더 이상 해당하지 않는다는 반증과 승인자를 요구한다. 예외 승인, 체크리스트 완료, 유효성 검사 오류, 단순 파일 삭제만으로 하향하지 않는다. 정책 버전 변경으로 재평가하면 이전 등급과 새 등급, 바뀐 규칙을 함께 보존한다.

같은 키가 여러 위치에서 발견되면 각 비정상 노출 위치에 평가를 기록한다. 현재 대응 건의 대표 심각도는 미해결 위치의 확인된 최고 등급이다. 미평가 위치 수는 별도로 표시한다. 모든 미해결 위치가 미평가면 대표 심각도도 미평가다. 해결된 위치의 과거 등급은 이력에 남기고 현재 대표 등급에 자동 반영하지 않는다. 등급 분포와 매트릭스는 [대응 정책](response-policy.md)의 현재 대응 건을 같은 시점에 집계한다.

## 5. 판정 예시와 검증 조건

| 입력 사례 | 적용 규칙 | 기대 결과 |
|---|---|---|
| 승인된 비밀 저장소에만 있는 유효한 키 | R00 | 인벤토리, 심각도 없음 |
| 공개 문서에 노출된 운영 관리자 토큰, 권한과 대상 확인 | R02 | CRITICAL |
| 제한된 내부 CI 로그에 노출된 운영 관리자 토큰, 접근 주체 확인 | R03 | HIGH |
| 공개 저장소에 노출된 운영 민감 데이터 읽기 토큰, 대상 확인 | R04 | HIGH |
| 제한된 팀 문서에 노출된 특정 자원 읽기 토큰, 영향 확인 | R05 | MEDIUM |
| 공개 저장소에 노출된 테스트 전용 토큰, 운영 접근 불가 확인 | R06 | MEDIUM |
| 제한된 팀 문서에 노출된 테스트 전용 토큰, 대상과 권한 제한 확인 | R07 | LOW |
| 공개 노출과 인증 성공만 확인, 권한과 대상 조회 실패 | R99 | 미평가, `IMPACT_UNKNOWN` |
| 노출은 확인했으나 접근 가능한 사람이 불명확 | R99 | 미평가, `EXPOSURE_UNKNOWN` |
| 탐지 문자열만 있고 자격 증명 확인이 안 됨 | R99 | 미평가, `CREDENTIAL_UNCONFIRMED` |
| 확인된 중대한 비인가 사용과 관련 노출이 있으며 현재 키는 폐기됨 | R01 | CRITICAL과 과거 영향 이력 유지 |

동일한 정책과 입력은 이 표의 결과를 재현해야 한다. 실제 공급자 권한 매핑은 승인된 시험 계정의 확인 근거를 사용하며, 확인하지 못한 공급자 권한은 R99로 귀결된다.
