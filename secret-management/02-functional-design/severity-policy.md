# 시크릿 노출 심각도 판정 정책

기준: [PRD](../01-requirements/PRD.md) FR-07, FR-10, [ADR-S007](../03-architecture/adr/ADR-S007.md). 이 문서는 제품의 판정 규칙이며 외부 솔루션의 공식 산식이 아니다. 평가와 저장 기록의 정책 버전은 `severity-v2`다. 네 등급은 `CRITICAL`, `HIGH`, `MEDIUM`, `LOW`이며, 미평가는 등급이 아닌 판정 보류 상태다.

규칙은 R00부터 순서대로 적용하고 최초 일치 결과를 쓴다. 각 평가에 정책 버전·규칙 ID·정규화 입력·근거를 보존한다. 다른 기능의 관리 안내 등급이나 공급자별 임의 점수로 대체하지 않는다. 아래 입력 근거·충돌·최신성 요건은 이 규칙의 적용 조건을 명확히 한다. 등급 경계, 규칙 우선순위 또는 동일한 적격 입력의 결과를 바꾸려면 새 정책 버전과 회귀 검증이 필요하며 `severity-v2`를 조용히 덮어쓰지 않는다.

## 1. 평가 단위와 제외 범위

심각도는 키 전체가 아니라 원천 객체·버전이 식별된 `Occurrence`의 노출에 대해 평가한다. 같은 키가 승인된 Secret 저장소와 공개 파일에 있으면 각각 정상 보관과 비정상 노출로 판단한다. 한 위치의 정상 보관 근거나 다른 위치의 악용 증거를 키가 같다는 이유만으로 전파하지 않는다. 위치·사고의 연관성이 확인된 근거만 해당 평가에 사용한다.

정상 보관 여부를 확인하기 위한 R00 경로와 비정상 노출의 R01~R07 경로를 구분한다. `NORMAL`은 유효한 보관 허용 정책과 실제 접근 범위가 일치한 결과다. 수집을 승인했다는 사실, 비밀 관리 서비스에 있다는 사실, 저장소 이름, 테스트 태그만으로 정상 보관을 확정하지 않는다. 보관 허용·접근 근거가 없으면 `UNKNOWN`이다. 위치에서 제거되거나 대응이 해결되었다는 사실도 과거의 비정상 노출을 `NORMAL`로 다시 쓰는 사유가 아니다.

다음은 평가 입력을 만들기 전에 구분한다.

| 관측 또는 판정 | 처리 |
|---|---|
| IAM 목록의 `METADATA_ONLY` | 인벤토리·관측만 유지. `CONFIRMED`·`CANDIDATE`로 자동 변환하지 않고 심각도 평가·대응 건 생성에서 제외 |
| Secrets Manager·SSM·S3 목록의 항목 수 | 실행 범위의 수집 결과만 유지. 자격 증명·위치·심각도를 만들지 않음 |
| 정확히 승인된 Secret·Parameter·S3 객체 본문에서 찾은 후보 | 값 탐지와 노출 판단을 분리. 보관 정책·실제 접근 범위가 확인되지 않으면 노출 상태·범위는 `UNKNOWN` |
| 정상 보관으로 확인된 값 위치 | R00, `NOT_APPLICABLE`, 심각도 없음. 인벤토리에 유지하며 미평가 건수에 넣지 않음 |
| 값 후보의 필요한 근거가 부족하거나 충돌한 위치 | R99, `UNASSESSED`, 심각도 없음. 정상 보관·LOW로 표시하지 않음 |
| 실제 자격 증명이 아님이 확인된 오탐 | 탐지 교정 이력으로 관리. R00의 정상 보관이나 R99의 정보 부족으로 대체하지 않음 |

공급자, 저장 위치, 발급 주체, 수집에 사용한 연결 자격 증명은 서로 다른 속성이다. 수집용 `JJanghoon`의 권한을 발견된 키의 권한으로 사용하지 않는다. `TEST`는 수집 출처 구분이며 키별 합성 fixture 증거도, `MINIMAL`의 근거도 아니다.

## 2. 여섯 입력 축과 근거

평가기는 다음 정규화 입력과 각 입력의 증거 ID·출처·대상·관측 시각·적용 범위를 받는다. 값의 이름이 같아도 축과 의미가 다르므로 `CONFIRMED` 등을 공통 불리언으로 합치지 않는다. 문자열 탐지·인증 성공·실제 권한·악용을 서로 대체하지 않는다.

| 입력 축 | 허용 값 | 확인 기준 |
|---|---|---|
| 보관·공유 적정성 (`exposure`) | `ABNORMAL`, `NORMAL`, `UNKNOWN` | 해당 위치·시점의 보관 허용 정책과 실제 접근 근거. 승인되지 않은 보관·노출이 확인되면 `ABNORMAL`, 허용 조건 충족이 확인되면 `NORMAL`, 부족·충돌은 `UNKNOWN` |
| 접근 가능 범위 (`exposureRange`) | `BROAD`, `BOUNDED`, `UNKNOWN` | 해당 위치를 실제로 읽을 수 있는 주체와 접근 통제 |
| 키 구성 확인 (`credential`) | `CONFIRMED`, `CANDIDATE` | 유형별 필수 구성요소·연결 관계·공급자 형식 또는 승인된 검증 근거. 형식 확인은 현재 인증 가능성을 증명하지 않음 |
| 권한과 자원 영향 (`impact`) | `ADMIN`, `IMPORTANT`, `LIMITED`, `MINIMAL`, `UNKNOWN` | 발견된 자격 증명 자체의 적용 권한·대상·제한 통제·자원 중요도를 지원 매핑으로 해석한 근거 |
| 중대한 사고 근거 (`abuse`) | `CONFIRMED`, `NOT_CONFIRMED` | 해당 자격 증명과 해당 노출의 연관성, 비인가 사용, 중요 자원 또는 민감 데이터 영향의 독립 증거 |
| 현재 인증 상태 (`validity`) | `VALID`, `INVALID`, `UNKNOWN`, `UNCHECKED` | 독립 검증의 결과·방법·시각. 심각도 등급을 올리거나 내리는 조건으로 쓰지 않음 |

`BROAD`에는 공개 저장소·문서, 누구나 접근 가능한 URL, 조직 전체에 열린 위치, 승인 명단 밖의 불특정 외부인이 접근할 수 있는 위치가 포함된다. `BOUNDED`는 접근 주체가 식별되고 그 집합과 실제 접근 통제가 제한됨을 확인한 경우다. Notion·CI/CD·클라우드·저장소에 같은 정의를 적용한다. 단순히 비공개라는 표시만 있거나 접근 권한을 조회하지 못하면 `UNKNOWN`이다. 제한된 사람에게 노출되어도 그 보관이 승인되지 않았다면 노출 상태는 `ABNORMAL`일 수 있다.

중대한 악용 `NOT_CONFIRMED`는 **중대한 악용을 확정할 증거가 아직 없다**는 뜻이다. 미조사, 로그 미수집·보존기간 경과, 권한 부족, 증거 부족도 포함하며 각 이유를 별도로 남긴다. 악용 없음·미사용·안전함이 확인되었다는 뜻이 아니다. 최근 사용 시각, 정상 업무 사용, 인증 성공, 의심 로그 하나만으로 `CONFIRMED`를 부여하지 않는다. 반대로 관련 사고의 비인가 사용과 중대한 영향이 독립 근거로 확인되면 현재 토큰이 무효여도 `CONFIRMED`를 유지한다.

### 근거의 적용 범위와 최신성

각 입력의 근거에는 해당 키의 보호된 식별자, 위치·원천 버전, 확인한 주체·자원 범위, 완전·부분 여부, 적용 정책·매핑 버전과 관측 시각을 연결한다. 본문 자격 증명, 원본 토큰, 인증 헤더, 공급자 오류 본문은 저장하지 않는다. 근거 보관·정규화 세부는 [평가·저장 계약](../03-architecture/risk-assessment-contract.md)을 따른다.

현재 보관 정책·접근 권한·토큰 권한·대상·자산 분류는 평가 기준시점에 적용 가능해야 한다. 최신성은 증거 유형별로 선언된 버전 있는 기준과 원천 변경·정책 변경·이후 실패·부분 조회 여부로 판정한다. 명시된 유효기간이나 최신성 기준이 없으면 무기한 최신 근거로 취급하지 않는다. 필요한 근거가 오래되었거나 현재 대상과 비교 불가능하면 노출 상태·범위·영향은 `UNKNOWN`, 자격 증명 확인을 입증하지 못하면 `CANDIDATE`로 정규화하고 재조회 가능한 범위를 안내한다. 악용을 확정할 수 없으면 `NOT_CONFIRMED`와 이유를 사용하되 이미 확정한 역사적 사고를 현재 조회 실패로 취소하지 않는다. 유효성의 최신성은 독립 검증 계약을 따른다. 최근 실패가 마지막 성공 시각을 갱신하지 않는다.

평가 기준시각·최신성 기준 버전·정규화 결과를 함께 고정해 같은 입력의 결과를 재현한다. 과거 사고의 발생·연관성에 대한 확정 근거는 현재 ACL 조회 실패나 키 폐기 때문에 만료되는 현재 상태 근거로 취급하지 않는다. 평가 경로에서 쓰지 않는 축의 미확인·오래된 근거가 R00·R01을 일괄 차단하지는 않는다.

### 영향 범위 분류

확인된 권한과 적용 대상 중 가장 큰 영향을 사용하되, 필요한 권한·대상·제한 통제의 완전성을 먼저 확인한다.

| 영향 범위 | 확인 조건 |
|---|---|
| `ADMIN` | 운영 환경 또는 조직 전체에서 권한 부여, 자격 증명 발급, 보안 설정 변경, 관리자 수준의 자원 제어가 가능한 실제 권한과 대상이 확인됨 |
| `IMPORTANT` | 운영 서비스 배포나 데이터 변경, 민감 데이터 열람, 중요 자원 제어 중 하나가 확인되고 `ADMIN`에는 해당하지 않음 |
| `LIMITED` | 영향을 받는 자원·권한이 특정되었고 위 두 범주에 해당하지 않지만 실질적인 접근 또는 변경 가능성이 남음 |
| `MINIMAL` | 비운영 또는 승인된 테스트 자원만 접근 가능하며 민감 데이터·운영 권한이 없고, 전체 대상과 권한이 제한됨을 확인함 |
| `UNKNOWN` | 권한·대상·자원 중요도·적용 제한 중 필요한 정보를 확인할 수 없거나 완전성 미확인·부분 조회·근거 충돌이 있음 |

인증 성공은 `ADMIN`·`IMPORTANT`의 증거가 아니다. 반대로 특정 조회의 권한 거절은 그 조회 외의 권한이 없다는 증거가 아니다. 명목상 권한만 확인했고 조직 정책·권한 경계·대상 제한이 평가에 영향을 줄 수 있는데 확인하지 못하면 `UNKNOWN`이다. 부분 조회에서 관리자 권한처럼 보이는 항목을 찾았어도 적용 가능성·제한 통제의 완전성을 입증하지 못한 지원 유형은 영향 범주를 확정하지 않는다.

자원 중요도는 버전과 적용 범위가 있는 자산 분류 근거에서 가져온다. 운영·민감 데이터·중요 서비스·테스트 전용 여부를 이름·경로·태그로 추론하지 않는다. `MINIMAL`은 낮은 중요도 표시나 `TEST` 라벨만으로 부여하지 않는다. 키가 합성 fixture라는 사실과 실제 테스트 계정의 제한된 권한은 별개다.

## 3. 자동 판정 규칙

표의 `—`는 **그 규칙이 해당 축을 사용하지 않음**을 뜻한다. `UNKNOWN`을 모든 값과 일치시키는 와일드카드가 아니다. `BROAD 또는 BOUNDED`에는 `UNKNOWN`이 포함되지 않는다. 필요한 축만 평가하고 그 축의 누락·오래된 근거·충돌을 검사한다. 모든 축이 채워져야 시작하는 공통 선행조건을 두지 않는다.

| 규칙 ID | 노출 상태 | 자격 증명 확인 | 노출 범위 | 영향 범위 | 중대한 악용 | 유효성 | 결과 |
|---|---|---|---|---|---|---|---|
| R00 | `NORMAL` | — | — | — | — | — | `NOT_APPLICABLE`, 심각도 없음, 정상 보관 인벤토리 |
| R01 | `ABNORMAL` | — | — | — | `CONFIRMED` | — | `ASSESSED`, `CRITICAL` |
| R02 | `ABNORMAL` | `CONFIRMED` | `BROAD` | `ADMIN` | — | — | `ASSESSED`, `CRITICAL` |
| R03 | `ABNORMAL` | `CONFIRMED` | `BOUNDED` | `ADMIN` | — | — | `ASSESSED`, `HIGH` |
| R04 | `ABNORMAL` | `CONFIRMED` | `BROAD 또는 BOUNDED` | `IMPORTANT` | — | — | `ASSESSED`, `HIGH` |
| R05 | `ABNORMAL` | `CONFIRMED` | `BROAD 또는 BOUNDED` | `LIMITED` | — | — | `ASSESSED`, `MEDIUM` |
| R06 | `ABNORMAL` | `CONFIRMED` | `BROAD` | `MINIMAL` | — | — | `ASSESSED`, `MEDIUM` |
| R07 | `ABNORMAL` | `CONFIRMED` | `BOUNDED` | `MINIMAL` | — | — | `ASSESSED`, `LOW` |
| R99 | 위 규칙에 일치하지 않거나 필요한 근거가 충돌함 | — | — | — | — | — | `UNASSESSED`, 심각도 없음, 부족·충돌 이유 기록 |

R00은 현재 적용 가능한 정상 보관 근거가 필요하다. R01은 비정상 노출 근거와 **해당 자격 증명·위치·사고를 연결하는 중대한 악용 근거**가 필요하다. 그 연관 근거가 있으면 자격 증명 확인 축이 `CANDIDATE`여도 별도로 확인된 사고 근거를 사용하며, 노출 범위·영향 범위·현재 유효성이 미확인이라는 이유로 R01을 막지 않는다. `CANDIDATE`가 R01을 제외한 등급 규칙에 들어가지는 않는다. `CONFIRMED` 악용이 없는 R02~R07은 악용 부재를 전제로 하지 않고 확인된 노출과 잠재 영향으로 평가한다.

### 정상 보관과 사고 근거의 충돌

동일 위치·적용 시점의 정상 보관 주장과 그 노출에 연관된 중대한 악용 `CONFIRMED`가 충돌하면, 규칙 적용 전에 노출 상태를 `UNKNOWN`으로 정규화하고 `EXPOSURE_INCIDENT_CONFLICT`를 기록한다. 그 평가 결과는 R99이며 R00으로 사고를 숨기지 않는다. 사고 증거만으로 노출 상태를 `ABNORMAL`로 자동 변경하지도 않는다. 같은 키의 다른 정상 보관 위치나 조치 이후의 현재 상태는 해당 노출의 과거 사고와 동일한 주장인지 먼저 구분한다.

기존에 확인된 사고의 `CRITICAL` 평가·이력은 이 충돌이나 최신 조회 실패 때문에 삭제·자동 하향하지 않는다. 최신 자동 평가가 R99여도 `lastConfirmedSeverity`와 미해결 사고에 적용 중인 기존 `CRITICAL` 유지, 재검토 필요를 별도로 표시한다. 잘못된 위치 연결·사고 오인 등의 반증이 확인되면 별도 교정 평가와 승인 근거를 추가한다. 원래 사고가 실제로 발생한 사실은 현재 키 폐기나 위치 제거로 반증되지 않는다.

유효성은 해당 검증 시점의 인증 가능성이고 심각도는 확인된 노출과 잠재 또는 발생한 영향이다. `VALID`만으로 등급을 올리지 않고, `INVALID`·`UNKNOWN`·`UNCHECKED` 또는 검사 실패만으로 등급을 내리지 않는다. 현재 키가 폐기되었어도 사고 당시 악용이 확인되면 R01의 사고 등급을 보존한다. 유효성 표시와 검증 지원·오류 해석은 [자격 증명 검증 명세](../03-architecture/credential-validation.md)에 따른다.

## 4. 공급자별 입력 정규화

인증 검증기와 영향 분석기는 독립 결과를 낸다. 영향 분석기는 **발견된 키**의 권한·실제 대상·환경·제한 통제를 함께 출력하며, 인증 조회만 성공하면 영향 범위는 `UNKNOWN`이다.

| 발급자 유형 | 인증만 확인하는 예 | 영향 분류에 필요한 추가 근거 |
|---|---|---|
| AWS IAM·STS | `GetCallerIdentity`의 주체 확인 | 해당 자격 증명에 적용되는 정책·권한 경계·세션 및 조직 제한, 대상 계정·자원과 중요도. 적용되지 않는 통제는 그 비적용 근거도 기록 |
| GitHub PAT·App | 유형별 사용자 또는 설치 주체 확인 | 해당 토큰의 권한과 접근 가능한 조직·저장소, 실제 역할·대상 제한, 운영 배포·민감 데이터 연결과 적용되는 조직 통제 |
| Notion 연결 토큰 | `users/me`의 bot 또는 사용자 확인 | 연결에 공유된 페이지·데이터베이스, 통합 기능, 페이지별 실제 접근 범위·민감도 |
| CI/CD·기타 SaaS | 공급자 인증 성공 | 토큰 범위, 프로젝트·파이프라인 역할, 배포 대상·운영 환경과 적용 제한 |

이 표는 분류에 필요한 근거를 정의하며 모든 유형의 자동 조회가 지원된다는 뜻이 아니다. 공급자·토큰 유형별로 확인 가능한 권한 목록, 전체 대상 조회, 제한 통제, 완전성 판단 방법과 매핑 버전을 등록한다. 해당 유형과 버전이 완전성을 입증한 범위에서만 R02~R07에 영향 범주를 제공한다. 미지원 권한·대상 누락·부분 페이지·정책 조회 권한 부족·제한 통제 미확인·상충 자산 분류는 `UNKNOWN`과 구체적 이유를 반환한다. 읽지 못한 제한을 ‘제한 없음’으로 가정하거나 API 오류를 낮은 권한으로 바꾸지 않는다.

AWS 수집 연결의 계정·사용자·권한과 발견된 AWS 키의 주체·권한을 분리한다. GitHub 수집 연결이 저장소를 읽을 수 있다는 사실도 그 안에서 발견한 토큰의 권한을 증명하지 않는다. 영향 분석을 위해 승인 범위나 수집 자격 증명의 권한을 자동 확대하지 않는다. 누락 근거는 허용된 재조회, 안전한 외부 증빙 또는 수동 근거 보완으로 해소할 수 있다.

매핑 기록에는 공급자·토큰 유형·매핑 버전, 읽은 권한·대상 필드, 완전성 상태, 적용·비적용 제한과 근거, 자산 분류 버전, 증거 ID·시각, 최종 영향 범주를 남긴다. 조회 계약과 지원 한계는 [수집원과 검증기 계약](../03-architecture/source-and-validator-contract.md), 검증의 실제 호출·응답 판별은 [자격 증명 검증 명세](../03-architecture/credential-validation.md)를 따른다.

## 5. 기록, 수동 보완과 화면 표시

평가에는 `policyVersion`, `ruleId`, 평가 상태와 nullable 심각도, 정규화 입력, 사용한 증거 ID·관측 시각·버전·완전성, 평가 기준시각, 부족·충돌 이유, 자동 또는 수동 판정자와 기록 시각을 남긴다. 입력이 갱신되면 새 평가를 추가하고 이전 결과를 덮어쓰지 않는다. 같은 정책·정규화 입력·평가 기준의 자동 결과는 동일해야 한다. 정책 버전이 바뀌면 이전·새 등급과 적용 규칙을 함께 보존한다.

### 수동 근거와 수동 등급

지원 어댑터가 충분한 근거를 제공하면 자동 판정한다. 모든 위치에서 사람이 여섯 축을 다시 입력하거나 이미 확정한 노출을 중복 승인하도록 요구하지 않는다. 수동 개입은 미지원·권한 부족·근거 충돌·특수 자원 분류·자동 결과에 대한 근거 있는 교정 등 자동 근거로 해결하지 못한 조건에 사용한다. 위치의 기존 조사 과제를 재사용해 부족 사실과 근거를 연결하며 매 평가마다 중복 과제를 만들지 않는다.

수동 **근거 보완**과 **등급 재정의**를 구분한다. 해당 범위 `SECURITY`는 제한된 증빙 참조, 대상 범위·시점·출처, 확인 사실과 남은 한계를 직접 기록·수용할 수 있다. 할당된 조치 담당자가 제출한 자료는 `SECURITY`가 수용한다. 일반 근거 보완에 별도 독립 승인을 일괄 요구하지 않는다. 서버는 적격성·최신성·충돌을 검사한 새 정규화 입력으로 자동 규칙을 다시 실행한다. 수동이라고 완전성 요건을 생략하거나 `UNKNOWN`을 임의로 낮은 값으로 바꾸지 않는다. 키 원문·토큰·비밀이 포함된 캡처나 자유 메모를 근거로 받지 않으며, 수동 근거를 공급자 능동 검증 성공으로 표시하지 않는다.

규칙 결과와 다른 수동 등급은 자동 결과와 별도로 보존한다. 지정된 보안 판정 권한, 적용 위치·평가 버전, 사유·근거·수행자·시각과 제출자와 다른 적격 검토자의 독립 승인을 요구한다. 기존 높은 등급을 낮추는 교정에도 반증과 독립 승인이 필요하다. 상향은 추가 영향·사고 근거가 필요하다. 예외 승인, 체크리스트 완료, 단순 파일 삭제, 인증 오류나 현재 `INVALID`만으로 과거 사고 등급을 낮추지 않는다. 근거가 바뀌면 수동 결정도 재검토 대상으로 표시하며 자동 평가가 기존 수동 이력을 덮어쓰지 않는다.

### 사용자에게 보여줄 이유와 다음 행동

결과 이유·부족 정보·`nextAction`은 서버의 규칙 ID, 검증된 사유 코드, 현재 상태·권한을 안전한 문구 템플릿에 대응시켜 생성한다. AI나 자유 메모가 등급·사실·버튼 권한을 만들어내지 않는다. 설명에는 판단에 사용한 사실·관측 시각, 사용하지 못한 근거와 이유, 실행 가능한 다음 행동을 함께 제공한다. 예를 들어 영향 정보가 부족하면 권한·대상 근거 재조회 또는 보완, 필요한 범위가 미지원이면 지원 한계와 안전한 증빙 보완을 안내한다. 미확인이라는 이유만으로 무조건 사람에게 재입력을 요구하지 않는다.

R00은 ‘정상 보관·심각도 해당 없음’, R99는 ‘미평가·부족 또는 충돌 근거’를 구분해 표시한다. `UNKNOWN` 유효성을 ‘무효’로, `NOT_CONFIRMED` 악용을 ‘악용 없음’으로 설명하지 않는다. 과거 사고 등급, 최신 자동 평가, 적용 중인 수동 판단과 현재 유효성을 서로 분리해 보여준다. 저장 필드·기존 작업 큐를 이용한 재평가·현재 적용 평가의 선택은 [평가·저장 계약](../03-architecture/risk-assessment-contract.md)을 따른다.

### 대응 건 대표 등급

같은 키가 여러 위치에서 발견되면 각 비정상 노출 위치에 독립 평가를 남긴다. 현재 대응 건의 대표 심각도는 미해결 위치의 적용 중인 확인 등급 중 최고 등급이며 미평가 위치 수를 별도로 표시한다. 일부 위치의 미평가가 다른 위치의 확정 등급을 지우지 않는다. 모든 미해결 위치가 미평가이고 보존할 미해결 사고 확정 등급도 없으면 대표 심각도도 미평가다. 정상 보관·메타데이터 위치는 이 집합에 넣지 않는다.

해결된 위치의 과거 등급은 이력에 남기고 현재 대표 등급에 자동 반영하지 않는다. 미해결 사고의 `CRITICAL` 보존과 정당한 교정은 위 충돌·수동 판정 원칙을 따른다. 해결·위험 수용·유효성 변경은 심각도와 독립이다. 등급 분포·매트릭스는 [대응 정책](response-policy.md)의 같은 출처 구분·필터·기준시점·현재 대응 건 단위로 집계한다.

## 6. 판정 예시와 검증 조건

| 영향 근거만 만료되어 재조회 전이고 관련 확정 사고는 없음 | R99 | `IMPACT_UNKNOWN`과 최신성 이유. 과거 평가 이력 보존 |
| 동일 키의 미해결 위치가 HIGH와 미평가이고 정상 보관 위치도 있음 | 위치별 규칙 | 대표 `HIGH`, 미평가 위치 수 병기. 정상 보관은 제외 |

동일한 정책·적격 입력은 이 결과를 재현해야 한다. 공급자 매핑은 승인된 시험 계정의 권한·대상·제한 경계 사례와 합성 사례로 검증한 버전만 활성화한다. API 거절·부분 페이지·권한 누락·정책 미확인·오래된 근거·서로 다른 위치의 사고 오연결을 포함해 낮은 등급이나 정상 보관으로 잘못 확정하지 않는지 검증한다. 합성 fixture의 검증 우회는 키별 증명에 따르며 `TEST` 라벨만으로 적용하지 않는다.

## 7. 사실 해석과 사용자 설명

사용자에게 표시하는 등급 이름은 **시크릿 노출 심각도**다. 여섯 입력 enum과 R00~R99는 유지하며 표시명 변경으로 새 등급을 만들지 않는다. `접근 가능 범위`와 로그인 필요 여부는 별도다. 조직 전체 공유는 인원수가 작거나 로그인이 필요해도 BROAD이며, BOUNDED는 해당 원본의 관련 공유 링크·상속·그룹·게스트 접근 경계를 확인해야 한다. 공개 접근 양성 근거는 전체 명단 조회가 부분 실패해도 보존한다.

키 원문 존재와 접근 상태는 동일 원천 revision·동시 관측 또는 겹치는 사실 적용 구간으로 결합한다. 오전 공개 관측과 비공개 전환 뒤 추가된 키를 조합하여 공개 노출을 확정하지 않는다. 적용 구간을 알 수 없는 기존 근거를 접수 시각으로 채우지 않는다. NORMAL과 같은 시점의 BROAD 근거가 충돌하면 `ACCESS_POLICY_CONFLICT`, 입력 UNKNOWN으로 보존하고 재검토한다.

권한이 없다는 완전한 자료가 있어도 지원 매핑이 없으면 `UNKNOWN/MAPPING_UNSUPPORTED`다. 빈 목록·403·부분 조회를 MINIMAL로 처리하지 않는다. 확인한 높은 권한 후보는 현재 확정 영향과 구별해 우선 조사 사유로 보여준다.

새 보관 정책의 초기 템플릿은 ‘승인된 보관소 외 실제 자격 증명 원문 보관 금지’다. 기존 범위에 DRAFT로 제공하고 정책 활성화·바인딩 절차를 거친 기간에만 적용한다. 이전 위치를 소급 판정하지 않는다. 정책이 없으면 보관·공유 적정성 UNKNOWN과 `보관 기준 설정 필요`를 표시한다.

사용 이력은 [별도 사실 계약](../03-architecture/usage-observation-contract.md)을 따르며 과거 사용 자체를 `abuse=CONFIRMED`로 바꾸지 않는다. 등록된 사고 observer가 없는 배포는 자동 사고 확정을 비활성으로 유지한다. AI는 등급 입력·정책·현재 적용 결과를 변경하지 않는다.

분류는 [NIST SP 800-30](https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication800-30r1.pdf)의 근거·불확실성·재현성 원칙을 참고한 제품 정책이다. 기관이 이 등급표를 인증하거나 지정했다고 표현하지 않는다. [AWS 정책 평가](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_evaluation-logic.html)처럼 명목 권한과 실제 요청의 적용 제약을 구분한다.

GitHub 파일의 blob SHA와 뒤이어 조회한 저장소 공개 상태만으로 동시 공개 노출을 확정하지 않는다. `ACCESS_COEXISTENCE_UNCONFIRMED`이면 공개 관측 후보는 보여주고 접근 범위는 UNKNOWN으로 유지한다. 같은 시점의 원문·ACL 결합은 [평가 계약](../03-architecture/risk-assessment-contract.md)을 따른다.
