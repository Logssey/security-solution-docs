# 시크릿 후보 판정과 조사 대기열

탐지 후보의 근거 확인, 위치별 노출 판정, 조사와 대응 건 연결 규칙을 정의한다. 대응 건을 연 뒤의 조치·재검증·해결은 [대응 정책](response-policy.md), 심각도는 [심각도 정책](severity-policy.md)을 따른다.

## 1. 담당자가 얻어야 하는 답

탐지 목록은 문자열의 모양이 키와 닮았다는 사실을 알려준다. 판정 화면은 담당자가 원문을 열람하지 않고도 다음 질문에 답할 수 있어야 한다.

1. 무엇을 어디에서 언제 찾았고, 마지막 **성공한** 검사에서 여전히 확인됐는가? 이번 검사에서 읽지 못한 범위는 무엇인가?
2. 그 위치는 수집을 허가한 범위인가, 비밀을 **보관해도 되는** 위치인가? 두 승인은 별개다.
3. 같은 인증 수단의 다른 발견 위치, 구성요소와 확인된 유효성은 무엇인가? 모르는 사실은 왜 모르는가?
4. 지금 담당자가 해야 할 일은 조치 요청, 근거 추가 조사, 인벤토리 유지, 검사 복구 중 무엇인가?
5. 조치 후 어느 위치를 어떤 범위까지 다시 확인해야 해결을 주장할 수 있는가?

Finding의 룰 일치, AWS IAM `METADATA_ONLY` 목록 관측, 연결 테스트 성공, `VALID` 검증은 각각 다른 사실이다. 어느 하나만으로 비정상 노출이나 심각도를 확정하지 않는다. 특히 수집을 승인했다는 사실은 그 위치에 비밀을 저장하도록 승인했다는 뜻이 아니다.

### 반복 판정을 줄이는 분기

서버는 먼저 현재 사실과 근거의 변경 여부를 확인한다. 새로 발견됐다는 이유만으로 모든 키에 같은 판정 양식을 요구하지 않는다. 아래 분기는 위험 등급이나 새 DB 상태가 아니라 기존 사실에서 도출하는 작업 경로다.

| 현재 근거 | 기본 경로 | 사람에게 필요한 결정 |
|---|---|---|
| 발급처 목록의 `METADATA_ONLY`이고 별도의 값 Finding이 없음 | 인벤토리의 `메타데이터` 하위 보기 | 존재 관측 자체를 노출로 판정하지 않음. 목록 읽기 실패는 범위 복구로 안내 |
| 완전한 값 위치에 유효한 명시적 허용 정책이 정확히 적용됨 | 정책 근거가 있는 `승인 보관` 인벤토리 | 같은 근거의 반복 확인은 생략. 정책·위치 버전 변경 시에만 재평가 |
| 이전 판정 또는 오탐 근거가 정확한 동일 증거에 여전히 유효함 | 기존 판정·대응을 유지 | 같은 값을 재입력하지 않음. 새 Finding에는 적용한 결정과 이유를 연결 |
| 키 구성·보관 허용·소유자·근거가 부족하거나 상충함 | `확인 필요` | 부족한 사실 하나를 조사 과제로 만들고 책임자·기한을 정함 |
| 금지 정책의 구체적 일치가 있고 실제 값 위치와 유효 Finding이 현재 확인됨 | `확인 필요`의 우선 확인 항목 | 보안 담당자가 근거를 확인해 한 번의 `노출 확인 및 조치 요청`으로 대응에 연결. 형식 탐지·금지 규칙만으로 자동 개설하지 않음 |
| 이미 확정된 비정상 위치이고 같은 출처의 현재 건에 연결됨 | 대응 건의 해당 위치 | 같은 노출을 다시 판정하지 않고 미완료 조치·재검사로 이동 |
| 승인 범위를 읽지 못해 현재 사실을 확인할 수 없음 | `검사 누락` 범위 | 연결·권한·설정 복구. 기존 노출 판정과 대응 이력은 유지 |

`확인 필요`의 목적은 입력 양식 완료가 아니라 불확실성 해소다. 이미 조사 중인 동일 위치·질문은 열린 과제를 갱신하며 6시간 재검사마다 새 과제를 만들지 않는다. 새 정책 위반·실키 의심·만료된 근거처럼 판단을 다시 요구하는 변화가 생겼을 때만 재확인 이유를 추가한다. 조사 완료 버튼 자체는 노출 판정·해결이 아니며, 결과 근거를 반영해 후속 경로가 결정되어야 한다.

## 2. 혼동하지 않을 독립 축

| 축 | 값과 의미 | 결정 또는 변경 주체 |
|---|---|---|
| 수집 허가 | 연결·범위·콘텐츠·이력과 읽기 권한. 승인되지 않은 데이터는 수집하지 않음 | 연결 관리자와 승인 기록 |
| 대응 출처 | `UNCLASSIFIED`, `TEST`, `PRODUCTION`. `TEST`는 승인된 합성·시험 시뮬레이션 출처, `PRODUCTION`은 운영 집계에 포함할 출처 | 승인 근거를 확인한 `SECURITY` |
| 자격 증명의 사용 환경 | `PROD`, `DEV`, `UNKNOWN` 등 확인된 사용처 | 사용처 근거. 출처 구분에서 추정하지 않음 |
| 구성 상태 | `CONFIRMED`, `CANDIDATE`, `METADATA_ONLY` | 정규화·동일성 근거 |
| 유효성 | `VALID`, `INVALID`, `UNKNOWN`, `UNCHECKED`와 사유·시각 | 승인된 공급자 검증기 |
| 위치별 노출 | `ABNORMAL`, `NORMAL`, `UNKNOWN` | 저장 정책과 위치 근거를 확인한 `SECURITY` |
| 후보 대기열 | 대응 대상, 확인 필요, 인벤토리, 검사 누락 | 위의 확정 기록과 검사 범위를 바탕으로 서버가 파생 |
| 심각도·대응 단계 | 확인된 영향의 등급과 대응 건의 조치 상태 | 각각 평가 정책과 대응 이력 |

`TEST` 출처에서도 실제 키가 부적절한 위치에 있을 수 있다. `TEST`라는 이유로 `NORMAL`, `INVALID`, 낮은 심각도 또는 해결로 자동 바꾸지 않는다. 운영 출처에서 시험용 키를 찾았더라도 그 발견 위치의 대응 출처는 `PRODUCTION`이며, 키의 실제 사용 환경은 별도 근거로 표현한다. `UNKNOWN`을 승인, 정상 또는 낮은 위험으로 읽지 않는다.

## 3. 연결 승인 시 출처와 보관 정책

`OPERATIONS`가 출처와 보관 정책을 제안하고 별도의 `SECURITY` 권한자가 승인한다. 신규 `TEST` 승인과 `PRODUCTION→TEST` 교정은 제안자와 승인자가 같은 사람일 수 없다.

새 범위를 승인할 때 연결 관리자는 수집 허가와 별도로 대응 출처, 비밀 보관 허용 정책의 참조·버전, 승인자, 승인 시각, 적용할 연결·범위·브랜치·경로·콘텐츠 유형과 유효 기간을 기록한다. 보관 정책은 허용 위치와 금지 위치를 판별할 수 있는 근거를 제공해야 한다. 정책이 없거나 해당 위치에 적용되는지 불명확하면 노출은 `UNKNOWN`으로 남긴다. 저장소 이름, 공급자, 파일 확장자, `private` 표시나 경로에 `test`가 들어간다는 이유로 출처 또는 보관 허용 여부를 추정하지 않는다. 알려진 합성 표본은 `PRODUCTION`으로 잘못 승인하지 못하게 제한한다.

기존 범위의 `UNCLASSIFIED`는 운영 건에 넣지 않은 채 **범위 설정 필요**로 보여준다. 담당자가 후보마다 출처를 반복해서 입력하지 않도록 출처 분류는 범위 승인 단계에서 한 번 수행한다. 한 범위에 시험·운영 콘텐츠가 섞여 있으면 범위를 나누거나 경계가 명확한 하위 범위를 승인한다. 섞인 범위를 편의상 전부 `TEST`로 지정하지 않는다.

오분류 교정은 기존 값을 조용히 덮지 않는다. 변경 전후 출처, 사유·근거, 승인자, 시각, 범위 버전을 추가 전용으로 남기고 영향을 받는 후보·집계·현재 대응 건을 재평가한다. 이미 개설한 시험 건을 운영 건으로 이름만 바꾸거나 반대 방향으로 조용히 이동시키지 않는다. 영향을 받은 건은 권한 있는 담당자가 재연결 또는 새 건 생성 여부를 검토하고 이전 이력과 연결한다. 출처나 보관 정책의 버전이 바뀌면 이전 위치별 판정의 근거가 여전히 유효한지 확인하며, 확인 전에는 해당 판정을 **재확인 필요**로 표시한다. 원본 판정 이력은 보존한다.

정확한 위치·콘텐츠 유형과 버전이 일치하는 보관 정책은 서버가 `ALLOWED`·`DENIED`·`UNKNOWN`의 **정책 적용 결과**를 근거와 함께 계산한다. 이 결과는 탐지·검증·심각도와 별개다. 명시적 허용 규칙이 `CONFIRMED`·`PRESENT` 값 위치의 유효 Finding에 적용될 때만 정책 버전과 자동 판정자를 남겨 `NORMAL` 인벤토리로 분류할 수 있다. 금지 규칙이 적용되면 근거와 함께 우선 검토 대상으로 올리되 `ABNORMAL`과 대응 건은 보안 담당자의 확인 후 기록한다. 정책이 없거나 적용 경계가 모호하면 `UNKNOWN`에 남긴다. 단순히 허용 규칙을 찾지 못한 것을 `DENIED`로 바꾸지 않는다. `TEST` 표식, 비공개 저장소 여부, 이전 수동 `NORMAL`은 자동 허용 규칙을 대체하지 못한다. 사람이 모든 후보에 같은 항목을 다시 입력하는 대신 자동 근거를 확인하고 예외·불확실한 위치에 시간을 쓰게 한다.

## 4. 근거 카드와 대기열

`/secrets/triage`는 상단에 **지금 처리할 위치 수**, 출처 확인 필요 범위 수, 검사 누락 범위 수를 단위와 함께 놓고, 그 아래에 `확인 필요` 위치 목록을 둔다. 목록 행의 읽기 순서는 **왜 여기 있나 → 마지막으로 확인한 사실과 시각 → 부족한 근거 → 담당자·기한 → 다음 행동**이다. 키 이름만 누르는 짧은 인벤토리 패널이 아니라 위치 ID로 연결된 `/secrets/triage/:secretId?occurrence=:occurrenceId` 독립 상세로 간다. 목록의 출처·원천·담당·기한 필터와 페이지는 주소에 남겨 복귀 때 복원한다.

상세 첫 화면은 다음 순서로 배치한다. 상단의 마스킹 식별자와 **현재 해야 할 한 가지 일**, 선택된 발견 위치 및 다른 위치의 수가 먼저 보인다. 그다음 `탐지·존재·검사 최신성`, `수집 허가와 별도 보관 정책`, `유효성·영향과 아직 모르는 사실`, `이전 판단·관련 대응 건` 근거 카드를 놓는다. 가능한 결과만 선택하는 **판정 영역**은 넓은 화면에서 근거 옆, 좁은 화면에서 근거 바로 아래에 놓고 긴 감사 이력은 별도 접기 영역으로 보낸다. `정상 보관`은 해당 허용 정책, `오탐`은 Finding 교정 근거, `추가 조사`는 부족한 사실·담당자·기한, `노출 확인 및 조치 요청`은 위반 근거와 기존/신규 건 연결 결과를 미리 보여준다. 조건이 부족한 결과는 비활성화 이유와 필요한 근거를 옆에 적는다. 저장 성공은 건 상세 또는 조사 과제로 이동하고, 실패는 입력 주변에 안전한 이유와 재시도 방법을 남긴다. 새로고침·직접 링크·뒤로 가기에서도 선택 위치와 목록 조건을 유지한다.

후보 상세는 긴 입력 양식보다 **근거 → 부족한 사실 → 다음 행동** 순서로 읽히게 한다. 상단에는 마스킹 식별자, 발급자·유형·구성 상태, 대응 출처와 사용 환경, 현재 주된 처리 상태를 둔다. 다음 카드에는 권한에 따라 안전한 저장소·브랜치·파일 경로·줄 번호 또는 제한된 위치 식별자, Finding 룰·버전·시각, 최초·최근 발견, 마지막 성공한 검사와 최신 검사 시도, 검사 범위·부분 실패, 동일 키의 다른 위치를 구분해 보여준다. 파일의 비밀 값, 원문 문맥, 보호키 지문과 원시 도구 출력은 표시하지 않는다. 위치 참조도 권한이 없는 사용자에게는 제한한다.

각 사실에는 **확인됨 / 확인 불가 / 아직 조사 안 함**과 근거의 출처·관측 시각을 붙인다. 저장 허용 여부에는 정책 ID·버전과 적용 범위를, 접근 범위와 유효성에는 확인한 방법과 시각을 표시한다. `VALID`라고 해도 실제 사용·악용을 확정하지 않는다. 오래된 성공과 최근 실패를 하나의 최신 성공처럼 합치지 않는다. 심각도 근거가 없다면 미평가와 누락된 입력을 표시한다. 화면의 첫 행동은 확인된 사실로 할 수 있는 일만 제안한다.

대기열은 다음 규칙으로 파생하고 수동 상태 변경 버튼으로 취급하지 않는다.

| 표시 | 단위와 조건 | 담당자에게 보이는 다음 행동 |
|---|---|---|
| 대응 대상 `ACTION_REQUIRED` | 운영·시험을 각각 분리한 `OPEN\|IN_PROGRESS\|REVALIDATION_PENDING` 현재 대응 건 중 남은 작업이 있는 건. 키당 현재 건은 출처별 최대 한 건 | 건 열기, 위치별 미완료 작업과 담당자 확인. `RESOLVED`와 전체 위험 수용은 제외 |
| 확인 필요 `NEEDS_DECISION` | 노출이 `UNKNOWN`인 실제 값 후보, 보관 정책·소유자·구성요소·접근 범위의 근거가 부족한 위치, 정책 변경 후 재검토 대상 | 무엇이 부족한지와 조사 담당자·기한·증거 요청을 표시. 확인 전에는 안전·사고를 단정하지 않음 |
| 인벤토리 `NORMAL_INVENTORY` | 같은 출처에 대응·판정 대기가 없고, 위치 보관 `NORMAL`이 정책으로 확인됐거나 `METADATA_ONLY` 또는 만료·폐기가 공급자 근거로 확인된 키 | 승인 보관 / 메타데이터만 / 폐기·만료 이력을 하위 유형으로 표시. 불완전 후보나 사유 불명 `INVALID`는 제외 |
| 검사 누락 | 범위·실행 단위의 접근 실패, 부분 실패, 지원 밖 콘텐츠 또는 비교 불가능한 현재 검사 | 복구할 연결·범위, 마지막 성공 시각, 실패 코드와 재시도 안내. 이 범위의 과거 발견은 기존 상태와 함께 최신성 경고를 유지 |

동일 키·출처에서 유효한 `ABNORMAL` 판정이 있으나 현재 건에 연결되지 않은 위치는 **건 연결 대기**로 표시한다. 권한 경계로 연결이 보류된 경우를 포함하며, 보안 조정자가 최신 범위·위치·권한 근거를 확인해 판정을 반복하지 않고 현재 건에 연결한다. 이 대기열은 판정과 건 연결의 무결성을 복구하는 경로다. 판정과 연결 이력은 보존하며 미연결 위치를 해결 조건에서 제외하지 않는다.

검사 누락은 키 수가 아닌 **검사 범위 수**다. 네 표시의 수를 무조건 더해 하나의 키 총수로 쓰지 않는다. 예를 들어 대응 중인 키의 이번 GitHub 검사가 실패하면 대응 건은 대응 대상에 남고 해당 범위는 검사 누락에도 보인다. 마지막 발견을 `MISSING`이나 정상 0건으로 바꾸지 않는다. `CANDIDATE`는 확인된 완전 키로 합치지 않고 부족한 구성요소와 확인 방법을 확인 필요에 표시한다. 오탐으로 확인된 엔진 Finding은 정상 키 인벤토리로 가장하지 않고 별도 **제외·판정 이력**에서 찾을 수 있게 한다.

인벤토리 안에서도 **승인 보관**, **메타데이터만 확인**, **폐기·만료 이력**을 다른 하위 분류로 표시한다. 메타데이터만 확인했거나 폐기된 항목을 현재 사용 가능한 정상 자격 증명으로 표현하지 않는다. 합성 `TEST` 범위의 후보는 fixture 목록·버전과 해당 키가 일치해야만 ‘검증된 합성’으로 표시한다. 일치가 없으면 ‘실키 가능성 조사’로 남기고, 실제 외부 키로 확인되면 운영 보안 담당자의 교차 환경 경고와 시험 대응 건을 함께 보여준다. 경고는 운영 대응 건수에 합치지 않지만 운영 화면에서 숨기지 않는다. 합성 시험 범위에서는 공급자 검증 호출을 자동 실행하지 않는다.

인벤토리의 **키 한 행**에는 같은 출처 구분에서 활성 대응 건이나 판정 대기 위치가 없어야 한다. 한 키의 허용된 위치와 비정상 위치가 공존하면 그 키는 대응 건 또는 검토 대기 위치에서 보고, 허용 위치는 상세의 위치별 표에만 나타낸다. 전체 인벤토리 `/secrets/findings`에서는 모든 키를 계속 찾을 수 있으며 상태별 필터가 어느 위치를 근거로 삼았는지 표시한다.

`TEST`에서 **완전한 `CONFIRMED` 값 후보가 최신 성공 검사에 `PRESENT`로 확인되고 유효한 Finding이 있으며**, 해당 키에 대해 승인 fixture 목록의 일치를 확인했으나 합성이라고 증명하지 못하면 `POSSIBLE_REAL`로 두고 운영 보안 담당자에게 **실키 의심 경고**를 즉시 보여준다. fixture 목록 조회 실패도 ‘합성 확인 불가’로 표시하며 조사를 지연하지 않는다. `CANDIDATE`, `METADATA_ONLY`, 현재 유효한 Finding이 모두 오탐으로 교정된 위치는 이 경고를 만들지 않고 판정·조사 이력에 둔다. 공급자 근거로 실키가 확인되면 같은 경고를 ‘실키 확인’으로 높이고, 나중에 승인 fixture와 일치함이 증명되거나 모든 연결 Finding이 오탐으로 교정되면 각각의 반증 근거를 검토해 경고를 닫는다. 경고는 해당 위치의 시험 대응 건이 있으면 그 건에, 아직 건을 열 근거가 없으면 조사 과제에 연결한다. 같은 키를 6시간 뒤 다시 찾아도 열린 경고를 갱신하고 중복 경고를 만들지 않는다. 경고는 운영 대응 건 수에 합치지 않으며 인지 표시만으로 위험이 처리된 것처럼 보이지 않게 한다.

자동 실키 경고와 조사 과제는 담당자·기한 설정이 없다는 이유로 생성에 실패하거나 경고를 누락하지 않는다. 해당 위치 연결에 유효한 기본 조사 담당자가 있고 그 사용자가 현재도 해당 위치의 적격 `SECURITY` 권한을 가지면 적용한다. 연결의 승인된 기한 정책이 있으면 생성 시각과 정책 버전으로 기한을 계산해 기록한다. 기본 담당자·기한 정책이 없거나 담당 권한이 취소됐으면 각각 `담당 미정`·`기한 미설정`으로 생성하고 `ASSIGN_INVESTIGATION`을 다음 행동으로 제시한다. 두 설정은 독립적이므로 한쪽의 유효한 설정까지 지우지 않는다. 기한이 없는 과제는 기한 초과 집계에서 제외하고 배정·기한 보완 대기에는 남긴다. 이후 기본 정책을 바꿔도 기존 과제의 담당·기한을 조용히 덮지 않고 명시적 변경 이력을 남긴다. 사람이 선택한 `추가 조사/NEEDS_MORE_INFO` 요청은 이 예외를 사용하지 않으며 조사 담당자와 기한이 필수다.

목록의 각 행은 상태 이름만 나열하지 않는다. **왜 이 대기열에 있는지 한 문장**, 신뢰 가능한 마지막 확인 시각, 열람 가능한 위치 수, 담당자, 다음 행동과 막힌 사유를 보여준다. `ACTION_REQUIRED` 전체를 현황의 `대응 중` 한 숫자와 동일시하지 않는다. 현황은 그중 `OPEN|IN_PROGRESS`를 `대응 중`, `REVALIDATION_PENDING`을 `재검사 대기`로 나누며 두 수는 같은 대응 건 단위다. 기본 정렬은 실제 대응 대상·기한이 지난 조사·검사 누락을 우선하되 심각도 미평가를 LOW로 취급하지 않는다. 필터와 카운트의 단위, 운영·시험 구분, 기준 시각을 화면과 API에 함께 명시한다.

기본 보기는 `PRODUCTION`만 사용하고 시험 범위는 명시적인 `시험 데이터 보기`에서 전환한다. 시험 보기의 상단과 상세·내보내기에는 시험 출처 표시를 유지하되 모든 필드에 `TEST` 문자를 반복하지 않는다. `UNCLASSIFIED` 범위와 시험 출처의 실키 의심 경고는 별도의 운영 주의 항목으로 보이며 운영 키·대응 건수에 합산하지 않는다. 표시 여부나 출처 필터를 바꿔도 권한 밖 위치의 정확한 수를 역산할 수 없어야 한다.

## 5. 위치별 판정과 불확실성 처리

자동 허용 정책이 정확히 적용되지 않은 위치는 보안 담당자가 아래 결과 중 하나를 선택한다. 선택한 결과에 필요한 근거가 없으면 서버가 저장을 거부하고 부족한 항목을 알려준다. 자동 결과와 수동 결과는 판정자·정책 버전·근거를 구별해 이력에 남긴다.

| 결과 | 필수 근거와 효과 |
|---|---|
| 노출 확인 `ABNORMAL` | 현재 발견 위치와 유효한 Finding, 적용한 보관 정책·범위 버전, 금지 또는 비승인 위치임을 확인한 근거. 유효성이 `UNKNOWN`이나 `UNCHECKED`여도 노출 판정은 가능하다. **조치 요청** 한 동작에서 판정 기록과 현재 대응 건 생성 또는 위치 연결을 함께 확정한다. |
| 승인된 보관 `NORMAL` | 완전한 현재 자격 증명과 해당 위치의 유효한 Finding, 그 위치를 실제로 허용하는 정책·승인자·유효 기간과 적용 범위. 정확한 자동 허용 규칙 또는 근거를 확인한 수동 판정으로 기록한다. 불완전 후보·메타데이터 관측, 수집 승인, 비공개 저장소 표시 또는 검증 불가만으로 정상 판정하지 않는다. 새 노출·정책 변경 시 다시 평가한다. |
| 오탐 | 이 Finding이 실제 자격 증명이 아님을 확인한 유형별 근거. 위치의 노출 상태 `NORMAL`이나 키의 유효성 `INVALID`로 바꾸지 않는다. 동일 룰의 다른 위치나 새 버전 결과까지 일괄 제외하지 않으며 이력과 재검토 조건을 남긴다. |
| 추가 조사 | 노출을 `UNKNOWN`으로 유지하고 부족한 근거 유형, 조사 담당자, 확인 기한과 안전한 티켓·변경 참조 또는 내부 조사 과제를 기록한다. 재검사 실패와 검증 미지원도 원인을 분리해 표시한다. 건을 열지 않지만 대기열에서 사라지지 않는다. |

Finding의 존재만으로 `ABNORMAL`을 결정하지 않는다. 정책이 명확하게 금지한 저장 위치라는 근거는 비공개 저장소에서도 비정상 노출 판정에 사용할 수 있다. 반대로 허용 정책을 찾지 못했다는 사실만으로 정책 위반을 확정하지 않는다. 수집 당시의 Finding과 판정 당시의 정책·위치·접근 근거를 스냅샷으로 남겨 이후 재탐지나 정책 변경으로 과거 판단이 바뀐 것처럼 보이지 않게 한다. 자유 입력에는 비밀을 붙여 넣지 못하게 제한하고 근거 참조는 허용된 내부 ID·티켓 형식만 받는다.

`INVALID_UNSPECIFIED`는 만료·폐기의 증거가 아니다. 신규 후보에서 만료 또는 폐기가 공급자 근거로 확인되면 신규 대응 건을 자동 생성하지 않고 인벤토리·발견 이력을 유지한다. 기존 대응 건은 그 뒤 키가 무효로 확인돼도 과거 노출과 다른 위치의 조치·재확인 근거를 보존하고 해결 조건을 별도로 검사한다.

현재 위치에 연결된 모든 최신 Finding이 근거를 갖춘 `FALSE_POSITIVE`로 교정됐고 독립된 유효 Finding이 없다면 그 위치를 활성 판정 대기열에서 빼고 **제외·판정 이력**에서 찾게 한다. 6시간 뒤 같은 증거가 다시 나와도 불필요한 반복 검토를 만들지 않도록, 보안 담당자가 승인한 오탐 근거는 **같은 승인 범위·원천 객체·정확한 객체 버전·위치·엔진/룰 버전·보호된 후보 동일성**이 모두 일치할 때 최대 30일 동안 새 Finding에 연결해 적용한다. 새 Finding에는 재사용한 원래 결정 ID·적용 시각과 `EXACT_EVIDENCE_REUSE`를 별도 이력으로 남긴다. 어느 하나라도 달라지거나 객체 버전을 알 수 없고, 기한 만료·승인 취소·독립된 유효 Finding이 있으면 자동 제외하지 않고 다시 대기열에 올린다. 오탐 교정은 키 전체, 다른 위치나 변경된 버전으로 넓히지 않는다.

## 6. 조치 요청은 한 번, 위치는 빠짐없이

`SECURITY`의 「노출 확인 및 조치 요청」은 위치별 `ABNORMAL` 판정과 같은 키·같은 대응 출처의 현재 건 생성 또는 기존 건에 위치 연결을 하나의 트랜잭션으로 처리한다. 저장 성공 후 화면은 새 건 또는 연결한 기존 건의 상세로 이동한다. 동일 요청의 재시도는 중복 판정·건·위치를 만들지 않고 같은 결과를 반환한다. 최신 Finding·존재 상태·범위 출처·보관 정책 버전·호출자 권한·예상 버전을 서버가 재확인한다. 충돌이면 현재 근거를 다시 읽고 차이를 보여준다. 다른 출처의 건에 위치를 붙이지 않는다.

같은 키가 여러 곳에 있으면 화면은 모든 **열람 가능한** 위치의 판단 상태를 보여주고, 각 위치에 필요한 근거를 따로 기록한다. 같은 키라는 이유로 `UNKNOWN` 또는 `NORMAL` 위치를 `ABNORMAL`로 일괄 판정하지 않는다. 이미 `ABNORMAL`으로 확정된 같은 출처의 `PRESENT` 위치는 같은 현재 건에 연결한다. 권한 밖 위치의 내용이나 수를 권한 없는 사용자에게 노출하지 않는다. 다른 연결에 걸친 건의 조회·조치 권한은 서버가 위치별로 검사한다. 새 위치가 대응 중 또는 재검사 대기 건에 추가되면 그 위치의 조치가 필요함을 상단에 알리고 건을 해결 가능 상태로 두지 않는다. 해결된 건 뒤의 새 노출은 새 대응 건으로 연결하고 과거 건을 보존한다.

노출 판정 자체가 보안 담당자의 근거 있는 검토 기록이며, 같은 판단을 대응 건에서 다시 승인하는 단계는 요구하지 않는다. 추가 검토는 새로운 증거, 부족 근거의 조사, 위험 수용, 해결 또는 정책이 명시한 예외를 대상으로 한다. 담당자 지정과 외부 시스템에서의 실제 조치는 별도 권한·기록으로 유지한다. 첫 실질 외부 조치 기록에서 `OPEN→IN_PROGRESS`로 전이하며, 상태만 바꾸는 별도 시작 동작은 제공하지 않는다.

## 7. 조사와 대응의 연결

추가 조사를 선택하면 `UNKNOWN`인 위치에 조사 과제를 남긴다. 과제에는 부족 근거 유형, 담당자, 기한, 요청 시각, 최근 활동, 참조와 결과를 기록하고 대기열에서 기한 초과를 찾을 수 있게 한다. 원천 소유자에게 확인을 요청하는 일과 보안 담당자의 최종 노출 판정을 구별한다. 근거가 들어와도 과제를 자동으로 `NORMAL` 또는 `ABNORMAL`로 바꾸지 않으며 보안 담당자가 갱신된 정책·위치·검증 증거를 보고 다시 판단한다. 원천 수집 실패는 범위 복구 작업으로, 유효성 검증 실패는 검증 지원·권한 조사로 안내한다.

조치 담당자에게는 원문 없는 위치 정보, 안전한 원천 링크, 확인된 영향과 미확인 사항, 공급자별 가이드, 담당 권한과 근거 참조를 제공한다. 조치의 실제 실행은 외부 시스템에서 이루어졌음을 화면에 표시한다. 가이드나 체크리스트를 읽거나 완료한 사실은 키 교체·폐기·위치 제거·재검증 성공의 증거가 아니다. [대응 정책](response-policy.md)의 같은 키·출처 필수 대응 위치에 대해 조치와 **각 조치 이후 같은 승인 범위에서 비교 가능한 재검사**를 확인하기 전에는 해결로 표현하지 않는다. 현재 미판정 exposure UNKNOWN과 검사 결과 presence UNKNOWN은 별개로 검사하며, 정상 보관 위치와 최신 비교 가능한 MISSING인 과거 미판정 위치에 삭제·현재 판정을 강제하지 않는다. 재검증 범위가 GitHub 현재 파일이면 Git 이력·다른 원천은 미확인이라고 명시한다.

## 8. 권한, 탐색과 실패 표현

분류·판정·조치 요청은 연결 범위의 `SECURITY` 권한을 서버에서 검사한다. 범위 관리자라는 이유만으로 비밀 발견 위치의 판정 권한이 생기지 않는다. 지정된 조치 담당자는 자신에게 허용된 위치의 안전한 근거를 읽고 외부 조치·재검증을 요청할 수 있어야 하며, 다른 연결의 제한 위치는 가린다. 원천 링크를 열 때도 해당 사용자의 원천 접근 권한을 확인한다. 키 원문, 마스킹되지 않은 문맥, HMAC 지문, 공급자 오류 본문, 외부 AI 입력은 이 흐름에 전달하지 않는다.

후보 목록·상세·대응 건은 서로 독립 주소를 갖는다. 목록 조건·페이지는 돌아왔을 때 복원한다. 상세를 여는 동안 범위·근거를 아직 받지 못했으면 로딩을 보여주고 빈 값을 읽지 않는다. 키와 위치가 일치하지 않는 링크, 삭제된 항목, 권한 없음, 로그인 만료, 비활성 범위, 오래된 판정 버전, 부분 실패는 각각 이유와 돌아갈 경로를 보여주며 흰 화면으로 끝나지 않는다. 해당 항목이 더 이상 없으면 후보 목록으로 돌아갈 수 있게 한다.

## 9. 수용 시나리오

1. 같은 완전 키가 두 GitHub 파일에서 발견되면 고유 키는 하나, 위치는 둘이다. 각각 근거를 판정하고 `ABNORMAL` 두 위치는 같은 출처의 현재 대응 건 하나에 연결된다. 한 위치만 사라져도 건은 해결되지 않는다.
2. 합성 `TEST` 범위의 노출은 시험 건에만 들어간다. 동일 키가 운영 범위에서도 발견되면 운영 위치를 `TEST`로 추정하거나 시험 건에 붙이지 않는다.
3. 보관 정책이 확인되지 않고 검증이 `UNKNOWN`이어도 담당자·기한·필요 근거가 있는 조사 과제로 남는다. `NORMAL`, LOW 또는 신규 사고로 보이지 않는다.
4. IAM `METADATA_ONLY`와 승인된 비밀 저장소의 값 존재는 그 사실만으로 노출 판정 대기열·운영 사고에 들어가지 않는다. 다른 비승인 위치에서 실제 값을 찾으면 그 위치만 별도로 평가한다.
5. 일부 범위가 실패한 실행은 성공 0건이나 `MISSING`으로 보이지 않는다. 기존 대응 건은 유지되고 누락된 범위와 마지막 성공 시각을 확인할 수 있다.
6. 같은 조치 요청을 재전송하거나 다른 담당자가 오래된 화면에서 저장하면 중복 건·중복 위치가 생기지 않는다. 최신 근거·버전과 충돌 안내가 돌아온다.
7. 기존 건에 새 비정상 위치가 붙거나 해결 후 재노출되면 과거 위치별 조치·재검증 이력이 유지되고 새 미완료 위치가 해결 가능 상태를 막는다.
8. 오탐과 승인된 보관은 다른 결과·근거·재검토 조건으로 기록된다. 오래된 정책의 `NORMAL`은 변경된 정책을 확인하기 전까지 현재의 영구 안전 판정으로 보이지 않는다.
9. `/secrets/triage/12?occurrence=12` 같은 직접 링크에서 위치·범위 자료가 늦거나 403·404로 끝나도 흰 화면이 되지 않는다. 로딩, 제한 또는 찾을 수 없음과 판정 목록 복귀를 구분한다.
10. 같은 객체 버전·위치·후보·엔진/룰 버전의 Finding이 6시간 뒤 다시 나오면 기한 안의 오탐 근거를 연결해 반복 검토를 줄인다. 파일 버전이나 후보가 바뀌면 다시 검토한다.
11. `TEST`에서 완전한 현재 값 후보의 합성 근거가 없으면 운영 보안 담당자가 실키 의심 경고를 보고 조사 담당·기한을 확인한다. 불완전 후보·메타데이터·오탐은 경고에서 빠지고, 같은 키의 재검사에서 중복 경고가 생기지 않는다.
12. 동일 위치의 변경 없는 허용 정책·정상 판정·오탐 근거를 다시 수집해도 같은 판정 양식이나 열린 조사 과제를 중복 생성하지 않는다. 실제 판정 근거가 바뀌면 변경 항목과 재확인 이유를 보여준다.
13. 운영 보기에서 시험 건을 제외해도 시험 출처의 실키 의심 경고와 출처 미확인 범위는 별도 단위로 남는다. 권한 밖 위치의 수는 이 필터 조합으로도 노출되지 않는다.
