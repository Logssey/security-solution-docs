# 사용자 문구와 상태 표시

개정일: 2026-11-07. 사용자 화면의 용어·안내·상태 표현을 정의한다. 내부 enum과 감사 기록은 표시 문구와 구분한다.

## 1. 읽는 순서와 정보량

- 상태: 배지 한 개는 한 사실만 전달한다. 유효성·노출·진행·커버리지를 같은 배지에 섞지 않는다.
- 이유: 현재 행동을 정하는 한 줄을 먼저 쓴다. 예: `최근 검사 실패로 현재 존재를 확인하지 못했어요.`
- 행동: `근거 확인`, `담당자 지정`, `조치 기록`, `재검사`, `범위 확인`처럼 목적을 쓴다.
- 도움말: 판정 규칙·보호 정책·지원 한계는 펼침 영역 또는 도움말에 둔다. 결정 직전의 중요한 차단 이유·확인 한계는 숨기지 않는다.
- 한 화면의 주 행동은 하나다. 부가 기능은 보조 버튼으로 둔다. 필수 작업이 불가능하면 막힌 이유·필요한 역할·담당자 요청 또는 대기 내역을 표시한다. 읽을 수 있는 대상의 다음 행동을 설명 없이 숨기지 않는다.

제목 24자, 배지 12자, 주요 버튼 12자, 안내 한 줄 60자를 작성 가이드로 삼는다. 안전·정확성에 필요한 설명을 억지로 잘라 뜻을 바꾸지 않는다. 긴 경로는 안전한 별칭과 위치 ID로 표시하고, 전체 내용을 보이는 hover만 유일한 접근 수단으로 사용하지 않는다.

## 2. 표준 용어

| 내부 개념 | 사용자 표시 | 주의 |
|---|---|---|
| CredentialSet / key set | 키 | 불완전한 구성은 `키 후보`, METADATA_ONLY는 `접근키 정보` |
| Occurrence / L4 | 발견 위치 / `4행` | L4는 4단계가 아님. 줄 번호 근거가 없는 경우 줄을 만들지 않음 |
| Finding | 탐지 근거 | 필요할 때 룰·엔진·버전·근거 ID 상세 제공 |
| ACTION_REQUIRED | 조치 필요 | 확인된 노출의 대응 사실. 유효성만으로 결정하지 않음 |
| NEEDS_DECISION | 확인 필요 | 부족한 이유를 병기. 이미 조치 중인 건과 별도 축 |
| UNCLASSIFIED 범위 대기열 | 보관 정책 보완 / 변경 검토 대기 | 호환 식별자. 실제 설정 사유만 표시하며 미분류 값 자체를 필수 업무로 만들지 않음. 발견 위치의 확인 필요와 다른 단위 |
| MANAGED_LOCATIONS | 보관·폐기 확인 | ALL의 actual origin별 적격 인벤토리 유형이 서로 다름. 전체 안전·폐기 완료 보증 아님 |
| NORMAL_INVENTORY | 인벤토리 | 메타데이터까지 정상 보관으로 단정하지 않음 |
| ABNORMAL / NORMAL | 노출 확인 / 보관 허용 | 보관 허용에는 정책·버전·유효 기간 근거 필요 |
| UNKNOWN 노출 | 노출 미확인 | 안전·오탐·위험 낮음으로 해석하지 않음 |
| PRESENT / MISSING / UNKNOWN | 발견됨 / 재검사에서 미발견 / 현재 확인 불가 | MISSING은 비교 가능한 성공 수집·탐지가 있는 위치에만 사용 |
| VALID | 인증 유효 | 검사 시각 병기. 권한·업무 사용·악용 증명과 구별 |
| INVALID | 인증 거부 | 사유 상세 제공. 자동 `폐기됨` 표시는 금지 |
| UNKNOWN 유효성 | 확인 불가 | 승인된 시도 후 통신 오류·호출 제한·재취득 실패 등 결론을 내리지 못한 이유 |
| UNCHECKED | 미검증 | 미시도·미지원·비활성·합성 생략·구성 부족의 실제 사유를 구분. UNKNOWN과 구별 |
| CONFIRMED / CANDIDATE / METADATA_ONLY | 키 구성 확인 / 구성 확인 필요 / 메타데이터 | 구성 확인이 공급자 인증 성공을 뜻하지 않음 |
| OPEN / IN_PROGRESS / REVALIDATION_PENDING / RESOLVED | 신규 / 조치 중 / 재검사 대기 / 해결 | API enum은 변경하지 않음. OPEN 상세 다음 행동은 `담당자 지정` 등 구체화 |
| REVALIDATE / revalidation | 재검사 | `키 유효성 재검증`과 `노출 위치 재검사`를 필요 시 구별 |
| PRODUCTION / TEST / UNCLASSIFIED | 내부 감사 분류 | 일반 화면의 선택·배지·내보내기 표시에서 제외. 기본 읽기는 ALL |
| PROD / DEV / UNKNOWN 환경 | 운영 환경 / 개발 환경 / 환경 미확인 | 공통 환경 선택과 일치 |
| finishedScopeCount | 종료 범위 | 성공 범위가 아님. 주 화면은 성공/부분 실패/실패/미실행 분리 |
| FULL / LIMITED / SIMULATION | 승인 범위 확인 / 제한 확인 / 외부 변경 미수행 | 실제 확인 범위·외부 수행 근거를 상세에서 제공 |

백엔드 raw failureCode는 기본 화면에 펼쳐 두지 않고 사용자 사유로 매핑한다. 지원 문의용 `오류 정보` 펼침 영역에서 안전한 코드·실행 ID만 제공한다. 원문 응답·스택·보호 참조·자격 증명은 표시하지 않는다.

유효성의 기본 문구는 [검증·심각도 화면](validation-and-risk-experience.md)을 따른다. `검증 미지원`, `검증 꺼짐`, `검증 생략`, `구성 부족`을 모두 `기록 없음`으로 합치지 않는다. 공급자 확인을 수행하지 않은 시각은 `—`와 구체 사유를 표시한다. 마지막 인증 성공·최근 시도·실제 공급자 확인 시각은 다른 항목이다. 심각도 적용 대상 아님·미평가·이전 등급 유지도 구분한다.

## 3. 주요 안내 문구

| 상황 | 기본 표시 | 도움말·상세 |
|---|---|---|
| 노출 근거 부족 | `노출 여부를 확인해 주세요` | 탐지 근거와 보관 정책의 구별 |
| 수집·탐지 종료, 키 검증 미완료 | `수집·탐지 완료`와 `키 검증 미완료 2개` | 미실행·미지원 이유와 실제 집계 |
| 범위 일부 실패 | `성공 6 · 부분 실패 1 · 실패 1` | 대기·진행·건너뜀의 수와 대상 |
| 비정상 노출 결정 | `노출 확인 및 조치 요청` | 대상 위치·근거·연결할 현재 건 |
| 담당자 없음 | `담당자 지정 필요` | 적격 담당자·지정 권한 |
| 연결 인증 성공 | `인증 확인` | 검사 방법·시각과 범위별 실제 읽기 결과 |
| 지표 미제공 | `현황을 제공하지 않아요` | 안전한 미제공 사유와 가능한 행동 |
| 보관 정책 변경 | `정책 저장` 또는 `정책 검토 요청` | 현재 원본 분류와 정책 승인 방식을 서버에서 확인 |
| 독립 검토가 필요한 변경 | `검토 요청` | 변경 전후·필요한 검토 이유와 적격 담당자 |
| 제안자 본인의 대기 화면 | `다른 보안 담당자의 검토 대기` | 요청 시각·담당 또는 `승인 담당자 미지정`, 허용된 지정 경로 |
| 정책 변경 완료 | `정책 저장됨` 또는 `정책 검토 대기` | 실제 적용·잔여 사유·적격 검토 담당을 제공 |
| 현재 사용자에게 실행 권한 없음 | `담당자 확인` 또는 허용된 `담당자에게 요청` | 필요한 역할·대상 범위와 요청 상태. 권한을 자동 부여하지 않음 |
| 조치 이후 다시 발견 | `조치 후 다시 발견` | 해당 위치·조치 시각·비교 가능한 검사 결과와 재조치 경로 |
| 발견 위치 요약 | `현재 발견 1곳 · 미발견 1곳 · 확인 불가 1곳` | 같은 출처·권한·대상 집합과 기준시각. 메타데이터를 값 발견 위치에 합치지 않음 |

## 4. 자료 표시와 자격증명 확인

일반 화면은 현재 열람할 수 있는 자료를 기본 전체 조회한다. 운영·시험 전환, 시험 배지, 시험 출처 복귀 버튼을 제공하지 않는다. 발견 플랫폼·자원 환경·위치와 실제 검증·보관·대응 사실을 표시한다. 저장된 자료 분류와 합성 판정은 내부 감사·안전성 근거다.

기존 교차 환경 경고는 사용자에게 `자격증명 여부 확인` 업무로 표현한다. SUSPECTED_REAL은 실제 자격증명 여부 확인 필요, CONFIRMED_REAL은 실제 자격증명 확인으로 표시하고 인증 성공·악용 사실과 구분한다. 해당 경고의 확인·종결은 기존 실제 근거를 사용한다.

합성 근거에 따른 외부 검증 제외는 `분석 전용 표본 · 외부 인증 확인 제외`로 설명한다. 과거 SOURCE_GUARD_BLOCKED는 `당시 적용된 원천 보호 설정으로 인증 확인을 생략했어요`로 표시한다. 현재 VALIDATOR_NOT_ALLOWED는 `이 연결에서 해당 키 발급 서비스의 검증을 허용하세요`로 안내한다. 공급자 호출을 하지 않은 결과를 인증 성공으로 표현하지 않는다. 화면의 명령·응답·처리량은 실제 실행 관측을 사용한다.

제품 화면의 데모·준비 중·fixture·구현 버전 같은 장식 문구는 제거한다. 설계 예시를 제공할 때는 문서 본문에서 예시의 의미를 설명한다.

## 5. 오류·빈 값·최신성

| 상황 | 표시와 행동 |
|---|---|
| 성공한 범위의 실제 0건 | `조건에 맞는 기록이 없어요` + 필터 초기화 또는 범위 보기 |
| 미지원·집계 없음 | 숫자 `—` + `이 버전에서 미지원`. 0으로 대체하지 않음 |
| 로딩 | 골격 또는 `불러오는 중`. 이전 데이터면 이전 기준시각과 갱신 중 표시 |
| 조회 실패 | `불러오지 못했어요` + 다시 조회. 과거 결과와 최신 실패를 혼합하지 않음 |
| 403 / 404 | `접근할 수 없어요` 또는 `항목을 찾을 수 없어요` + 허용 목록으로 복귀. 숨겨진 존재·개수 노출 금지 |
| 충돌·낡은 근거 | `정보가 변경됐어요` + 최신 근거 다시 확인. 입력은 보존하되 재확인 없이 재제출하지 않음 |
| 집계 스냅샷 만료 | `기준시각이 만료됐어요` + 현황 새로고침. 최신 수치로 조용히 대체하지 않음 |
| 조치 후 옛 VALID | `조치 이후 미검증` + 이전 결과 시각. 옛 유효성을 현재 상태로 읽히게 하지 않음 |

시각은 화면에 KST와 기준시각을 표시하고 내부 API는 UTC ISO-8601을 사용한다. 상태는 색상과 함께 텍스트·아이콘을 제공한다. 도움말은 키보드로 열고 닫을 수 있어야 하며 필수 차단 이유를 hover에만 두지 않는다. 스크린리더는 `확인 필요, 발견 위치 3곳`처럼 단위와 상태를 읽는다.

검사 대상은 저장소·브랜치·디렉터리 또는 AWS 서비스·리소스로 설명한다. 일반 분류 버튼은 `분류 저장`, 실제 조치 담당 배정은 `실제 조치 담당자 지정`으로 표시한다. 연결 설정의 활성 상태는 인증 성공과 구분하고 최근 연결 테스트 결과·시각을 따로 보여준다.

## 6. 판단과 조사 용어

| 내부 개념 | 화면 이름·표현 | 경계 |
|---|---|---|
| severity | 시크릿 노출 심각도 | 현재 인증·업무 우선순위와 별도 |
| exposure | 보관·공유 적정성 | 정책이 없으면 `보관 기준 설정 필요`. 수집 승인과 다름 |
| exposureRange | 접근 가능 범위 | `넓은 접근 / 제한된 접근 / 접근 범위 미확인`. 로그인 필요 여부는 별도 |
| credential | 키 구성 확인 | 실제 발급·인증 성공으로 표현하지 않음 |
| impact | 권한과 자원 영향 | 관리자 / 중요 자원 / 일반 자원 / 제한된 시험 자원 / 영향 미확인 |
| abuse | 중대한 사고 근거 | `확인된 사고 근거 없음`과 미조사·커버리지 한계 병기. `악용 없음` 금지 |
| validity | 현재 인증 상태 | 인증 거부 원인 미상이면 만료·폐기로 단정하지 않음 |
| workPriority | 처리 우선순위 | 즉시 대응 / 우선 확인 / 일반 처리 / 계획 처리 / 관리 기록 |
| 자동 권한 관측 | 권한 후보 | 담당자 확정 전 전체 실효 권한·영향이 확인됐다고 표시하지 않음 |
| NOT_OBSERVED_IN_SCOPE | 조회 범위에서 사용 기록 없음 | 기간·계정·리전·이벤트 종류 병기. 미사용·안전으로 줄이지 않음 |
| UNAVAILABLE 사용 조회 | 사용 이력 확인 불가 | 미지원·권한 부족·정확한 키 연결 불가를 구분 |
| PRINCIPAL_ONLY | 주체 수준 기록 | 해당 키의 사용 기록으로 확정하지 않음 |
| AI risk-briefing | AI 조사 요약 | 버튼 `AI로 조사 순서 정리`. AI 점수·AI 판정 표현 금지 |
| DEFAULT / AI | 기본 설명 / AI가 정리한 조사 순서 | 실패·캐시·오래된 결과를 각각 표시 |

`확정`은 사실의 수용·연결·최신성 범위에서만 쓴다. 현재 미확인과 과거 확정을 함께 표시할 수 있으며 과거 정보를 현재 근거처럼 강조하지 않는다. 근거 조회 실패는 빈 목록·0건으로 바꾸지 않고 다시 읽을 행동을 제공한다.
