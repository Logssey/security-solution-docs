# 사용자 작업과 승인 기준

이 문서는 담당자가 문제를 이해하고 실제 조치와 재확인까지 이어 가는 공통 계약이다. 목록에 표시되는 이유, 다음 행동, 완료 조건과 승인 방식을 정의한다. 위치의 판정 근거는 [판정 정책](triage-policy.md), 실제 해결 조건은 [대응 정책](response-policy.md)을 따른다.

## 1. 업무를 설명하는 기본 단위

모든 업무 행과 상세 상단은 **왜 여기 있는가 → 확인된 사실과 시각 → 지금 할 행동 → 처리 후 결과 → 남은 일** 순서로 읽힌다. 하나의 주요 행동과 필요한 보조 행동을 제공한다. 시스템이 사실에서 계산할 수 있는 중복 묶기·검사 실패·재발견·정책 적용·현재 업무 분류를 담당자가 다시 입력하게 하지 않는다.

| 업무 | 대상·진입 이유 | 수행할 행동 | 해당 업무의 완료 조건·다음 화면 |
|---|---|---|---|
| 출처 분류 | Scope. 운영·시험이 미분류이거나 분류 근거가 낡음 | 연결 관리의 범위 상세에서 근거와 출처를 저장하거나 승인 요청 | 유효한 분류 결정이 적용됨. 범위 상세에서 적용 결과를 보고 키·위치로 이동. 보관 허용·노출·해결을 자동 확정하지 않음 |
| 보관 정책 보완 | Scope·정책. 정책이 없거나 만료·불일치 | 정책 담당자에게 요청하거나 해당 범위에 맞는 정책 작성·검토 | 현재 범위에 유효한 정책이 적용됨. 위치별 허용·금지·미확인 결과와 남은 판정 표시 |
| 위치 확인 | Occurrence. 구성·소유자·보관·노출 근거 부족 또는 상충 | 부족한 사실에 맞는 조사·판정. 동일한 유효 자동 허용·오탐 근거의 재입력 생략 | 현재 근거에 따른 분류와 후속 작업 반영. 노출 확인이면 현재 대응 건, 조사 요청이면 같은 조사 상세로 이동 |
| 외부 조치 | ResponseCase·위치. 확인된 노출과 미완료 조치 | 담당자 지정, 사용처·서비스 영향 확인, 외부 교체·폐기·위치 제거 기록 | 실질 조치와 대상 위치가 기록됨. 다음은 위치별 재검사이며 아직 해결이 아님 |
| 재확인 | 위치·실행. 조치 후 비교 가능한 근거 부족 | 대상과 승인 범위를 확인하고 재검사, 키 수명주기 근거 확인 | 위치와 키의 결과를 각각 표시. 남은 위치·실패가 있으면 후속 행동, 모두 준비되면 해결 근거 확인 |
| 검사 복구 | Scope·실행. 실패·부분 실패·지연·미지원 | 실패 사유에 맞는 연결·권한·설정 확인과 승인 범위 재실행 | 같은 현재 범위의 필수 단계 성공 근거 확보. 실제 노출·위치 제거·키 폐기를 대신하지 않음 |

`UNCLASSIFIED` 범위 대기열의 사용자명은 **범위 설정**이다. 출처 미분류, 정책 미설정, 변경 검토 대기를 원인별로 표시하고 연결 관리로 보낸다. `확인 필요`는 키 발견 위치의 판단 업무다. 두 목록 사이에 수동 이동 버튼을 만들거나 하나의 진행 단계로 표시하지 않는다.

범위 설정 사유는 독립 집합이다. 예를 들어 출처를 운영으로 저장하고 정책을 지정하지 않았다면 `출처 미분류` 사유만 해소되고 `보관 정책 미설정`은 남는다. 저장 결과에 **출처 저장됨 · 보관 정책 보완 필요**를 표시한다. 그 범위의 발견 위치는 동시에 확인 필요에 나타날 수 있다. 범위 수와 위치 수를 합치거나 중복 오류로 설명하지 않는다.

## 2. 근거로 정하는 업무 순서

대응·판단·검사·설정 목록은 서로 다른 단위로 유지한다. 각 목록 안에서는 현재 조치해야 할 이유를 먼저 표시하며 같은 권한·스냅샷에서 안정적으로 정렬한다.

- 대응: 조치 후 재발견, 현재 발견된 확인 노출, 담당 미지정·기한 초과, 재검사·해결 확인 순으로 필요한 행동을 설명한다. 확인된 심각도·기한은 보조 근거로 사용한다.
- 위치 확인: 현재 값과 유효한 금지 규칙의 일치, 실제 키 근거, 미완료 조사·정책 변경, 구성·소유자 부족을 이유별로 표시한다. `VALID`와 금지 규칙 일치도 사람의 노출 확인을 대체하지 않는다.
- 검사·설정: 알려진 미해결 노출의 재확인을 막는 실패와 승인 검토를 우선 안내하고, 최근 시도·마지막 성공·대기 시각을 보여준다.

이 순서는 **업무 추천**이며 심각도 산정이 아니다. 미검증·미평가를 낮은 위험으로 간주하지 않고, 불확실성 자체를 숨기지 않는다. 각 항목은 우선 이유와 근거 시각을 제공한다. 값이 같은 경우 대상 ID로 순서를 고정한다. 공개할 권한이 없는 관련 건의 존재·수·긴급도를 정렬 근거로 노출하지 않는다.

## 3. 영향에 따른 출처·정책 승인

분류 변경은 수집 허가 변경과 분리한다. 범위를 넓혀 읽거나 외부 자격 증명을 변경하는 권한은 이 절차에서 부여하지 않는다. 변경 미리보기에서 서버가 현재 권한·분류·정책·관련 근거를 확인해 `DIRECT` 또는 `INDEPENDENT_REVIEW`와 이유를 정한다. 아래 승인 규칙의 버전은 `scope-change-v1`이며 결정 당시 버전을 보존한다.

| 변경 | 처리 방식 | 조건 |
|---|---|---|
| 안전한 별칭·담당·조사 자료 보완, 실질 조치 기록·승인 범위 재검사 | 해당 명령의 기존 권한으로 직접 수행 | 판정·허용 정책·해결 결과를 바꾸는 승인을 겸하지 않음 |
| 미분류→운영, 시험→운영의 출처 지정 | `SECURITY`는 `DIRECT` | 정책 연결·수집 범위 유지, 혼합 범위 아님, 알려진 합성 시험 범위 아님. 과거 건을 이동·종료하거나 기존 노출을 낮추지 않음 |
| 운영 출처 근거의 갱신 | `SECURITY`는 `DIRECT` | 출처·정책·범위·기존 대응 처리 유지. 의미 없는 동일 요청은 새 업무·결정을 만들지 않음 |
| 시험 최초 분류·운영→시험 변경 | `INDEPENDENT_REVIEW` | 제안자와 다른 해당 범위 `SECURITY`가 영향 확인. 시험 분류만으로 합성·안전·해결을 주장하지 않음 |
| 보관 정책의 활성화·연결·교체·해제 | `INDEPENDENT_REVIEW` | 다른 `SECURITY`가 범위·유효 기간·기존 판정 영향을 확인. 정책 미설정으로 저장하는 것은 보관 허용이 아님 |
| `OPERATIONS`만 있는 사용자의 출처 변경 제안 | `INDEPENDENT_REVIEW` | 제안 권한이 최종 보안 결정 권한을 뜻하지 않음. 적격 `SECURITY`에게 전달 |
| 위험 수용·외부 수동 수명주기 증거 검토 | 각 기능의 보안 승인 조건 적용 | 단순 출처 보완의 직접 저장 규칙으로 예외·해결의 근거를 우회하지 않음 |

두 조건 이상이 적용되면 더 강한 검토 요건을 따른다. 출처와 정책을 한 번에 입력해도 각 변경의 영향을 계산한다. 미분류→운영과 정책 미설정 유지 조합은 직접 저장할 수 있지만, 운영으로 분류하며 허용 정책을 새로 연결하면 독립 검토가 필요하다. 허용된 무변경·동일 본문 재시도는 기존 결과를 반환한다. 현재 유효한 분류 결정·근거까지 같을 때만 무변경이며, 운영 표식만 있고 정식 결정이 없는 과거 범위는 직접 근거를 기록해 재확인 사유를 해소할 수 있다.

현재 검토자가 없는 경우 **승인 담당자 미지정**과 필요한 역할·요청 시각을 표시하고 적격 담당자 지정 경로를 제공한다. 제안자는 요청·근거를 보존한 채 조회·조사·긴급 조치 안내를 계속 사용할 수 있다. 단독 운영을 이유로 검토 필수 변경을 자동 승인하거나 ADMIN에게 보안 역할을 암묵 부여하지 않는다. 직접 저장 가능한 작업까지 다른 계정의 승인을 요구하지 않는다.

검토가 필요한 제안에는 요청자, 허용된 검토 담당자, 대기 시각, 변경 전후, 영향, 근거와 반려 사유를 보여준다. 제안자의 승인 버튼 대신 **다른 보안 담당자의 검토 대기**를 표시한다. 반려 후 이전 분류를 유지하고 근거를 보완해 새 버전으로 요청한다. 검토 완료 전 제안 값을 활성 분류로 쓰지 않는다.

출처 변경은 과거 대응 건·판정·실키 경고를 자동 이동·폐기하지 않는다. 시험으로 바뀌어도 합성 미확인·실키 경고는 운영 보안 담당자에게 보이며 미연결·재평가 작업을 유지한다. 영향·기존 건 처리가 남았으면 **출처 적용됨 · 기존 대응 연결 확인 필요**로 표시한다.

## 4. 막힌 행동과 담당자 요청

필수 행동을 버튼 없이 없애지 않는다. 읽을 수 있는 대상에서는 `다음 행동`, `실행 가능 여부`, `막힌 이유`, `해결할 담당 역할`, `허용된 담당자·과제 링크`를 함께 표시한다. 쓰기 권한 없는 사용자가 볼 수 없는 대상의 존재는 이 안내에서도 노출하지 않는다.

| 이유 | 사용자에게 제공할 경로 |
|---|---|
| 권한 부족 | 필요한 역할·해당 범위 안내와 권한 있는 담당자 확인. 허용되면 내부 업무 요청 등록 |
| 담당자 미지정 | 적격 담당자 지정. 지정 권한이 없으면 기존 요청 또는 내부 담당 요청으로 이동 |
| 독립 검토 대기 | 요청 내용·대기 시각·담당과 근거 보기. 자기 승인 제공 금지 |
| 근거 부족 | 부족한 항목과 제출 위치를 입력 옆에 표시. 키 원문·자유 메모를 요구하지 않음 |
| 이미 실행 중 | 같은 실행 링크와 현재 상태. 새 요청 중복 등록 방지 |
| 오래된 버전·조회 기준 | 입력을 보존하고 변경된 근거를 다시 읽기. 목록은 새 기준으로 갱신 |
| 지원하지 않는 검사 | 지원 한계와 담당자 조사 경로. 성공·안전으로 대체 금지 |

내부 업무 요청은 기존 `InvestigationTask`의 `HUMAN_HANDOFF`로 저장하고 대상·요청 종류별 열린 요청을 재사용한다. 요청자는 열람·요청이 허용된 대상만 지정할 수 있고 수신자에게 대상 밖 권한을 부여하지 않는다. 적격 담당자가 없으면 배정 대기로 보존하며 별도 전송 기능 없이 제품 안에서 조회한다. 완료에는 실제 분류 결정·정책 적용·연결 복구 등 요청 종류에 맞는 결과 근거가 필요하다. 버튼 클릭·요청 접수만으로 문제를 해결했다고 표시하지 않는다.

## 5. 저장 결과와 화면 복귀

저장 전에는 대상·필요 근거·직접 적용 또는 검토 요청·예상 후속 작업을 짧게 보여준다. 버튼은 **출처 저장 / 검토 요청 / 담당자 지정 / 조치 기록 / 재검사 요청 / 해결 근거 확인**처럼 실제 효과를 표현한다. 조치 기록 마침과 작업 등록이 별도 명령이면 각 성공·실패를 구분하고 이미 저장한 조치를 재입력하지 않게 한다.

성공 응답은 적용 결과와 남은 이유를 제공한다. 직접 분류는 범위 상세, 검토 요청은 같은 제안, 노출 결정은 현재 대응 건, 조사 요청은 기존 또는 새 조사 과제, 재검사 요청은 해당 실행·위치 결과로 연결한다. 원래 목록 조건·선택 위치를 보존한다. 상세를 목록 밑에 붙이거나 성공할 때마다 긴 이력을 현재 작업 영역에 누적하지 않는다.

목록·현황의 같은 스냅샷을 조용히 수정하지 않는다. 변경 후 **새 기준으로 목록 확인**을 제공하고 이동 시 새 스냅샷을 생성한다. `출처 저장됨`과 `범위 설정 업무 완료`는 구분한다. 목록에 남으면 남은 이유와 주 행동이 갱신돼야 한다. 과거 사실·해결 이력은 기록 영역에서 조회한다.

## 6. 보안 효과를 확인하는 사용자 여정

키 하나의 값 발견부터 시작해 안전한 위치 정보로 문제를 이해하고, 같은 키의 여러 위치를 비교하고, 담당자에게 필요한 외부 조치를 전달하고, 조치 후 재검사와 키 수명주기 근거를 확인할 수 있어야 한다. 자동 확인된 사실을 사람이 다시 승인하는 횟수를 늘리지 않는다.

키 상세와 대응 상세는 **필수 대응 위치 중 현재 발견 / 조치 후 미발견 / 현재 확인 불가**, 조치 후 재발견 여부, 키 사용 종료의 확인 수준과 마지막 검사 시각을 함께 보여준다. 승인 보관 위치까지 제거 목표에 합치지 않는다. 확인되지 않은 범위를 제외하거나 기한 없는 위험 수용으로 남은 위험이 줄었다고 표현하지 않는다.

표시 수는 같은 기준시각·출처·권한·대상 집합에서만 비교한다. 단순 탐지 수 감소, 필터 변경, 시험 재분류, 검사 실패, 오탐 교정·예외 승인만으로 위험 감소율을 만들지 않는다. 해결 상세에는 확인된 조치·비교 범위·남은 한계가 남아야 한다.
