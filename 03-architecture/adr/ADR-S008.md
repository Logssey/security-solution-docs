# ADR-S008 — 기존 대시보드 연동과 데이터 확장

- 상태: **Accepted — 논리 데이터와 대시보드 경계**, 물리 배치와 API 필드는 Proposed
- 결정일: 2026-10-09
- 기준: [PRD v0.3](../../01-requirements/PRD.md), FR-04부터 FR-15, NFR-03, NFR-05, SEC-02, SEC-05

## 이슈

탐지 결과, 검증 이력, 영향 평가, 담당자와 조치 기록은 갱신 주기와 접근 권한이 다르다. 대시보드에는 같은 기준시점의 집계와 상세 근거를 제공하면서 비밀 원문과 내부 실행 데이터를 차단해야 한다.

## 결정

대시보드 API가 화면의 유일한 조회 및 변경 경계가 된다. API에서 인증, 권한 검사, 서버 측 마스킹과 입력 검증을 적용한다. 화면에는 발견 위치, 발급자, 유효성, 심각도, 최신성, 담당자와 조치 근거를 제공하며 원문을 반환하지 않는다. 구체적인 URL, 응답 필드와 물리 테이블은 API 및 데이터 설계에서 정한다.

Connection/ScanRun, CredentialSet/Occurrence, ValidationAttempt, Assessment, ResponseCase/AssignmentHistory를 논리적으로 구분한다. 한 key set의 여러 발견 위치, 검사 시도와 대응 이력을 보존한다. Notion 연결, 재검증 대기, 심각도 미평가, 환경 미확인과 개인 담당자 표시를 데이터 계약에 포함한다.

## 남은 구현 선택

기존 detection_events 확장과 별도 시크릿 모델을 연결하는 방법을 비교한다. 한 key set에 여러 위치가 있을 때 대응 단위와 대표 상태를 정하되, 어느 방법이든 네 단계와 별도 예외의 배타적 집계를 지켜야 한다. 현재 구현의 PostgreSQL 사용과 운영 저장소 배치는 별개이며 기존 저장소 배치 ADR의 상태를 이 문서가 변경하지 않는다.

## 영향, 검증

기존 대시보드의 인증과 조회 계약을 확인해 전환 계획, enum 마이그레이션, 집계 기준을 설계한다. UI의 수집 시각은 실제 수집 실행 이력에 연결한다. 쓰기 API에는 권한 검사, 입력 검증, 감사 이력과 동시 변경 처리를 포함한다. 카드, 목록, 매트릭스는 같은 필터와 기준시점에서 같은 수를 보여야 한다.
