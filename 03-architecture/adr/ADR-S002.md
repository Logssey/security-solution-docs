# ADR-S002 — 유효성 검증과 6시간 재검사

- 상태: **Accepted — 검증 상태와 6시간 주기**, 재시도 수치는 Proposed
- 결정일: 2026-10-09
- 기준: [PRD v0.3](../../01-requirements/PRD.md), FR-05부터 FR-09, NFR-01, SEC-04, SEC-08

## 이슈

탐지 결과는 현재 사용 가능한 인증 수단인지, 실제 업무에 쓰이는지, 어떤 리소스에 접근 가능한지를 각각 판단해야 한다. 한 API 응답으로 모두 판단할 수 없다.

## 최종 결정

유효성과 지원되는 사용 메타데이터를 기본 6시간마다 다시 확인한다. 만료 또는 폐기가 확인된 신규 발견은 기록을 보존하고 신규 사고로 올리지 않는다. 검증 불가는 사유를 기록하고 수동 검토 대상으로 남긴다. 사용 여부와 영향 범위는 별도 근거로 표시하며 조회 미지원이나 기록 부재를 미사용으로 확정하지 않는다.

## 검증 계약

발급자와 키 유형별 검증기를 사용한다. 각 시도는 결과, 사유, 검사 시각, 방법, 버전과 제한 사항을 기록한다. 미시도는 UNCHECKED, 시도 후 결론 불가는 UNKNOWN이다. 403, 404, 429, 타임아웃 등을 일괄 INVALID로 처리하지 않는다.

AWS STS, GitHub 사용자 및 설치 토큰, Notion 연결 토큰은 서로 다른 검증 계약을 갖는다. 공개 리소스 조회 성공을 인증 성공으로 오해하지 않는다. 검증을 위해 키를 갱신, 재발급, 폐기하거나 외부 데이터를 다운로드하지 않는다. 최근 시도와 마지막 성공을 분리해 기록하며 실패로 과거 성공 시각을 갱신하지 않는다.

## 남은 운영 수치와 영향

- 신규 발견 직후 검사 시점, 전체 재수집 간격, 보존 전용 무효 이력의 재검사 범위는 별도 운영 정책으로 정한다. 유효성의 기본 6시간 주기는 유지한다.
- 공급자별 제한, 백오프, 최대 재시도, 지연 허용치는 실험으로 정한다.
- 원문 미보관 시 재취득 실패가 가능하다. 이를 무효, 해결로 처리하지 않는다.
- 조치 이후 검사 전에는 이전 VALID를 최신 상태처럼 표시하지 않고 재검증 대기를 표시한다.
- 검사 트래픽도 사용 이력, 감사 로그에 영향을 줄 수 있으므로 업무 사용 여부 해석 시 검증 시각을 함께 본다.
