# ADR-S005 — 탐지된 비밀 원문 보관

- 상태: **Proposed — 원문 보관 방식 결정 대기**, 보호 경계는 PRD 기준으로 확정
- 검토일: 2026-10-09
- 기준: [PRD v0.3](../../01-requirements/PRD.md), NFR-08, SEC-01부터 SEC-03

## 이슈

유효성의 기본 6시간 재검사에는 자격 증명의 구성요소가 필요할 수 있다. 원문을 보관하면 재검증 가능성이 높아지지만 솔루션이 새 비밀 저장소가 된다. 보관하지 않으면 원천에서 값이 삭제되거나 읽기 권한이 바뀐 뒤 재검증하지 못할 수 있다. PRD는 보관 여부와 기간을 구현 정책으로 남겨 두고 보호 요건을 먼저 고정한다.

## 선택지

| 선택지 | 장점 | 제약 |
|---|---|---|
| 원문 미보관, 매번 재취득 | 중앙 원문 축적 최소화 | 원천 삭제, 권한 변경 후 검사 불가, 수집 비용 증가 |
| 제한된 기간 암호화 보관 | 대응 기간 내 재검증 가능 | 보관 기간, 키 관리, 접근 감사, 백업 만료 정책 필요 |
| 별도 보호 저장소에 보관 | 지속 검증과 이력 연계 용이 | 침해 영향, 운영 복잡도, 분리된 접근 통제와 삭제 설계 필요 |

세 방식의 보안 부담과 실제 재검증 성공률을 비교해 선택한다. 암호화 알고리즘, 저장 제품과 보관 기간은 이 ADR에서 확정하지 않는다.

## 선택에 관계없이 필요한 조건

화면, API 조회 응답, 일반 DB 필드, 애플리케이션 로그, 오류 응답, AI 입력에는 원문을 포함하지 않는다. 보관하는 경우 암호화, 목적별 접근 제한, 접근 감사, 삭제 기준을 적용한다. 엔진 출력, 임시 파일, 실패 로그, 큐, 백업도 같은 보호 경계에 포함한다. 연결용 비밀과 탐지된 비밀의 권한을 구분한다.

중복 식별에는 별도 보호키 기반 HMAC 등 원문을 되돌릴 수 없는 식별 방법을 평가한다. 마스킹 문자열이나 단순 해시만으로 인증 재검증을 할 수 없다. 동일성 판단 범위와 보호키 교체 시 처리도 설계한다.

## 선택 전 제한과 결정 기준

보관 방식, 삭제 시점, 복구 범위와 접근 주체를 정하기 전에는 실제 비밀 원문을 지속 저장하지 않는다. 원문 재취득 실패는 SOURCE_UNAVAILABLE 등 사유로 남기고 무효 또는 해결로 바꾸지 않는다. 결정에는 원천별 재취득 가능성, 6시간 검사 성공률, 노출 시 피해 범위, 저장 및 백업 비용을 사용한다.
