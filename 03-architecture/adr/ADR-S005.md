# ADR-S005 — 탐지된 비밀 원문 보관

- 상태: **Accepted — 발견한 원문은 영속 보관하지 않음**
- 결정일: 2026-10-09
- 기준: [PRD v0.4](../../01-requirements/PRD.md), NFR-08, SEC-01부터 SEC-03

## 이슈

유효성의 기본 6시간 재검사에는 자격 증명의 구성요소가 필요할 수 있다. 원문을 보관하면 재검증 가능성이 높아지지만 솔루션이 새 비밀 저장소가 된다. 보관하지 않으면 원천에서 값이 삭제되거나 읽기 권한이 바뀐 뒤 재검증하지 못할 수 있다. PRD는 보관 여부와 기간을 구현 정책으로 남겨 두고 보호 요건을 먼저 고정한다.

## 최종 결정

발견한 비밀 원문은 영속 보관하지 않는다. 승인된 원천에서 검증 시점에 다시 읽고 격리된 검증 작업의 메모리에서만 사용한다. 일반 DB, 메시지 큐, 로그, 오류 응답, 임시 파일과 백업에는 원문을 넣지 않는다. 원천 삭제 또는 권한 변경으로 재취득하지 못하면 검사 시도와 `SOURCE_UNAVAILABLE` 사유를 기록하고 UNKNOWN 또는 UNCHECKED로 남긴다. 지난 유효 판정과 성공 시각을 덮어쓰지 않는다.

## 검토한 선택지

| 선택지 | 장점 | 제약 |
|---|---|---|
| 원문 미보관, 매번 재취득 | 중앙 원문 축적 최소화 | 원천 삭제, 권한 변경 후 검사 불가, 수집 비용 증가 |
| 제한된 기간 암호화 보관 | 대응 기간 내 재검증 가능 | 보관 기간, 키 관리, 접근 감사, 백업 만료 정책 필요 |
| 별도 보호 저장소에 보관 | 지속 검증과 이력 연계 용이 | 침해 영향, 운영 복잡도, 분리된 접근 통제와 삭제 설계 필요 |

원문 미보관은 중앙 원문 축적을 줄이는 대신 재취득 실패 가능성을 수용한다. 제한 기간 암호화 보관과 별도 보호 저장소는 재검증 가능성을 높이지만 중앙 저장, 키 관리, 백업과 삭제 부담이 커져 초기 설계에서 채택하지 않는다. 재취득 성공률은 운영 지표로 측정한다.

## 보호 조건

화면, API 조회 응답, 일반 DB 필드, 애플리케이션 로그, 오류 응답, AI 입력에는 원문을 포함하지 않는다. 보관하는 경우 암호화, 목적별 접근 제한, 접근 감사, 삭제 기준을 적용한다. 엔진 출력, 임시 파일, 실패 로그, 큐, 백업도 같은 보호 경계에 포함한다. 연결용 비밀과 탐지된 비밀의 권한을 구분한다.

중복 식별에는 별도 보호키 기반 HMAC 등 원문을 되돌릴 수 없는 식별 방법을 평가한다. 마스킹 문자열이나 단순 해시만으로 인증 재검증을 할 수 없다. 동일성 판단 범위와 보호키 교체 시 처리도 설계한다.

## 영향과 검증

원문 재취득 실패는 무효 또는 해결로 바꾸지 않는다. 원천별 재취득 가능성, 6시간 검사 성공률과 지연을 측정하고 수동 검토 대상을 표시한다. 성공, 오류, 도구 출력과 백업 경로에서 원문 잔류를 검사한다. 원문 보관으로 정책을 바꿔야 한다면 기간, 암호화, 접근 감사와 삭제를 정의한 별도 ADR을 먼저 승인한다. 상세 데이터와 실행 경계는 [데이터 계약](../data-contract.md), [보안 실행 정책](../security-and-runtime.md)을 따른다.
