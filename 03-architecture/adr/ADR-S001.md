# ADR-S001 — 룰 기반 탐지와 키 유형 지원 범위

- 상태: **Proposed — Gitleaks와 TruffleHog 비교 후 단독 또는 병행 운영 결정**
- 제안일: 2026-10-09
- 기준: [PRD v0.4](../../01-requirements/PRD.md), FR-01부터 FR-04, NFR-04

## 이슈

AWS, GitHub, Notion, K8s에 연결된 코드, CI/CD 설정, 문서, 클라우드 자원에는 정형 토큰뿐 아니라 키 쌍, 개인키, 암호, 연결 문자열이 존재할 수 있다. 발견 위치와 발급자가 다를 수 있어 단순 접두사만으로 모든 유형을 판정할 수 없다.

여기서 정적 탐지는 코드의 전체 실행 경로나 취약점을 분석하는 일반 SAST가 아니라 읽은 콘텐츠에서 자격 증명 후보를 찾는 비밀 탐지다. 후보 발견과 실제 유효성, 사용 여부, 영향 평가는 서로 다른 단계다.

## 비교 평가 결정

탐지 엔진의 운영 조합은 아직 확정하지 않는다. **Gitleaks와 TruffleHog를 동일한 평가 자료로 각각 실행**하고 결과에 따라 Gitleaks 단독, TruffleHog 단독 또는 두 도구 병행 운영을 결정한다. 두 도구를 평가한다는 사실은 운영 환경에서 둘을 이미 사용한다는 뜻이 아니다. AI는 탐지에 사용하지 않는다.

비교할 때 수집 어댑터가 승인된 원천 객체, 버전과 위치를 추적하고 동일한 텍스트를 각 도구의 `stdin` 모드로 전달한다. GitHub의 승인된 브랜치와 커밋 이력도 수집기가 파일 버전 또는 변경 내용을 읽어 같은 검사 단위로 전달한다. 수집 실패, API가 반환하지 않은 이력과 크기 제한으로 건너뛴 콘텐츠는 누락 범위로 기록한다. 도구에 수집원 연결 자격 증명을 전달하거나 비교를 위해 Git 저장소를 워커 디스크에 복제하지 않는다. 도구의 원천 직접 스캔 기능은 수집 범위와 위치 추적을 별도로 입증하기 전까지 제품의 수집 계약을 대체하지 않는다.

두 도구의 기본 탐지기를 출발점으로 삼고 부족한 유형의 사용자 정의 룰과 탐지기는 각 도구의 설정으로 버전 관리한다. 도구명, 실행 파일 버전과 해시, 룰 또는 탐지기 ID와 설정 해시, 원천 위치를 실행 및 발견 기록에 남긴다. 키 ID나 공개 인증서처럼 단독 비밀이 아닌 구성요소는 별도로 분류하고, 불완전 key set을 유효한 전체 키로 표시하지 않는다. 룰, 탐지기와 허용 목록 변경은 합성 정상 및 노출 표본의 회귀 시험을 거친다.

평가와 운영에서 두 도구는 **후보 탐지만** 수행한다. TruffleHog의 능동 검증은 `--no-verification`으로 비활성화하고, 제품의 `VALID`, `INVALID`, `UNKNOWN`, `UNCHECKED`는 별도 공급자 검증기만 판정한다. 원문을 포함할 수 있는 입력과 결과는 제한된 워커의 프로세스 파이프와 메모리에서만 처리하고 일반 파일, 보고서, 로그에 쓰지 않는다. 워커는 각 도구의 결과를 원천 위치에 연결해 정규화, 동일성 판정 및 비밀 제거한 뒤 메타데이터만 저장한다. 구조화 결과를 안전하게 변환할 수 없거나 실행이 실패하면 해당 도구의 검사 범위를 실패로 기록한다. 종료 코드만으로 0건 성공을 판정하지 않는다. 별도 공급자 검증기는 [ADR-S002](ADR-S002.md)를 따른다.

## 선택 기준

동일한 합성 표본과 승인된 테스트 자료에서 AWS, GitHub, Notion, K8s 및 CI/CD 설정의 지원 유형별 탐지 누락과 오탐을 측정한다. 두 도구를 함께 쓸 때 추가로 발견하는 항목과 중복 항목을 분리하고, 원천 위치 복원, 처리 시간, 실패와 부분 누락, 원문 출력 보호, 룰 유지 비용, 배포 및 라이선스 조건을 비교한다. 경로 문맥이 필요한 룰과 `stdin`의 위치 정보 손실도 각각 시험한다. 실계정의 비밀 원문이나 탐지 보고서를 비교 자료로 저장하지 않는다.

두 도구를 함께 쓸 때 단독 사용보다 의미 있는 탐지 이점이 있고 보안 및 운영 조건을 충족하면 병행 운영할 수 있다. 두 도구가 같은 키를 찾으면 엔진별 Finding은 보존하되 CredentialSet과 발견 위치를 중복 집계하지 않는다. 필수 유형의 누락을 해결하지 못하거나 승인되지 않은 외부 호출, 원문 잔류를 막지 못하는 조합은 운영 선택에서 제외한다. 평가 결과, 도구별 버전, 설정, 지표와 선택 근거를 이 ADR에 기록한 뒤 상태를 Accepted로 바꾼다. 자체 탐지 엔진을 처음부터 작성하는 방식은 초기 평가 대상에 넣지 않는다.

## 영향, 검증

- 탐지와 유효성 검사를 별도 단계로 분리한다. 탐지 결과 자체를 VALID 또는 INVALID로 변환하지 않는다.
- 유형별 정상, 오탐, 변형, 누락 구성요소 사례로 재현율과 오탐률을 측정한다.
- 평가 전 두 도구의 실행 파일 버전과 해시, 룰 또는 탐지기 설정을 고정한다. CI/CD 설정을 포함한 위치별 지원 여부와 수집 누락을 도구별로 보고한다.
- 동일 키의 여러 위치와 엔진 결과를 연결하되 근거 없이 서로 다른 값들을 한 key set으로 묶지 않는다.
- `stdin`에서 원본 파일 경로를 직접 보지 못하는 룰 또는 탐지기와 Git 이력 API의 크기 제한을 별도 평가한다. 경로 문맥이 필요한 탐지가 누락되면 해당 유형을 지원 완료로 표시하지 않고 수집 및 스캔 방식을 다시 결정한다.
