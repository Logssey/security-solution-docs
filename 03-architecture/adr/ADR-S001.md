# ADR-S001 — 룰 기반 탐지와 키 유형 지원 범위

- 상태: **Accepted — 룰 기반 탐지**, 엔진 조합과 버전은 Proposed
- 결정일: 2026-10-09
- 기준: [PRD v0.3](../../01-requirements/PRD.md), FR-01부터 FR-04, NFR-04

## 이슈

AWS, GitHub, Notion, K8s에 연결된 코드, CI/CD 설정, 문서, 클라우드 자원에는 정형 토큰뿐 아니라 키 쌍, 개인키, 암호, 연결 문자열이 존재할 수 있다. 발견 위치와 발급자가 다를 수 있어 단순 접두사만으로 모든 유형을 판정할 수 없다.

## 최종 결정

AI를 탐지에 사용하지 않는다. 유형별 형식, 접두사, 정규식과 문맥을 조합한 룰 기반 탐지를 사용한다. 발견 위치, 발급자, 키 유형, 구성요소와 엔진 및 룰 버전을 분리해 기록한다. 지원하지 않는 유형, 콘텐츠와 접근 불가 범위를 명시하며 미탐지 0건을 보장하지 않는다.

## 선택지와 제안

Gitleaks 중심, TruffleHog 중심, 두 엔진 결합을 같은 평가셋으로 비교한다. 엔진 구성과 버전은 지원 유형, 정밀도, 재현율, 처리량, 중복과 운영 비용을 확인한 뒤 정한다. 엔진이 내장한 검증 결과는 제품의 유형별 유효성 판정과 근거를 확인한 뒤 연결한다.

## 영향, 검증

- 탐지와 유효성 검사를 별도 단계로 분리한다. 엔진의 verified/unverified를 통일된 상태로 신중하게 변환한다.
- 유형별 정상, 오탐, 변형, 누락 구성요소 사례로 재현율과 오탐률을 측정한다.
- 도구명, 버전, 룰 ID, 룰 버전을 저장하고, CI/CD 설정을 포함한 위치별 지원 여부와 수집 누락을 보고한다.
- 동일 키의 여러 위치와 엔진 결과를 연결하되 근거 없이 서로 다른 값들을 한 key set으로 묶지 않는다.
