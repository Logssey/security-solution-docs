# 데이터 계약과 집계 기준

기준: [PRD](../01-requirements/PRD.md), [ADR-S003](adr/ADR-S003.md), [ADR-S005](adr/ADR-S005.md), [ADR-S008](adr/ADR-S008.md), [대응 정책](../02-functional-design/response-policy.md)

## 1. 기록 단위

| 논리 기록 | 필수 정보 | 관계와 불변 조건 |
|---|---|---|
| Connection | 연결 ID, 플랫폼, 승인 범위, 권한 참조, 자원별 자산 분류 참조와 버전, 활성 상태, 범위 버전 | 플랫폼은 발견 위치의 속성이다. 키 발급자와 혼동하지 않는다. 권한 참조는 비밀 값이 아니다. 분류가 없는 자원의 중요도를 이름에서 추정하지 않는다. |
| ScanRun | 실행 ID, 연결 ID, 요청 및 시작, 종료 시각, 범위, 성공, 부분 실패, 실패 사유, 엔진과 룰 버전 | 실제 0건과 접근 실패를 다른 결과로 기록한다. 재실행도 별도 실행 ID를 갖는다. |
| CredentialSet | 내부 ID, 발급자, 유형, 구성요소 완전성, 보호된 동일성 식별값, 최초 및 최근 발견 시각 | 동일성 식별값은 원문이나 단순 해시가 아니다. 증명되지 않은 후보는 병합하지 않는다. |
| Occurrence | 위치 ID, CredentialSet ID, Connection ID, 원천 객체와 버전, 위치, 환경, 최초 및 최근 발견, 노출 판정 | 한 키의 여러 위치를 보존한다. UNKNOWN 환경을 PROD 또는 DEV로 바꾸지 않는다. |
| Finding | 발견 ID, Occurrence ID, ScanRun ID, 엔진, 룰 ID와 버전, 마스킹된 문맥 | 같은 위치의 두 엔진 결과를 보존하되 위치 수를 중복하지 않는다. |
| ValidationAttempt | 시도 ID, CredentialSet ID, 실행 ID, 검증기와 버전, 요청, 완료, 결과, 사유, 승인된 엔드포인트 분류 | 시도 실패는 과거 성공 시각을 갱신하지 않는다. 원문과 공급자 응답 본문을 일반 필드에 저장하지 않는다. |
| UsageEvidence | 증거 ID, 유형, 관측 주체, 근거 시각, 확인 범위, 출처 | 인증 가능, 사용 기록, 리소스 접근 가능, 침해 사실은 서로 다른 주장이다. 미지원과 기록 부재를 구분한다. |
| Assessment | 평가 ID, CredentialSet ID, 위치 ID, 심각도 또는 미평가, 정책 버전, 규칙 ID, 정규화 입력, 증거 ID와 관측 시각, 누락 사유, 평가 시각, 자동 판정자 또는 수동 승인자 | 위치마다 평가하고 과거 평가는 덮어쓰지 않는다. 수동 변경은 자동 결과와 분리한다. 확인되지 않은 사실로 등급을 낮추지 않는다. |
| ResponseCase | 대응 ID, CredentialSet ID, 생성 원인, 단계, 예외 상태, 담당 팀과 개인, 버전, 생성 및 변경 시각 | 한 CredentialSet의 현재 대응 건은 최대 하나다. 해결 후 재발은 새 ID를 쓴다. |
| ResponseOccurrence | 대응 ID, 위치 ID, 노출 판정, 조치, 재확인, 예외 범위와 증거 | 한 위치의 해결 또는 예외가 다른 위치를 자동 처리하지 않는다. |
| ActionRecord | 작업 ID, 대응 ID, 수행자, 종류, 외부 조치 시각, 기록 시각, 증거 참조 | 절차 안내와 실제 외부 실행 기록을 구별한다. 제품 실행으로 표시하지 않는다. |
| AuditEvent | 감사 ID, 실행 ID 또는 요청 ID, 대상, 변경 전후의 비밀 제거 값, 수행자, 시각 | 변경과 실패를 추적한다. 원문 비밀이나 전체 도구 출력을 담지 않는다. |

실제 테이블 분할과 인덱스는 기존 PostgreSQL 마이그레이션에서 결정한다. 위 필드와 관계는 화면과 API가 지켜야 할 논리 계약이다. 기존 `detection_events`는 일반 탐지 이력으로 유지하고 Secret 전용 기록은 별도 논리 모델로 연결한다. 기존 V1 마이그레이션은 수정하지 않으며 새 버전 마이그레이션으로 확장한다.

## 2. 동일성, 시간과 원문

CredentialSet의 동일성은 발급자, 유형, 구성요소 형식과 보호키 기반 식별값으로 판정한다. 구성요소가 빠졌거나 값을 검증할 수 없으면 같은 접두사, 마스킹 문자열, 위치만으로 병합하지 않는다. 식별키 교체 시 이전 식별값과 새 식별값의 대응은 접근 제한된 전환 작업에서 처리하고 일반 API에 노출하지 않는다.

일반 영속 저장소에는 발견한 원문을 보관하지 않는다. 검사할 때 승인된 원천에서 필요한 값을 다시 읽고 격리된 검증 작업의 메모리에서만 사용한다. 큐에는 원문 대신 내부 ID와 작업 ID를 넣는다. 재취득 실패는 UNKNOWN 또는 UNCHECKED와 `SOURCE_UNAVAILABLE` 사유로 남긴다. 시도 실패로 마지막 성공 판정이나 사용 메타데이터의 성공 시각을 갱신하지 않는다. 원문 정책의 근거는 [ADR-S005](adr/ADR-S005.md)에 둔다.

모든 시각은 UTC로 저장하고 API에서 UTC 시각을 반환한다. `lastAttemptAt`, `lastSuccessfulValidationAt`, `nextDueAt`, `lastCollectionSuccessAt`, `actionPerformedAt`은 각각 다른 사실이다. 조치가 마지막 유효성 판정 뒤에 있으면 `postActionValidationPending`을 표시한다. 예약 기준은 마지막 성공만을 기준으로 밀리지 않도록 직전 예정 시각과 운영 정책을 사용한다.

## 3. 현재 상태와 이력

현재 유효성은 최신 시도의 결과와 사유를 표시한다. 이전 성공 결과가 있을 때는 그 결과와 시각을 별도 필드로 보존한다. 오류 시도를 마지막 성공으로 덮어쓰지 않는다. 현재 심각도는 최신 평가와 정책 버전이며 과거 평가를 삭제하지 않는다. 대응 단계, 검토, 예외는 독립된 상태로 저장한다.

기본 집계는 각 CredentialSet의 최신 ResponseCase 한 건을 모수로 한다. `scope=currentCases`에서 정상 인벤토리와 대응 건이 없는 만료, 폐기 이력은 제외한다. `scope=inventory`는 모든 CredentialSet을 고유 키 단위로 조회하고 정상 보관, 대응 중, 만료, 폐기 등을 구분한다. `scope=history`는 과거 ResponseCase를 별도 건으로 조회한다. 같은 필터와 기준시점에서 조치 네 단계와 전체 위험 수용 예외는 배타적으로 집계한다. 남은 미해결 위치가 모두 승인된 예외 범위에 있을 때만 예외로 센다. 다른 미해결 위치가 있으면 조치 단계에 센다. 카드, 매트릭스, 목록은 동일한 `scope`, 필터와 `asOf`를 적용한다.

집계 스냅샷은 서버가 발급한 `snapshotId`로 고정한다. 이 ID는 집계에 반영한 마지막 확정 이벤트와 범위 버전을 가리키며 요약, 매트릭스, 목록에서 같은 ID를 사용한다. 이후 저장된 변경은 기존 스냅샷의 수를 바꾸지 않는다. 만료된 스냅샷 요청은 새 조회를 요구하는 오류를 반환한다. 발견 소스나 환경 필터에 여러 위치가 걸려도 대응 건을 한 번만 센다.

## 4. 보존과 복구

메타데이터, 감사 이력, 조치 증거는 서로 다른 보존 정책을 적용한다. 운영 설정에는 범주별 기간, 삭제 방식, 백업과 복구 범위를 명시한다. 기간이 정의되지 않은 범주의 자동 삭제나 무기한 보존을 기본값으로 두지 않는다. 원문은 영속 저장하지 않으므로 백업에도 포함하지 않는다. 복구 후에는 대응 단계와 감사 이력, 마지막 성공 및 최근 시도의 구분, 집계의 배타성을 검증한다.
