# PoC 결과 (10/7~10/11)

**PRD에서 옮긴 PoC 실측과 실험 근거.** 요구사항은 [PRD](../01-requirements/PRD.md)가 정하고, 이 문서는 그 요구사항이 어떤 관찰과 측정에서 나왔는지를 보존한다. 진행 과정 전체는 Notion의 PoC 작업 기록에 있다.

## 1. 기준 실행

| 항목 | 내용 |
|---|---|
| 대상 | ReUsed api(`service-backend`, Spring Boot 4.1.1, Java 21, Gradle) |
| 분석 기준 | 분석 커밋 `6583020`, 운영 배포 이미지 `logssey/reused-api@sha256:a6ffffef…`(revision `bb4639b`). 두 커밋의 소스 트리가 같다(`e5b4a3af`) |
| 기준 실행 | 2026-10-10~11. 배포 digest를 Trivy 0.75.0(10/10 DB)로 스캔해 23행. 이 문서의 대상 앱 수치와 판정은 이 실행 기준이다 |
| 갱신 원칙 | 앱이 바뀌어도 이 수치를 고치지 않는다. 다시 돌리면 PoC 작업 기록에 회차를 추가하고, 기준을 바꾸기로 할 때만 이 표와 수치를 함께 고친다 |
| 보조 실험 | 로컬 샘플 앱과 실제 앱 사본에 취약 조건을 넣은 대조군 실험, 도구 비교 실험. 대상 앱 수치에는 섞지 않고 탐지 능력 지표(NFR-01, M-04, M-05)의 근거로만 쓴다 |

## 2. 운영 api 이미지 23행

23행 = CRITICAL 5 · HIGH 11 · MEDIUM 7. Java CVE 14개, Jackson 2.21.5 사본 7행, OS 패키지 2행으로 나뉜다. 판정한 Java CVE 14개는 모두 `unreachable`이다.

| 묶음 | CVE | 행 | 심각도 | 판정 | 방식 |
|---|---|---|---|---|---|
| tomcat-embed-core 11.0.24 | CVE-2026-65182, 65905, 68525 | 3 | CRITICAL 3 | `unreachable` | `rule` |
| bcprov-jdk18on 1.81 | CVE-2025-14813, CVE-2026-8763, 13506, 0636 | 4 | CRITICAL 2 · HIGH 1 · MEDIUM 1 | `unreachable` | `callgraph` |
| jackson-core 3.1.5 | CVE-2026-89407, 89425 | 2 | HIGH 2 | `unreachable` | 89407 `rule`, 89425 `callgraph` |
| jackson-databind 3.1.5 | CVE-2026-68497, 91776, 91777, 19032, 83557 | 5 | HIGH 3 · MEDIUM 2 | `unreachable` | `rule` |
| Jackson 2.21.5 사본 (com.fasterxml.jackson) | 위 Jackson CVE 7개와 같음 | 7 | HIGH 5 · MEDIUM 2 | `not_analyzed`(`unanalyzed_copy`). 제안(확정 대기): 89407·89425 도달 불가, 나머지 5개 도달 불가(발동 조건 없음) | 확정되면 `manual` |

이 이미지에는 도달하는 CVE가 없다. 그래서 이 결과만으로는 분석기가 도달 경로를 잡아내는지 보여 줄 수 없고, 도달 판정 능력은 3·5절의 실험과 회귀 테스트로 따로 검증했다.

### 요구사항으로 이어진 관찰

| 관찰 | 근거 | 이어진 요구사항 |
|---|---|---|
| 경고 대부분이 실제 위험이 아니다 | Trivy 23행 중 판정한 Java CVE 14개가 모두 도달 불가 | FR-05, FR-06 |
| 고치는 것도 공짜가 아니다 | 23행 모두 수정 버전이 있지만, 버전업에는 호환성 확인이 필요하다(실험 clone에서 백엔드 테스트 945개, 약 5분 49초) | FR-13, 시나리오 D |
| 패키지 수준 판정으로는 부족하다 | 앱은 bcprov를 직접 부르지 않고 Spring Security의 Argon2 경로로만 쓴다. CVE-2026-13506은 패키지·클래스 단위로는 닿고 메서드 단위로만 배제된다 | FR-05 |
| 같은 CVE가 여러 사본으로 들어온다 | Jackson CVE 7개가 3.1.5와 2.21.5 두 사본에서 나온다 | FR-07, US-11 |
| 스캔 대상이 실제 배포물과 다를 수 있다 | 10/9 로컬 이미지에는 오래된 jar 102개만 있었고 bcprov가 없었다(레포 bootJar는 185개) | FR-04 |

### 실현 가능성

- PoC 판정은 사람 판정이 확정된 CVE와 모두 일치했고, 주입 실험과 샘플 앱 회귀 테스트로 도달 경로 탐지도 확인했다. 실제 앱(클래스 376개, jar 184개) 분석은 약 40초다.
- 판정은 실제 배포물에 적용된다. 운영 파드 2개의 digest `a6ffffef…`와 분석 커밋의 소스 트리가 같다.

## 3. 비기능 요구사항 실측

| ID | PoC 실측 |
|---|---|
| NFR-01 | 규칙 모양 그대로 10개 + 우회한 모양 10개 → **20/20 탐지**. 리플렉션으로 넣은 것(14813, 89407)은 놓쳤고, 알려진 한계로 회귀 테스트(`app-blindspots`)에 고정했다. 오탐 1건(91777)을 고치고 회귀 테스트로 고정했다. 정답지 대조의 첫 불일치 1건(89407)도 `unknown`이었다 |
| NFR-02 | 주입 실험의 판정 20개 모두 넣은 코드의 정확한 줄을 근거로 가리켰다. 보고서는 사실을 먼저 보여주고 호출 경로는 후보로 표시한다 |
| NFR-03 | 실제 앱 **약 40초**(노트북, 앱 클래스 376개, 라이브러리 jar 184개, 도달 메서드 67,091개, 로딩 12초 포함, bootJar 빌드 제외). 증가 곡선(10/14, 시험 분석기 `reach_poc`, SootUp RTA, 실제 앱에 라이브러리 25~100%): 클래스패스 2.5배에 그래프 생성 약 2배(거의 선형), 도달 그래프 1.2배. 라이브러리 100%에서 힙 2GB 부족, 3GB 성공. 같은 조건 반복 편차 최대 약 45%. `reach.jar` 기준 곡선과 CI 러너 측정은 아직 없다 |
| NFR-04 | 판정은 정적 분석과 규칙으로만 한다. 샘플 앱 회귀 테스트 앱 5개 **44/44 일치**. 같은 digest를 새 DB로 재스캔해도 23행이 10/7 결과와 같았다. 같은 입력 반복 실행 비교는 확인 필요 |
| NFR-05 | L1 조회는 읽기 명령(`kubectl get pods`, ECR 조회)만 썼지만 관리자 kubeconfig로 실행했다. 읽기 전용 계정은 계획이다. 스캐너 버전(Trivy 0.75.0)과 DB 날짜를 기록했다. 체크섬·서명 확인은 아직 없다. 배경: 2026년 3월 Trivy 배포 체계 침해 사고 |
| NFR-06 | 실제 앱 분석은 노트북(WSL)에서 실행했다. 시험용 대형 classpath(클래스 약 8만 개)는 `reach.jar`가 힙 1GB로 9초에 분석했다. 시험 분석기(`reach_poc`, SootUp)는 실제 앱에 힙 3GB가 필요했다(10/14). dep-scan은 DB 약 42GB로 디스크가 차 실패해 보류했다. 최소 실행 환경 정의와 CI 러너 실행은 아직 없다 |
| NFR-07 | 취약 함수는 조사 파일 → 생성 스크립트 → `vuln-functions.json`, 규칙은 `rules.json`이다. CVE 4개를 추가해 판정 대상이 10개에서 14개가 됐다. 새 사실 수집에 코드 변경이 필요했는지는 확인 필요. npm 분석기는 계획이다 |
